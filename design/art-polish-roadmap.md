## 0. 结论先行（10 秒版）

1. **立绘底子比预期好，但资产本身全部要重生成**：6 张图风格谱系一致（厚涂+强描边+深靛夜底），可作风格锚；但**每张右下角带「AI生成 AIGOODS」水印、无透明通道、1024² 方图、单张 1.3–1.7MB**——四项全踩规格红线，修补不如按管线重出。
2. **最致命的美术问题不是图，是"脸不会动"**：emoji 徽章冒充表情系统，"动摇"和"被说服"肉眼不可辨——这直接废掉核心卖点「对手是活的」的**可读性**。P0 第一优先级是把 4 档整脸变体做出来。
3. **P3 骨骼动画（Spine/DragonBones）结论：不做。** CSS 微动效 + 4 档表情 crossfade 已能覆盖目标演出量的 ~85%，solo 时间花在这里是负 ROI（理由见 §2.4）。
4. **产能红线**：全部投入收敛到 **P0 约 6.5–8 人日 + P1 约 4–5 人日**，两周半内可完成参赛版美术；其余全部进"不做清单"。
5. art-bible 附录里「15 NPC × 4 表情 = 60 张」已过时（GDD 2026-09-07 裁决定为 5 名），本文口径统一为 **5 NPC + 1 玩家 = 30 张**。

### 1.2 问题清单与严重度

严重度定义：**致命**=评审可能因此直接降档 / **大**=明显拉低观感或体验 / **中**=扣分但不致命 / **小**=打磨项。

| # | 问题 | 严重度 | 对评审观感的伤害 | 对玩家体验的伤害 |
|---|---|---|---|---|
| A1 | **每张立绘带 AI 工具水印** | **致命** | 第一眼即"生图没洗"，专业度归零；录屏/截图传播时水印跟着走 | 玩家感知"粗糙的 AI 感"，破坏沉浸 |
| A2 | **表情系统 = emoji 贴纸**（无真变脸） | **致命** | "演出完成度"维度直接挂科——核心卖点的演出落点是空的 | 看不出"动摇 vs 被说服"的差别，「读人」乐趣的一半不可见 |
| A3 | **构图不统一**：方图立绘当头像卡用、脸部只占画面 ~25%、cover 裁切后构图随机 | **大** | 两侧立绘大小/重心/留白各不相同，"对峙法庭"的对称张力立不起来 | 视线交汇的压迫感缺失；表情特写时脸太小像素不足 |
| A4 | **音量超标**（8.6MB / 首屏预算 3MB） | **大** | 评委弱网/首次打开白屏等待，第一印象先扣分 | 加载卡顿打断"点开即玩" |
| A5 | **玩家朝向错误**（面朝左、背对 NPC） | **大** | 违背美术圣经 §2.2「视线即冲突」，对峙构图语言崩坏 | 潜意识觉得"俩人没在对视"，张力全无 |
| A6 | **主界面/结算无仪式感**：标题纯文字、结算纯弹窗、晋级/淘汰无演出 | **大** | 评审 10 秒定生死，开场没有"哇"点；系列赛情绪无落点 | 三局两胜的输赢没有情绪回报，"再来一局"动力弱 |
| A7 | **字体未自托管**：serif 栈落到 宋体/SimSun，细瘦无气势 | **中** | 换机器渲染漂移；大字异议/标题失去"判决书"气势 | 同左，且 Windows 下 SimSun 假加粗难看 |
| A8 | **t3 陈博主风格跳脱**：糖果色+高光塑料感，与整体厚涂夜景色温断差大 | **中** | 五张摆一排时一眼跳；但部分符合 art-bible L3「张扬、色彩饱和」设定，属"越界但不全错" | 该角色辨识度高反而可能讨喜——压制色调即可，不必推翻 |
| A9 | **圆形头像残留**（选关/自由/选边用 50% 圆裁切，对局用切角卡框） | **中** | 同一角色两种裁切形态，视觉语言不统一 | 轻微；属一致性问题 |
| A10 | **无 AI 生成内容显式说明**（页面级） | **中** | 合规与诚意信号：赛事/平台对 AI 生成内容标识有监管要求（图内水印应去除，改为页面显式声明——最终口径请大王确认） | 无感 |
| A11 | **六维雷达藏进 ℹ️ 弹窗**，主界面无焦点区 | **中** | "强游戏框架"的证据被藏起来了 | 「先读懂再出拳」的核心 HUD 不可见，读图成本高 |
| A12 | 杂项：token 低量无暗角预警、表情 chip 与标签色弱对比、情绪标签无图案冗余（色盲） | **小** | 打磨项 | 可访问性 Standard 级未达标 |

### 1.3 哪些其实没问题（避免误伤）

- **风格谱系一致性高于预期**：5 张 NPC 同属"厚涂+强描边+顶光+深靛夜底"，t1/t2/t4/t5 几乎可以同框。**不需要推翻画风重来，需要的是把这套风格锁成可复现的提示词模板**（见 §4.1）。
- **NPC 全部面朝画面左**，恰好符合"NPC 居右面向左"的布局——这 5 张在朝向维度上全对（只有玩家错）。
- **对局立绘卡框、双向异议闪帧、打字机、系列赛横幅、票据切角 chip** 均已落地且方向正确——P0 是"强化"不是"重建"。

**审计总结论**：底子（画风、布局、演出骨架）是 75 分的图纸，资产（图本身）和表情演出是 30 分的施工。P0 目标：把这两块补到 85+。

### 2.4 专项结论：P3 骨骼动画（Spine/DragonBones）—— **不做**

给 main 的明确结论，替代 plan-art-upgrade 里"P3 后议"的悬置：

| 评估项 | 事实 |
|---|---|
| 目标动画 | 头/眼/手微晃、说话张口、破防抖动——全是**小幅度的形变**，非位移动画 |
| CSS+表情变体已覆盖率 | 空闲呼吸（transform）✅ 说话感（打字机+头部微倾）✅ 破防（表情档+震动+前倾）✅——目标动画的 ~85% |
| 骨骼方案的真实成本 | ① 立绘必须**拆件重绘**（身体/头/眉眼口分离）——AI 生成拆件一致性是全管线最难点，24 张的活变 40+ 张；② Spine $69/项目 + spine-webgl 运行时 ~300KB（违背零依赖轻量）；③ 学习曲线 + 骨骼绑定调试，solo 估 **3–6 人日起**；④ 换来的是剩余 15% 的微动收益 |
| ROI 判定 | 同样的 3–6 人日投到 P1 全部 + P2 两项，观感提升远大于骨骼动画 |
| 未来复核条件 | 仅当 ① 演出被证明是败因、且 ② 已完成 P0/P1 仍有 >1 周余量、且 ③ 决定做「照片 AI 化转角色」愿景时，重启评估；届时首选 **DragonBones**（免费、Canvas、国内生态），且从第一张基准像起就按"可拆件构图"出图 |

**替代方案（已并入 P1/P2）**：CSS idle 呼吸 + 异议前倾/后仰 + 表情 crossfade + 震动。这套"穷人骨骼"对 Web 评审完全够用。

### 2.5 art-bible-v2 五个待拍板问题 · 推荐答案

| # | 问题 | 我的推荐 | 理由 |
|---|---|---|---|
| 1 | 表情方案：整脸变体 4 张 vs 脸层贴回身体 | **整脸变体**（维持 v2 建议） | 图生图"同 seed + 低 denoise + 同身份块"一致性够用；脸层方案需拆件重绘+图层对位校准，工程 3 倍且 solo 翻车率高。兜底：派生漂移时改用"脸部 inpaint（mask 只盖脸区，denoise 0.7）"，仍然不出图层 |

| 3 | 玩家形象：1 预设 + 4 表情，换装延后 | **同意，且"延后"改为"永不"** | GDD 已列设计禁令；30 张预算里玩家占 5 张已足够存在感。省下的全部投 NPC 表情 |

| 5 | 音频先做两组 | **同意**：异议 hit + 晋级金钟/淘汰低音 | 配合 P0-7 晋级仪式是情绪闭环；其余音效全延后。建议 Web Audio 合成或 CC0 单文件，**不引入音频资产目录管理**（solo 纪律） |


**字体栈（零网络依赖）**

| 用途 | 栈 | 托管策略 |
|---|---|---|
| 大字异议/标题/层号/NPC 名/按钮强调 | `"Noto Serif SC Heavy","Source Han Serif SC","Songti SC",SimSun,serif` | **自托管子集 woff2**：仅固定 UI 字符集（标题/按钮/异议大字/晋级淘汰/5 个 NPC 名/层号/数字），~200–400 字 → 100–200KB；动态文本（辩题、对话）不进该子集 |
| 正文/对话/说明 | `"Noto Sans SC","PingFang SC","Microsoft YaHei",sans-serif` | 系统栈，不托管（现代系统黑体质量已够） |
| 数字（token/倒计时/比分/自信度） | 同 sans + `font-variant-numeric:tabular-nums` | — |

**字号阶梯（px）**：11（chip/标签）· 13（辅助）· 15（正文强调）· 17（名字）· 20（小标题）· 24（对话正文）· 32（区块标题）· 48（横幅比分）· `clamp(64px, 14vh, 160px)`（异议大字）。行高：正文 1.6 / 标题 1.2。

**间距阶梯**：4 / 8 / 12 / 16 / 24 / 32（一切 padding/margin/gap 取值于此）。

**圆角**：控件 4px · 面板 6px · 票据切角 `clip-path: polygon(0 12px, 12px 0, …)`（对局卡框现行实现）· chip 12px · **禁止对任何角色头像使用 50% 圆形**。

**阴影**：e1 立体卡 `0 0 20px rgba(69,214,200,.15)`（玩家）/ `rgba(240,138,93,.15)`（NPC）· e2 印章 `0 6px 24px rgba(0,0,0,.5)` · 无第三种发光色。

**动效**：时长档 120 / 300 / 450 / 800 / 1000ms；easing：进出 `cubic-bezier(.2,.7,.3,1)`、弹性 `cubic-bezier(.2,.9,.3,1.2)`（overshoot，大字/金印专用）；全屏动效总开关（P2.5 拍板项）挂 `body.reduce-motion` 类，`animation:none` 化震/闪。

### 3.2 关键界面视觉语法与布局规格

| 界面 | 布局与视觉语法 | 硬性验收 |
|---|---|---|
| **主界面** | 深靛底 + CSS 顶部聚光（radial-gradient 金 4%）+ 微放射纹（repeating-conic-gradient，透明度 ≤5%）；金宋大标题「抬杠模拟器」+ 印章副标（红印小方章「抬杠」）；两张**票据模式卡**：天梯=异议红描边、自由=玩家青描边，切角框+悬停 translateY(-4px)+金色 focus-ring；页脚 AI 生成声明 | 首屏无网络请求字体也能渲染；标题字号 ≥32px 且有印章元素 |
| **天梯选关** | 5 张竖卡（切角票据框）：层号宋体大字（L1…L5）+ 透明立绘（贴卡底）+「交手 N 次」红金徽章 + 锁定态（灰底+锁图标+文字「先攻破上一层」）；hover 前倾 translateX(6px)（现行） | 立绘统一为透明 WebP、贴卡底、无圆形裁切；锁定/解锁/交手徽章三态齐 |
| **对局主界面** | 保持三栏骨架；立绘区=切角卡框+**底部 20% 渐变压边**（让人物"站"在卡上）+ 表情双 img crossfade；自信度条加刻度线 20/40/60/80 + 背水线标记；token/计时 tabular-nums；雷达进入主焦点区（P1-5） | 玩家面右 NPC 面左；四档表情预载；刻度与背水线可见 |
| **系列赛横幅** | 现行金斜纹横幅保留；比分变化数字 200ms `scale 1→1.15→1` 弹跳 + 金印色 | 比分变化必弹跳；横幅常显不遮挡对话 |
| **结算/晋级** | 胜=金印「晋级！」落下（scale 3→1 + blur 8px→0 + 震 6px，450+800ms）→ 票据式成绩单（SVG 虚线边框+印章角标）；单局胜=金粒子 + NPC"被说服"定格（P1-7）；败/淘汰=全场 grayscale(.85)+「差一点」+ 复盘入口 | 三态演出各有 ≥1 个"可截帧"的瞬间；可被 reduce-motion 关闭 |

### 3.3 表情系统最终方案

**档位与命名（对局表情为整脸变体位图，非 emoji）**

| 角色 | 档位 | state 键 | 触发（后端已输出，前端零改动量） |
|---|---|---|---|
| NPC | 得意 | `smug` | 自信度 ≥80，或玩家命中强项（被反驳） |
| NPC | 从容 | `calm` | 自信度 60–80（含开局） |
| NPC | 动摇 | `shaken` | 自信度 40–60，或玩家命中薄弱点（立即置位） |
| NPC | 被说服 | `defeated` | 自信度 <40；归零时定格 1.2s（接 P1-7） |
| 玩家 | 从容/紧张/焦虑/绝望 | `calm/tense/anxious/desperate` | 按 token 剩余百分比：>60% / 35–60% / 15–35% / <15%（配额 420–280 映射） |

**切换过渡规格**

- 实现：立绘容器内双 `<img>`（A/B 交替），切档时新图 `opacity 0→1`，旧图 `1→0`，**300ms linear**（纯淡入淡出，无缩放——表情要"变脸"不要"换海报"）。
- 跨 ≥2 档（如 smug→defeated）：400ms + 新图入场附加 100ms 白闪（`filter:brightness(1.6)` 衰减）+ 2px 抖动。
- 防抖：同档不重播；演出（异议/结算）期间表情切换延迟到演出结束；优先级 **异议 > 归零定格 > 情绪档 > idle**。
- 预载：对局开始即 `new Image()` 预载当前 NPC 4 档 + 玩家 4 档（≤0.6MB，见 P0-4）。
- emoji 徽章**删除**（`NPC_EMOJI`/`PLAYER_EMOJI` 字典退役）；ℹ️ 底细弹窗里的情绪区改用"档位小图标"（SVG，色盲冗余：得意=上扬箭头/动摇=波浪线/…，同色系内做形状差异，不引入新色）。
- 失败回退：`onerror` 时回退 `base` 图，保证永不裂图。

**目录与命名规范（本规范取代 art-bible 附录 A 的 15-NPC 命名）**

```
demo/static/assets/char/
  char_npc_t{tier}_base.webp        # 基准像：t1…t5
  char_npc_t{tier}_{state}.webp     # state ∈ calm | smug | shaken | defeated
  char_player_base.webp
  char_player_{state}.webp          # state ∈ calm | tense | anxious | desperate
design/assets/raw/                  # 原始生成物（PNG 源、带背景版）——不入 demo
design/assets/ai-manifest.json      # 每张图的 prompt/seed/模型/denoise/日期/验收人
```

- 文件名一律小写蛇形；**禁止空格/中文/版本号后缀**；定稿覆盖同名文件，候选版本只存在于 `design/assets/raw/`。
- 现有 `npc_t1~t5.png / player.png`：重生成定稿后，在 `ai-manifest.json` 里标记 `superseded_by`，源文件移入 raw 归档，**demo 目录不留 1MB 级 PNG**。

## 4. AI 资产生产管线（本项目命脉）

### 4.1 角色一致性方案与提示词模板

**一致性三板斧（按优先级叠加）**：

1. **角色身份证（identity block）**：每个 NPC 一段固定不变的描述块，存 `ai-manifest.json`，所有派生图原样携带，只允许追加表情/镜头后缀。
2. **同 seed + 低 denoise 图生图**：表情派生一律以该角色 `base` 图为 init image，`denoise 0.40–0.50`、seed 固定不变——只够重画表情，不够换人。
3. **构图锚（可选加强）**：ControlNet lineart/openpose 以 base 为参考（weight 0.5–0.7），锁住身体朝向与轮廓，防止"表情对了但肩膀转了 30°"。

**身份块模板（以王阿姨为例，中文注释不入 prompt）**：

```
{风格锚}
thick-paint anime style cel-shading, strong black outlines, top-key lighting
with subtle warm rim light, dark indigo night background tone, high contrast,
realistic adult proportions, no chibi

{构图锚 —— 每张必带，一字不改}
half-body portrait, bust shot, character facing screen left, three-quarter view,
eyes looking toward screen left, body touching the bottom edge of the frame,
empty space above head within 8% of frame height, head occupies 28-32% of frame
height, hands hidden below frame

{角色身份证 —— 王阿姨}
a warm-hearted retired Chinese woman in her 60s, gray curly short hair,
dark floral-patterned jacket over a black top, kind but stubborn expression

{表情后缀 —— 唯一允许变化的部分}
calm:     calm relaxed neutral expression, soft closed-mouth smile, steady gaze
smug:     smug triumphant smirk, one eyebrow raised, eyes narrowed with pride,
          chin slightly lifted
shaken:   shaken anxious expression, furrowed brows, mouth slightly open,
          a single sweat drop on the cheek, gaze wavering
defeated: defeated expression, wide stunned eyes, deflated slumped posture,
          bitter forced smile, all confidence gone

{负面词 —— 固定}
watermark, signature, text, logo, multiple people, extra characters,
deformed hands, extra fingers, bad anatomy, lowres, jpeg artifacts,
bright colorful background, chibi, 3d render, photorealistic skin
```

玩家（青锋）的身份证块同理替换，且**构图锚写 `character facing screen right`**（P0-3）。

### 4.2 输出规格

| 项 | 规格 |
|---|---|
| 画幅 | **3:4 竖幅**。SDXL 源图 1024×1365（或 1024×1024 生成后向下扩图补齐）；**禁止再出 1:1 方图** |
| 构图 | 半身、贴底边、头顶留白 4–8%、脸占画面高 ≥28%、双手藏于画外（防手指崩坏+省抠图）、NPC 面朝画面左 / 玩家面朝画面右 |

### 4.5 批量生产步骤（推荐路径）

**路径推荐：本地 ComfyUI/SDXL 为主干，ImageGen 工具只做基准像候选海选。**

| 环节 | 本地 SDXL/ComfyUI（RTX 5080 16GB） | ImageGen 工具 |
|---|---|---|
| 一致性控制 | seed 固定 / denoise / ControlNet / IPAdapter / LoRA 全可控 | 只有 prompt（+可能无参考图控制），一致性靠运气 |
| 批量成本 | 零成本无限重 roll；单张 15–25s | 有额度限制 |
| 适用 | **表情派生 24 张（唯一合理选择）**、抠图、扩图 | 基准像海选（并行多候选快筛风格）、灵感稿 |
| 风险 | 需 1 次性搭环境（半天内） | 出图不可复现，无法进"血缘"管理 |

**执行步骤（一次性流程，总计 2–3 个工作日内可全部产出）**：

1. **定风格锚**（0.5h）：用现有 6 张中 t2/t4 作为风格参照图，把 §4.1 风格锚提示词跑 3–5 张校验图，确认 SDXL 出图与参照风格谱系一致，定稿风格锚与负面词（此后一字不改）。
2. **产基准像 6 张**（0.5–1d）：ImageGen 海选每角色 3–4 候选 → 选定后**仍用本地按同身份块重出定稿**（保证血缘与复现）；跑 rembg 出 alpha；验收（§4.6）通过后入 manifest。
3. **派生表情 24 张**（0.5–1d 纯生成 + 0.5d 挑图）：ComfyUI 图生图，同 seed、denoise 0.45 起，每档出 2 候选；漂移超限的改"脸部 inpaint"路径；挑选入 manifest。
4. **后处理入库**（0.5d）：alpha 修边（羽化 2px）→ 降采样变体 → cwebp → 重命名入库 → 更新 manifest → 前端切换 + 全量验收。
5. **体积核对**（0.2h）：脚本扫 `demo/static/assets` 全目录，超标即回炉。

**踩坑预警（每条都是真实翻车点）**：

- **从变体派生变体=漂移累积**。所有表情必须从 base 出发，禁止链式派生。
- **中文人脸在 SDXL 偏日系/网红脸**：身份块里"Chinese, realistic adult proportions"必须带；必要时叠 Chinese-style LoRA 或 IPAdapter 用基准像自引导。
- **水印进训练分布**：若参考图带水印，生成图会自己长水印——参照图一律先去水印再用；生成结果每张必查右下角。
- **rembg 吃掉发丝/描边**：厚涂风格常见；预案=修边笔刷救 6 张以内的量，超量改 LayerDiffuse 重出 alpha。
- **手是重灾区**：构图锚已把双手藏画外，任何出现完整双手的图直接重生成，不修图。
- **seed 只保证"同模型同配置"下复现**：换 checkpoint/采样器后血缘失效——manifest 必须记录模型与采样器名。
- **表情"过戏"**：defeated 容易生成哭戏夸张脸，与美术圣经"气势瓦解但保持体面"冲突——挑图时宁可收敛。

### 4.6 质量验收清单（命中任何一条 → 重生成）

**一致性**
- [ ] 与 base 五官/发型/服装完全同源，未"换了个人"
- [ ] 服装颜色/图案未漂移（ Floral 外套还是那件 Floral 外套）
- [ ] 朝向正确（NPC 左 / 玩家右），肩膀未转动 >10°

**情绪**
- [ ] 该档 4 档并排 5 秒内可两两区分（重点：smug vs calm、shaken vs defeated）
- [ ] 幅度收敛：defeated 不哭戏、smug 不狰狞

**构图**
- [ ] 3:4、贴底、头顶留白 4–8%、脸占比 ≥28%
- [ ] 无完整双手、无多余人物、无文字/水印/logo
- [ ] 无肢体畸变（手指/眼距/牙齿）

**技术**
- [ ] alpha 边缘干净、2px 羽化、无白晕黑晕
- [ ] WebP 体积达标（base ≤150KB / 变体 ≤80KB）
- [ ] 命名与目录符合 §3.3，manifest 血缘完整
