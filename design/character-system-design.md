## 0. 结论先行

| 决策 | 选型 | 理由 |
|---|---|---|
| 动画技术 | **分层 sprite + CSS transform 骨架动画** | 零依赖零成本；纯 Web（transform/opacity 合成器加速）；最适合 AI 生成部件 |
| 捏人 | **自由拼装**：性别(2) × **脸(5)** × **头发(5)** × **衣服(5)** = 250 种 | **公用一套骨架**，所有脸/发/衣部件对齐同一骨骼参数，动画通用 |
| 骨骼动画 | 本阶段**不引入 Spine/DragonBones**（付费 + runtime 依赖 + 换装与骨骼两套系统冲突） | 大幅动作留作参赛版定型后再议 |

**核心矛盾与解法**：AI 生图产「合成整图」，不产「可自由组合的换装部件」。解法 = **部件分别生成（透明背景）+ 统一画布锚点 + 前端 CSS 定位拼装**。一致性靠「同一画布规格 + 固定锚点 + 描述词锁定画风」。

**风格锚**（2026-09-08 大王拍板）：参考《逆转裁判》系列群像插画的**半写实日式动漫 + 鲜明轮廓线 + 青年角色（无老幼）**。具体见 `design/comfyui-workflow.md` 的提示词模板（v3 验证中）。

## 1. 分层结构（部件树，层级自底向上）

```
character (画布 576×864, 2:3 竖版)
├─ L0 body        身体（躯干+四肢+基础打底衣）   ← 底层，含性别差异（2 套）
├─ L1 head        头+脸（含 4 档表情变体）        ← 中下层
├─ L2 outfit      衣服/上装（覆盖身体，可切换）    ← 中层
└─ L3 hair        头发（覆盖头顶，可切换）         ← 顶层
```

| 层级 | 部件 | 玩家可换 | NPC | 说明 |
|---|---|---|---|---|
| L0 body | 身体 | ✅ 2 性别 | 固定 | 男/女各 1 套基础身体，**画布/锚点共用** |
| L1 head | 头+脸 | ✅ **5 款**（不分性别） × 4 表情 | 固定 1 脸 × 4 表情 | 表情变体即「变脸」；**5 款脸型都是青年** |
| L2 outfit | 衣服 | ✅ **5 款** | 固定 1 款 | 覆盖身体上装 |
| L3 hair | 头发 | ✅ **5 款** | 固定 1 款 | 盖头顶 |

**组合数**：玩家 2 × 5 × 5 × 5 = **250 种**；NPC 固定 1 套（复用同架构）。

**公用骨架铁律**（2026-09-08 拍板）：所有脸/发/衣部件的**头-身接缝 y、眼睛 y、肩膀 y**必须严格对齐，画布规格统一（576×864），让 CSS 骨架动画（呼吸/点头/破防晃动）对**所有 250 种组合通用**，不用按组合调参。

## 2. 资产规格

| 项 | 规格 |
|---|---|
| 画布 | **576×864**（2:3，与现有 `portrait/` 一致），所有部件同一画布坐标 |
| 锚点 | 头中心 ≈ (288, 240)；身体中轴 x=288；头-身接缝 y≈360（脖子处） |
| 背景 | **透明**。⚠️ 实测 ImageGen 的 `background: transparent` 参数**不生效**（固定输出灰底 RGB），改为「ImageGen 生图 → **rembg 抠图**」后处理（`tools/segment_parts.py`） |
| 格式 | 部件原图 PNG → 转 WebP q80（复用 `optim_portraits.py` 思路） |
| 命名 | `assets/parts/{part}/{id}.webp`，part ∈ {body, head, outfit, hair} |
| 表情 | head 部件按 state 出变体：`head_{faceId}_{state}.webp`（state=calm/tense/anxious/desperate 玩家；smug/calm/shaken/defeated NPC） |

**统一画框铁律**（crossfade/换装不「跳头」）：所有 head 部件的**眼睛 y 坐标、头部大小、颈部接缝**必须对齐；所有 body 的**肩线 y、躯干中轴**对齐。验收即查这两点。

## 3. 动画清单（CSS 骨架，动作 = 部件 transform 组合）

| 动作 | 触发 | 部件动画 | CSS 实现 |
|---|---|---|---|
| 呼吸（idle） | 常驻循环 | body scaleY 1→1.02 微起伏 | `@keyframes breathe` 3.5s |
| 眨眼 | 随机 2–6s | head 表情层快速切换「闭眼帧」 | opacity 闪切 |
| 说话点头 | NPC 打字机期间 | head rotate -1.5°↔1.5° | `@keyframes nod` 循环 |
| 破防晃动 | 被命中软肋 | 全身（容器）shake | 复用现有 `#app.shake` 逻辑，作用到角色容器 |
| 得意后仰 | NPC 命中强项 | body+head rotate 后仰 2° | `@keyframes lean` 一次性 |
| 被说服垂头 | 自信度归零 | head rotate 下垂 + 整体下移 | `@keyframes slump` 一次性 |

**纪律**：只动 `transform`/`opacity`（不触发 layout）；`prefers-reduced-motion` 与「演出降级开关」全局生效（复用 `bianyi_fx`）。

## 4. 捏人规则

- 玩家默认：男 / 脸 A / 发型 A / 衣服 A。
- 自由拼装：4 个维度各自独立切换，前端实时预览。
- 持久化：`localStorage: bianyi_avatar`（存 {body, head, outfit, hair}）。
- 捏人入口：主界面新增「🎭 角色」卡，或开局选边屏加「自定义形象」入口（待定，实现时选更顺的一处）。

## 5. AI 部件生成策略（命脉）

**路径：部件分别生成（灰底）→ rembg 抠透明 → 程序拼装**（God Mode AI 等拆件工具拆不出「性别/发型/衣服」换装维度，弃用）。

1. **先产 1 套「玩家男」完整基准像**（身体+脸+头发+衣服同框），作为风格锚与对齐参照。
2. **派生部件**（图生图，参考基准像）：
   - body：男/女 2 张（同一姿势、肩线同高）
   - head：3 张脸（同大小、眼睛同 y、脖子接缝对齐）
   - outfit：3 张（同身体轮廓、领口对齐）
   - hair：3 张（同头顶位置）
3. **表情变体**：head 每张脸再图生图派生 4 表情（沿用 `art-polish-roadmap` §4 三段式提示词）。
4. **拼装验收**：写一个预览页/脚本把「随机组合」拼出来目检——**对齐偏差超 2% 即重生成该部件**。

**踩坑**：① 部件之间禁止「链式派生」（都从基准像出发，防漂移累积）；② 透明背景抠图残边用 alpha 羽化；③ 描述词统一加「flat game character, 2:3 vertical, front view, centered, solid transparent background」锁画风。

## 7. 遗留风险

- **R1 对齐漂移**：AI 生成部件的位置/大小漂移导致拼装「跳头」→ 靠统一画布锚点 + 逐部件目检，超差重生成。
- **R2 我看不了图**：当前模型无法目检生成图，拼装对齐需大王肉眼验收。
- **R3 表情×脸×性别组合爆炸**：54 组合若都要单独验收不现实 → 先验收「部件层」对齐，组合层靠锚点约束兜底。
