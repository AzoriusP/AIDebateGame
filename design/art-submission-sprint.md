## 2. 替代方案：对峙演出栈（Courtroom Performance Stack）

### 2.1 核心思路

**"活"的感觉 = 单位时间内的视觉变化密度 × 变化的语义强度**，与是否使用骨骼动画无关。
逆转裁判系列本身不用 Live2D，靠的是：**快速切帧 + 冲击特效 + 屏幕震动 + 硬切构图**。这套语法在 Web 上的实现成本极低。

### 2.2 六件套（按性价比排序，全部不依赖 Live2D）

| # | 演出 | 实现 | 触发 | 工作量 |
|---|---|---|---|---|
| **P0-1** | **异议冲击**（最高性价比） | 立绘 `scale(1.08) translateY(-4px) rotate(-2°)` 150ms 冲入 → 红色放射速度线（纯 CSS `conic-gradient` + mask）→ 「异议！」描边字弹出（`-webkit-text-stroke` + `scale` 弹性）→ 震屏 120ms → 闪白 60ms | 命中/被命中 | 0.8 人天 |
| **P0-2** | **情绪切换** | 旧帧 `opacity→0` + 新帧 `opacity→1`，120ms crossfade；叠 6px 位移 + 情绪色温（动摇 `saturate(.6)`，绝望 `brightness(.8) saturate(.4)` + 整体下沉 10px） | 情绪档位变化 | 0.5 人天 |
| **P0-3** | **呼吸** | 容器 `scaleY(1↔1.015)`，周期随情绪变化：冷静 3.5s / 紧张 2.2s / 焦虑 1.8s+抖动 / 绝望 4.5s 不规则 | 常驻 | 0.2 人天（已有 `character-performance.js`，接上即可） |
| **P0-4** | **说话点头** | 打字机期间 head 每 2 字 `rotate(±1.5°)`，发言结束回位 | NPC 出字 | 0.3 人天 |
| **P1-1** | **受击反馈** | 抖动 8px + 白闪 + 汗滴/裂纹 SVG 角标（复用 §5 的 19 枚 SVG 体系，不出图） | 被命中软肋 | 0.3 人天 |
| **P1-2** | **得意后仰** | `rotate(2deg) translateY(-6px)` 一次性 + 金色光晕 | NPC 命中强项 | 0.2 人天 |

**纪律**：只动 `transform` / `opacity` / `filter`（走合成器，不触发 layout）；`prefers-reduced-motion` 与演出降级开关（`#fx-master`）全局生效——**这条是可访问性 Standard 级的硬要求，评审会查**。

### 2.3 玩家侧 Live2D 的保留用法

- 男主 `male-master` 已能跑呼吸 / 双眼 / 嘴开合 / 异议伸指 5 个参数 → **对局中玩家侧默认走 Live2D**。
- 若首屏性能不达标（移动端），自动降级到静态立绘 + §2.2 六件套（已有 `renderer: "portrait"` 兜底路径，无需新增代码）。
- **必须在提交前做一次降级演练**：手动禁用 Live2D，确认演出栈单独成立。评委用手机打开时大概率走降级路径。

### 2.4 捏人：零出图成本的 64 组合

现状 `parts/` 只有 `body/male.webp` ×1 + `head/faceA_{4情绪}.webp` ×4，**没有 hair、没有 outfit → 当前实际组合数 = 0**。

破解法：**配色变体用 CSS `filter: hue-rotate()` 派生，不出图**。

| 维度 | 出图数 | 派生方式 |
|---|---|---|
| 发型 | **2 张**（hairA / hairB，576×864 带 alpha） | × 4 发色（`hue-rotate` 0/60/180/300）= 8 |
| 上装 | **2 张**（outfitA / outfitB） | × 4 配色（`hue-rotate` + `saturate`）= 8 |
| 身体 | 已有 1 张 male（P2 补 1 张 female） | × 1 |
| 脸 | 已有 faceA × 4 情绪 | × 1（P2 补 faceB） |

→ **仅出 4 张图，得到 8 × 8 = 64 组合**。0.5 人天。大王 P0 里的"捏人"即可交付。

> ⚠️ `hue-rotate` 会连带改变肤色描边。规范：hair/outfit 图层**单独应用 filter**，body/head 图层不加 filter。

## 4. NPC 表情缺口：最低成本补法

### 4.1 现状（已核实）

| 角色 | 现有 | 缺口 |
|---|---|---|
| L1_A 王阿姨 / L2_A 林经理 / L3_A 陈博主 / L4_A 赵律师 / L5_A 陆教授 | 各 **1 张** `calm.webp`（576×864，**无 alpha**） | 得意 / 警觉 / 动摇 / 被说服 全部缺失 |
| player | 4 档齐全 ✅ 带 alpha | — |

**引擎语义映射**（`character-performance.js:19` 已实现）：`smug→calm`、`shaken→tense`、`defeated→desperate`。
即：**引擎只需 4 档 canonical 状态（calm/tense/anxious/desperate），NPC 的四个语义情绪已能落位**，无需新增状态机代码。

### 4.2 补法（按最低成本排序）

| 优先级 | 情绪 | 补法 | 出图数 | 工作量 | 理由 |
|---|---|---|---|---|---|
| **P0-①** | **动摇 shaken** → `tense.webp` | 以 `calm.webp` 为底，**img2img 局部重绘脸部区域**（眉梢下垂 + 嘴角紧绷 + 瞳孔缩小），躯干不动 | 5 | 0.6 人天 | 对局中出现频率最高（被命中软肋） |
| **P0-②** | **被说服 defeated** → `desperate.webp` | 同上（眉垮 + 张嘴 + 眼神失焦 + 轻微低头） | 5 | 0.6 人天 | 结算前的高光时刻，情绪峰值 |
| **P1-①** | **警觉 anxious** | 同上（挑眉 + 抿嘴 + 汗） | 5 | 0.6 人天 | 中局张力 |
| **P2** | **得意 smug** | ❌ **不出图**。用 `calm.webp` + 演出表达：`rotate(2deg)` 后仰 + 金色光晕 + 特效层 | 0 | 0.2 人天 | 得意是"气场"不是"五官"，演出比换脸准，且省 5 张 |

### 4.3 关键工艺纪律（决定成败）

1. **只重绘脸部，不重绘整个人** → 保证与 `calm` 的肩线/头位/光照严格一致，避免"换表情就跳头"。
2. **必须局部重绘（inpaint），禁止整图重出** → 整图重出会导致画风漂移，5 个人脸不一致。
3. **链式派生禁令**：所有情绪帧都从 `calm.webp` 直接派生，**禁止 anxious 从 tense 派生**，防累积漂移。
4. **A1 与 A2/A3 的顺序依赖**：先完成去水印 + 抠图 + 补裁断的干净 `calm.webp`，再从它派生情绪帧。**顺序颠倒 = 全部返工**。
5. **对齐验收**：5 人 × 3 帧的眼睛 y 偏差 ≤ 2%（约 ±5px），超差重出。这是唯一必须大王肉眼看的点。
6. **统一提示词后缀**（沿用 `comfyui-workflow.md`）：`flat game character, 2:3 vertical, front view, centered, solid transparent background, consistent lighting`

> 💡 **大王只需目检 1 张拼图**：把 5 人 × 3 帧排成 3×5 网格（`design/art-output/` 下已有 `regenerated_grid.png` / `split_grid.png` 的先例），一眼看齐不齐、像不像。这比逐张看快 10 倍。

# 附录 B · 视频优先演出方案（ART-SUBMIT-002）

> 编制 2026-09-10 ｜ 承接大王四条拍板：① 主题不回滚（GATE-0 关闭）② Live2D 只留玩家 ③ 云部署 ④ **演示视频是评委主要载体，演出优先为视频供料**。

## B.0 新优先级公式

> **演出价值 = 视频可见度 × 持续秒数 ÷ 工作量**
> 观众要能在**连续 3 秒以上**的镜头里看见它在动；只有亲手操作才能感知的反馈，权重下调。

由此产生的三条重排原则：
1. **常驻动效 > 瞬间特效**：呼吸/点头每秒都在画面里，异议冲击一局只有 3–5 次、每次 0.9s。前者是"活"的基底，后者是"爽"的爆点，**基底没做，爆点撑不住整段 75 秒实机**。
2. **可后期补的一律后期补**：Ken Burns、转场、字幕标注属于镜头语言，不需要占用游戏工期。
3. **禁止造假**：剪辑只能加"全局镜头语言"，不能给游戏画面加游戏内不存在的局部特效（见 B.5.3）。

---

## B.1 【最高优先级发现】演出引擎正在空转

**这是本轮最重要的取证，它决定了整个 Top 6 的成本。**

| 事实 | 证据 |
|---|---|
| `character-performance.js` **每帧都在计算** breath / eyeOpen / mouthOpen / bodyAngle / browForm / mouthForm / objection 七个值 | `character-performance.js:37` |
| `characters.js` 只**写入** performance（setEmotion / setSpeaking / playObjection / pause / setMotionEnabled / reset），**从不读回** `performance.values` | `characters.js:196,216,222,250,262,269` — 全文无 `transform` / `style.setProperty` / `--` 写入 |
| `characters.css` 明确把立绘钉死：**`transform: none; animation: none;`** | `characters.css:4` |

### 后果

> **当前录屏里，6 个角色（玩家 + 5 NPC）全是完全静止的死图。**
> 演出引擎算出来的值每帧被丢弃，一个都没作用到画面上。玩家侧默认 `renderer: "portrait"`，Live2D 不启用，所以**连玩家也是死的**。

大王担心的"静态画面在视频里 = 完成度低"——现状比这更糟：不是"动得少"，是**一点都不动**。

### 好消息：修法是接一根线，不是造一套系统

计算层已就绪，只缺"把 `performance.values` 映射成 CSS 自定义属性"这一段。

```css
/* characters.css —— 删掉钉死的第 4 行，改为消费变量 */
.character-view .character-portrait {
  transform:
    translateY(calc(var(--ch-lift, 0) * 1px))
    translateX(calc(var(--ch-shake, 0) * 1px))
    rotate(calc(var(--ch-rot, 0) * 1deg))
    scaleY(var(--ch-breathe, 1))
    scale(var(--ch-punch, 1));
  transform-origin: 50% 82%;
  animation: none; /* 由 JS 逐帧写变量，不用 keyframes */
  will-change: transform;
}
```
```js
// characters.js —— 每帧同步（rAF，只在有可见变化时写）
this.performance.values → host.style.setProperty("--ch-breathe", v)
```

**工作量：0.4 人天**（不是附录 A 估算的 0.8，因为引擎已有）。
**这条不做，Top 2–6 全无意义**——在完全静止的画面上叠再炫的特效，评委也只看到"一张不动的图配了个闪光"。

## B.4 浅色主题下的戏剧张力补偿

> 前提：不回滚靛蓝。冰蓝浅底（`--bg-deep:#d9f1f7`）上，"发光"语法失效（浅底不发光），"厚重"语法失效（浅底不沉）。
> **破解思路：从「夜场发光」语法切换到「印刷/盖章/剧场聚光」语法。** 浅底不是劣势，它只是换了一套语法。

| # | 做法 | 具体参数 | 解决什么 | P | 人天 |
|---|---|---|---|---|---|
| **C1** | **局部压暗：中央"舞台池"** | 对局区（对话流 + 两张对峙卡）容器背景压到 `--bg-mid` 再深一档（如 `#bfe4ee` / 透明度叠 `rgba(30,60,75,.10)`），四周保留 `#d9f1f7` 亮底 → 形成**剧场聚光灯** | 浅底"平"的毛病：画面没有视觉中心 | **P0** | 0.2 |
| **C2** | **异议瞬间：全屏降饱和 + 冲突色满饱和** | 异议 0.9s 内：`#app { filter: saturate(.35) }`，**角色层与异议红字除外**（分层应用 filter，角色层 `saturate(1.15)`） | 这是**浅底独有**的张力手段，暗底上没这招。世界褪色 → 冲突炸出来 | **P0** | 0.2 |
| **C3** | **红/金改用"印刷语法"而非"发光语法"** | 异议红 `#D95159`、认同金 `#B5904F`：配 **2px 硬描边 + 3px 斜切投影（`4px 4px 0 rgba(...)`）+ 45° 斜纹底**，**去掉所有 `box-shadow` 辉光**（浅底上辉光=脏） | 浅底上红金依然炸，靠"实"不靠"亮" | **P0** | 0.2 |
| **C4** | **对峙斜切线** | 对话流与两侧卡之间加 45° `repeating-linear-gradient` 斜纹分隔带（红侧 / 蓝侧各一），呼应美术圣经的"切角票据卡"语言 | 强化"对峙"构图；浅底上斜纹比暗底更清晰 | **P1** | 0.15 |
| **C5** | **暗角改冷色** | `#vignette` 由 `rgba(10,8,20,.85)`（暖黑）改为 **`rgba(22,58,74,.45)`（冷墨蓝）**，更贴合冰蓝且保持压迫感 | 现有暗角在浅底上会发脏、发棕 | **P1** | 0.1 |
| **C6** | **字重与字号兜底** | 正文 ≥ 16px、字重 ≥ 500；**禁用 12px 以下**；浅底上禁用模糊 `text-shadow`（会糊成一团），改用纯色或 1px 硬描边 | 浅底小字在 H.264 压缩下最容易糊（见 B.6） | **P0** | 0.15 |

**C1 + C2 是两个最高杠杆项，合计 0.4 人天。**

> 一句话给大王：**浅底不靠"暗"来压，靠"聚光 + 褪色 + 硬边印刷"来压。** 这三条做完，对峙感不会比深蓝版弱，而且在视频里更清爽、更易读。

## B.5 静态 NPC「看起来像活的」最低方案

### B.5.1 必须做进游戏（可量化清单）

全部通过 B.1 的 CSS 变量通道驱动，**只动 `transform` / `opacity` / `filter`**，不触发 layout。

| 手段 | 量化参数 | 触发 | 优先级 |
|---|---|---|---|
| **呼吸** | `scaleY` 1.000 ↔ 1.015；周期按情绪：calm 3.5s / tense 2.2s / anxious 1.8s+抖动 / desperate 4.5s 不规则 | 常驻 | **P0** |
| **头部微摆** | `rotate` ±0.8°，周期 5s，`transform-origin: 50% 22%` | 常驻 | **P0** |
| **说话点头** | `rotate` −1.5° ↔ +1.5°，打字机期间循环，发言结束回位 | NPC 出字 | **P0** |
| **情绪切换** | crossfade 120ms + `translateY(6px→0)` + 色温：动摇 `saturate(.6)`，绝望 `brightness(.85) saturate(.4)` + 下沉 10px | 档位变化 | **P0** |
| **异议前冲** | `scale(1.06) translateY(-8px) rotate(-2°)`，150ms 冲入 → 250ms 回弹（`cubic-bezier(.2,1.6,.4,1)`） | 异议 | **P0** |
| **受击抖动** | `translateX` 抖动 8px / 200ms + `brightness(1.3)` 闪一下 | 被命中 | **P1** |
| **得意后仰** | `rotate(2deg) translateY(-6px)` 一次性 + 金色光晕 | NPC 命中强项 | **P1** |
| **垂头** | `translateY(10px) rotate(1.5deg)` + `saturate(.4)` | 自信度归零 | **P1** |
| **入场** | `translateX(±40px)` + `opacity 0→1`，400ms | 开局 | **P1** |
| **眨眼** | ⚠️ 需闭眼帧。若无，`scaleY(0.985)` 80ms 微压（弱但免费）；**不建议为此单独出 6 张图** | 随机 2–6s | **P2** |

> **最低可行集 = 呼吸 + 微摆 + 点头 + 情绪切换 + 异议前冲**（全部 P0，0.4 人天）。
> 只做这五项，NPC 在视频里就已经"活着"了。

### B.5.2 诚实标注：哪些能靠剪辑补

| 类别 | 手段 | 是否造假 |
|---|---|---|
| ✅ **可后期剪辑补**（镜头语言，不造假） | Ken Burns 慢推/慢拉、镜头切换、转场闪白/黑、全局调色与锐化、字幕与箭头标注、画中画、分屏布局、倍速 | 否——这是导演手法，任何实机录屏都会做 |
| ⚠️ **有条件可补** | 在**转场处**加闪白、在**剪辑点**加抖动 | 否——只要不落在"游戏内某一刻"上，观众理解为转场 |
| ❌ **禁止**（造假） | 给游戏画面中**某个角色单独**加抖动/发光/位移；伪造游戏内不存在的特效；合成未真实发生的对局过程 | **是**——若评审要求现场演示或补录，会直接穿帮 |

> **给大王的纪律**：S1 实机段必须**一镜到底、零剪辑特效**，只有切镜。所有"看起来厉害的瞬间"必须真的是游戏跑出来的。S2/S3 的标注、分屏、慢推属于讲解镜头，随便加。

### B.5.3 视频真实性自检

录制前逐项确认：**所有在视频里出现的效果，都能在游戏里通过真实操作复现一次。**

## B.6 录屏工程建议

### 硬要求（3 条）

| # | 硬要求 | 参数 | 原因 |
|---|---|---|---|
| **R1** | **1920×1080 @ 60fps，浏览器视口 1:1** | 视口宽高设为 **1920×1080**（`deviceScaleFactor = 1`），不要用手机模拟器 | 异议冲击仅 0.9s，30fps 下会丢冲击锐利感；竖屏在横屏视频里两侧留黑且字太小，直接判"完成度低" |
| **R2** | **码率 ≥ 12 Mbps（1080p60），关键帧间隔 2s** | H.264 High Profile；若平台允许用 H.265 可降到 8 Mbps | 浅底 + 小字是 H.264 压缩的天敌，低码率下正文会糊成一片 |
| **R3** | **实机段保留鼠标指针，讲解段隐藏** | S1 保留（证明是真人在玩），S2/S3 隐藏（指针会抢走标注的注意力） | 全程无指针像"播片"，全程有指针会干扰 |

### 完整参数表

| 项 | 建议 |
|---|---|
| 录制工具 | OBS（窗口捕获，非显示器捕获，避免任务栏入镜） |
| 分辨率 / 帧率 | 1920×1080 / 60fps |
| 视口 | 1920×1080，`deviceScaleFactor=1`，**桌面布局**（不模拟移动 UA） |
| 码率 / 编码 | ≥12 Mbps CBR，H.264 High，关键帧 2s |
| 音频 | **系统音 + 麦克风分轨录制**。系统音必须包含 `playImpact()` 的冲击音（打击感来源） |
| ⚠️ TTS | 演示前**关闭或调低** `🔊` 语音——机械/神经音会抢戏且拖慢节奏，建议 S1 静音、仅保留冲击音 |
| 字体清晰度 | 正文 ≥16px、字重 ≥500；**禁用 <12px**；浅底禁用模糊 `text-shadow`；`theme.css` 的 `--text-dim:#5d717b` 在浅底上偏灰，视频中建议提到 `#4a5c66` |
| **规避 AI 水印入镜** | ① 录制前 DevTools → Network 确认 `portrait/*.webp` **零 404**（404 会回退到带水印的 `npc_t*.png`）<br>② 提前跑一遍完整对局预热，确保 `fallback` 不被触发<br>③ 页脚 AI 声明**保留**（合规加分），字号压到 11–12px 置于角落<br>④ 录制前清缓存并完整重载，避免首帧闪出占位图 |
| 录制前检查 | ① 关闭系统通知/输入法候选框 ② 关闭其他标签页 ③ 确认 `#fx-*` 五项全开 ④ 确认 `prefers-reduced-motion` 未开启（**开了会关掉全部演出**）⑤ Network 零 404 |
