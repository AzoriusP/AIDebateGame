这是首轮生产分层。后续眼睑需要形成清楚的闭合与中间形态；嘴内与口缘必须能闭合；肩肘腕移动不能露空。第二版指向手与整臂需具备朝对手伸出的透视和轮廓，不能靠旋转普通手臂代替。

## 第一轮：5 主参数 + 眉形 + 嘴形

以下为项目规格；其中眉形是新增的共用自定义参数。只创建当轮会绑定的参数。

当前真正通过的是表内前五项（Breath、EyeL、EyeR、MouthOpenY、Objection）。后两项眉形/嘴形仍是计划，不能将运行时代码存在或空默认参数存在说成已经绑定。正式导出当前保留 28 个总参数，未来新增参数前先核对 motion、expression、物理及运行时引用，再清理确实不需要的空默认项。

| ID | 范围 / 默认 | 键形态 | 作用 |
|---|---|---|---|
| ParamBreath | 0…1 / 0 | 0、1 | 胸腹和肩部轻微呼吸；身体父变形器承担 |
| ParamEyeLOpen | 0…1 / 1 | 0、0.5、1 | 左眼闭合、半开、睁开 |
| ParamEyeROpen | 0…1 / 1 | 0、0.5、1 | 右眼闭合、半开、睁开 |
| ParamMouthOpenY | 0…1 / 0 | 0、0.5、1 | 闭嘴、普通说话、异议发声 |
| ParamObjection | 0…1 / 0 | 每个绑定对象至多 3 键 | 常态臂/指向臂切换、伸出、身体前倾 |
| ParamBrowForm | -1…1 / 0 | -1、0、1 | 悲伤/担忧、中性、紧绷/坚决眉形 |
| ParamMouthForm | -1…1 / 0 | -1、0、1 | 低落口形、中性、坚决口形 |

`ParamBreath`、左右眼、`ParamObjection` 沿用 proof 中已验证的语义。标准名称依据 [官方参数表](https://docs.live2d.com/en/cubism-editor-manual/standard-parameter-list/)；本项目定义具体外观与动作幅度。

新建工程后先清理空默认参数。proof manifest 实际记录 28 个参数，但仅 4 个必要参数有动作；若原样保留再加换装参数，很快超过 FREE 的 30 个上限。Parameter 面板菜单提供 `Delete empty parameters`，删除没有对象关键形态的参数；不要在建立了待绑定参数后盲目重复执行。参见 [官方 Parameter 面板](https://docs.live2d.com/en/cubism-editor-manual/palametorpalatte/)。

推荐结构：身体呼吸 → 异议前倾 → 脸部/衣身/手臂；脸部下设左右眼和嘴部形变。常态臂和指向臂各有可见性父变形器；当前整层指向分支先做肩部支点与整体前伸，未来需要独立前臂运动时再细分。眉形在眉网格或眉变形器上，嘴形与开合放在父子节点或两个直接绑定轴上。

`ParamObjection` 的可见性可用 0、0.1、1 三键：常态臂透明度为 100、0、0，指向臂为 0、100、100；几何运动使用自身合适的 2–3 键。播放时跨过 0…0.1 的切换区，减少双臂重影，再连续伸出到 1。运行时或动画必须实际验证此切换；首轮不新增单独 Pose 参数。透明度也可在变形器中控制其子 ArtMesh，参见 [官方 Inspector 属性](https://docs.live2d.com/en/cubism-editor-manual/inspector-palette/)。

每个绑定轴补齐范围两端；眉/嘴双轴的组合形态也要逐一查看，不能只拖单轴。现有 proof 的几何形变只能证明接口可动，不代表正式眼口绑定已经完成。

## 四状态与异议节奏

四状态是眉、眼、嘴与呼吸时序的组合，不复制四套整脸。以下是 `demo/static/character-performance.js` 当前已实现值，属于虚构角色的调试起点，仍需正式模型校正。

| 状态 | 脸部起点 | 呼吸起点 | 眨眼起点 |
|---|---|---|---|
| 冷静 / calm | 眉形 0、眼开度 1、嘴形 0 | 周期 4.2 s，深度 0.32 | 基准间隔 4.6 s |
| 焦虑 / anxious | 眉形 -0.4、眼开度 1、嘴形 -0.3 | 周期 1.7 s，深度 0.58 | 基准间隔 2.2 s |
| 紧张 / tense | 眉形 0.8、眼开度 1、嘴形 0.3 | 周期 2.6 s，深度 0.45 | 基准间隔 3.0 s |
| 绝望 / desperate | 眉形 -1、眼开度 0.75、嘴形 -0.8 | 周期 1.15 s，深度 0.72 | 基准间隔 1.7 s |

当前眨眼间隔在基准的 0.75–1.25 倍内作种子随机变化，闭合周期为 0.18 s；首次眨眼在重置后约 2–4 s，呼吸输出有平滑。代码尚未实现表中旧建议的偶尔双眨或绝望单独慢眨。眉嘴数值为确定性状态映射，不随说话开关变化。

`tools/live2d/src/preview.ts` 及构建产物已接入 `ParamBrowForm` / `ParamMouthForm`，仅写入实际存在且未被活动动作占用的参数；自动表现关闭时直接跳过，手动固定值最后覆盖。共享驱动暂停时冻结值，禁用动作时清零眉/嘴形，重新启用后使用当前状态。类型检查、构建及 19 项测试通过；官方 Core 对旧几何 proof 的 36 组状态/异议姿态验证五个网格顶点和透明度不变。正式角色的眉嘴形变尚未制作，当前四状态主要通过呼吸和眨眼节律体现。

数值必须以正式美术校正，第一轮通过条件是四状态能被肉眼区分。眨眼系数应乘在当前状态的眼开度上，结束后回到当前开度；嘴开合驱动与嘴形分开。网页每帧恢复稳定基态，再合成状态、呼吸、眨眼、说话、异议，避免多个循环互相覆盖或逐帧累加。

当前打包的原创异议为 1.5 s：0–0.12 s 准备；0.12–0.20 s 将 `ParamObjection` 从 0 推到 1；保持至 1.12 s；1.12–1.20 s 回到 0；1.5 s 结束。`ParamMouthOpenY` 在 0.12–0.20 s 打开，在 0.8–1.12 s 关闭，全程由 motion 接管。全局 FadeIn/FadeOut 为 0.03/0.05 s。

当前 MOC 两臂透明度仅在 0/1 端点互斥，中间线性交叉淡化；motion 把两次换臂窗口各压缩至 80 ms。官方 Framework 对真实 MOC 的采样确认 0.16/1.16 s 时两臂均为 0.5，因此不能宣称全程互斥或肩肘腕连续骨骼伸展。`work/live2d/male-master/motion-audit.json` 已通过格式和时间采样检查。

网页实测也已通过：点击异议后 450ms 暂停，真实模型开口伸指，MouthOpenY/Objection 都为 1，暂停中保持；继续播放后两者归零并显示动作结束。四状态参数更新、卸载后异议禁用、重载一个动作成功，控制台无错误/警告。该检查仍不等于完整眉嘴情绪、换装、NPC 或实际对局接入完成；连续触发和更细过渡仍可继续回归。

1. 已完成 `source-v2` 的 13 层 PSD、图层清单及四张合成预览，画布固定为 1024×1536；保留原 11 层包作回退依据。

3. 菜单 `Modeling → ArtMesh → Automatic Mesh generator` 建初始网格；眼、口缘、关节手工修正。先完成网格再加动作。
4. 用 `Modeling → Deformer → New Rotation Deformer` / `New Warp Deformer` 建层级，Inspector 检查父节点、支点、绘制顺序。不能把所需运动的手臂留在错误衣身分支。

6. `Modeling → Texture Atlas → Edit Texture Atlas` 建一张图集，优先 2048×2048。不要等全部绑定后才检查脸与指向手的导出清晰度。
7. 本机 5.3.04 已实际使用的入口为 `File → Export For Runtime → Export as moc3 file…`。通过正式角色验收后进入第二轮换装。

菜单依据 [官方 Modeling 菜单](https://docs.live2d.com/en/cubism-editor-manual/modeling-menu/)，键形态依据 [官方添加/删除键](https://docs.live2d.com/en/cubism-editor-manual/edit-parameters/)。本机 `Ctrl+Shift+A` 与飞书截图冲突，网格操作走菜单。

## 从 proof 或已有正式模型重导入的区别

官方 PSD 重导入适合更新原图：保持层名、文件夹名、顺序稳定，拖入 PSD 后选择目标模型与被替换的来源 PSD。仅含新增层的文件使用 `Add all Layers as new ArtMesh`。匹配错误时，选择目标 ArtMesh，在 Project → Source Image 中找到正确层，使用 `Set as input image for selected object`。修改网格后原关键形态可能需要修正。参见 [官方 PSD 重导入](https://docs.live2d.com/en/cubism-editor-manual/psd-re-import/)。

本项目据此采用以下办法：

| 情况 | 执行办法 |
|---|---|
| 正式母模原图同层改色、修线 | 对模型副本重导入，保持原对象，检查参数、ID 和关键形态 |
| 同层轮廓增大 | 重导入后扩网格及父变形器有效范围，回归已有形态 |
| 第二套头发/脸/衣服 | 唯一新层名，新增网格与父节点，再绑定外观参数及局部动作 |
| 将原来一层拆成多层 | 把它视作新增/改造局部绑定；不要假设原层参数自动完整传播 |
| 五层几何 proof 换成正式人物 | 新建正式工程，只复用已验证参数契约与网页流程 |

保留 ID 的含义是保留原目标对象、更新它的输入图像，不是把新 PSD 层名当成参数绑定。任意第三方重写 PSD 的自动匹配没有保证；每次以实际对象检查为准。proof 的 512×512、五层与正式母模的尺寸、轮廓、锚点都不同，直接替换需要大量修正，因此保持正式工程独立。
