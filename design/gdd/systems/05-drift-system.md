## ① 概述与目标

**一句话职责**：让 NPC 的六维在**单局之内**随玩家打法持续变化——被打疼的软肋上浮警觉、被冷落的维度下沉露出新破绽、被反驳的强项越辩越固——使"最优解随对局推进而失效"，玩家必须持续读人。

**对应设计支柱**：总纲 §4.2 支柱 2「对手是活的（A living opponent）」，落点是**反抄作业**。支柱 1「先读懂再出拳」是本系统的**存在前提**：漂移必须先被玩家读到，否则它只是隐藏的随机性（见 §③）。

**删掉它会失去什么**：若六维静态不变，玩家背住一条软肋即可通关，本作从"读人博弈"退化为"查表解谜"——支柱 2 崩塌，Fun Hypothesis 中的"洞察 + 对手会反抗"同时失效。

**本系统不负责什么**（划清边界）：

| 不负责 | 归属 |
|---|---|
| 跨局长期成长（channel 2：持久 ±2、记忆摘要、`npc_state.json`） | 未来的 `21-npc-memory-growth.md`（C4） |
| 维度/强度判定（Judge） | A2（core-loop §3.2/§3.3） |
| 自信度查表换算 | A3（core-loop §3.4） |
| 雷达图如何画 | D1（core-loop §5.1 + art-bible） |

### A8 通道分层（2026-09-07 裁决落地 · 独立小节）

> 背景：旧文档将「局内漂移 ±3」与「跨局成长 ±2」都只写成"钳制"，未标层级，±2/±3 极易混淆。裁决文档 §2 定案：**显式拆成两条独立通道**。本文件落地该裁决。

| 通道 | 名称 | 作用域 | 生命周期 | 钳制 | 驱动 | 存储 | 归属文档 |
|---|---|---|---|---|---|---|---|
| **通道 1** | **局内漂移（drift）** | 单局内六维的临时变化 | **局末清零**（`new_session` 重建 `drift = 全 0`） | 单维 **±3.0**（`DRIFT_CLAMP`） | 每回合结算：`DRIFT_VIGILANCE 0.5 / DRIFT_ABANDON 1.0 / DRIFT_FORTIFY 0.5`，**× 该 NPC 个性乘数** | 会话内存（`state["drift"]`） | **本文** |
| **通道 2** | **跨局成长（growth）** | NPC 因与你交手而产生的长期变化 | **持久化**，可一键重置 | 单维累计 **±2** 封顶，冷落缓慢回弹 | 局终按有效命中维度统计微调 | `data/npc_state.json`（`adj`） | `21-npc-memory-growth.md` |

**两条通道在玩家感知上是两件事**：漂移是"这一局 TA 在变"（临时、可当场读图）；成长是"TA 记得你、变难了"（跨局、持久）。二者**只在读数时合并**，从不互相写入——见 §⑥ 接口契约。

## ② 核心机制（规则 / 状态 / 流程）

### ②.1 完整判定链（一回合，含时序）

```
玩家一句话
   → [A2 Judge] 产出 {dimension, strength, confidence}          （LLM，只做映射）
   → [A3 查表]  delta_conf = CONFIDENCE_DELTA[direction][strength]  （direction 由 _direction 给出）
   → [本系统]  漂移结算（R1/R2 → 记 _last_hit → R3 → R4 钳制）   （本回合，确定性纯函数）
   → [本系统]  下一回合 _direction() 读取「叠加后的当前值」        （漂移的效力在下回合生效）
   → [D1]      雷达图刷新「叠加后的当前值」                        （玩家立刻看到）
```

> **关键**：漂移结算发生在 `delta_conf` 之后、本回合判定已用**旧方向**；漂移写入后，**下一回合**的方向判定与置信查表才使用漂移后的新值。因此"软肋会被打没、冷落维会变成新软肋"是**滞后一回合生效**的——玩家每次都打"上一回合读到的图"。这条滞后是节奏的一部分，不是 bug。

### ②.2 当前值公式（一切判定与显示的输入）

```
V_current(d) = base[d] + drift[d] + adj[d]     （round 到 2 位小数）
```

| 项 | 含义 | 来源 |
|---|---|---|
| `base[d]` | 该维初值（0–10） | `npcs.json: dimensions`（只读，漂移不改写） |
| `drift[d]` | 局内漂移累计（通道 1） | 本文管理，钳制 ±3.0 |
| `adj[d]` | 跨局成长修正（通道 2） | `npc_state.json: adj`，仅 `memory_on = true` 时并入 |

- **方向判定（`_direction`）读 `V_current`**：`≤ 4.0` → 软肋（weak）；`≥ 6.5` → 强项（strong）；其余 → 普通（normal）。
- **弃守目标选择（`_weakest_dim`）也读 `V_current`**：取最小值的维度（排除最近命中维，见 R3）。
- 取值范围说明：`V_current` **允许越出 [0,10]**（如 base 9 的强项被连加 drift 到 12）。判定阈值口径不受影响（越界后仍 ≥6.5 / ≤4 语义不变）；显示层由前端夹取到 [0,10]（见 §⑦ 边界 2）。

### ②.3 规则逐条枚举（每回合结算后，顺序执行；R1 与 R2 互斥——direction 每回合只有一个值）

**R1 · 警觉上浮**
- 触发条件：`_direction(dim) == weak` 且 `|delta_conf| ≥ 20` 且 `dim` 非空。
  - 由 CONFIDENCE_DELTA 可知：命中软肋 L1 = −8（|Δ|<20，**不触发**）、L2 = −20、L3 = −40。**有效命中 = L2/L3**。
- 效果：`drift[dim] += DRIFT_VIGILANCE × npc.drift_personality.vigilance_mult`
- 意图：NPC 意识到被戳中，开始补强/绕开。L1 弱命中视为"没打疼"，不引起警觉。

**R2 · 强项加固**
- 触发条件：`_direction(dim) == strong` 且 `dim` 非空。
- 效果：`drift[dim] += DRIFT_FORTIFY`（**不乘个性乘数**——加固是全 NPC 一致的固执，与个体警觉差异无关）
- ⚠️ 实装注记：触发只看方向（strong），不看强度——**即使 L1 命中强项（delta_conf = 0，"NPC 不屑，不涨不跌"）也会触发 +0.5 加固**。语义上"不屑"是否还应"更固一步"存疑，登记 §⑧ 待定 3。

**R3 · 弃守下沉**
- 触发条件：每回合结算后必然评估一次（**含 L0/无效回合**——时间在流逝，NPC 注意力仍会被拉走）。
- 目标选择：`V_current` 最小的维度，且**排除最近命中维**（`_last_hit`，本回合命中的维度，L0 回合则沿用上一命中维）。
- 效果：`drift[weakest] −= DRIFT_ABANDON × npc.drift_personality.abandon_mult`（仅当存在满足条件的目标）
- 意图：冷落的维度逐回合滑向 ≤4，变成新软肋——这是"旧软肋被打没后，总有新破绽浮出来"的引擎。

**R4 · 钳制**
- 效果：每次写入 drift 都经 `_clamp`：`drift[d] = max(−3.0, min(3.0, drift[d]))`（`DRIFT_CLAMP`）。
- 意图：单维总漂移受限 → 人格"可识别"、初值仍可辨认，NPC 不会漂成另一个人。

### ②.4 一次完整的"软肋失效 + 新软肋浮现"循环（示例链）

以陆教授（L5，EMOTION base 2，`vigilance_mult 1.4 / abandon_mult 0.6`）为例：

```
开局：EMOTION=2(软肋)  IDENTITY=5  UTILITY=6 …
T1 玩家 L2 命中 EMOTION（weak，Δ=−20）
    → R1: drift[EMOTION] += 0.5×1.4 = +0.7 → 当前 2.7（仍 weak）
    → R3: 排除 EMOTION，最弱为 IDENTITY → drift[IDENTITY] −= 1.0×0.6 = −0.6 → 4.4
T2 玩家 L2 命中 EMOTION
    → R1: drift[EMOTION] += 0.7 → 3.4（仍 weak）；R3: IDENTITY → 3.8 → 已跨 ≤4，**新软肋浮现**
T3 玩家 L3 命中 EMOTION
    → R1: drift[EMOTION] += 0.7 → 4.1 → 判为 normal，**旧软肋失效**
    玩家此刻在雷达图上看到：EMOTION 升回普通、IDENTITY 已沉到新软肋 → 必须换维
```

- 上例说明**软肋平均可有效命中约 3 次**（高层）；低层 NPC 警觉慢（王阿姨 vigil 0.8 → 步进 0.4），软肋存活命中次数更多（约 5–6 次），新手容错更高。**该节奏是设计目标，不是偶然结果**——见 §④ 数值约束 C1 与 §⑧ 待定 2。

### ②.5 与「抄作业三重防线」的关系

动态漂移是第一道防线（本系统本体）；情报误差带（D1，玩家看到的是带误差的估计）与「命题 × 人设耦合」是第二、三道，本系统只保证第一道成立——**若漂移不生效，后两道防线失去意义**。

## ③ 玩家交互与 UX

> 本系统是**被动观察型**系统：玩家不输入任何命令，靠"读图"与"读结算标签"建立心智模型。**漂移机制存在的前提 = 玩家能感知漂移**（支柱 1）。感知缺失则机制等同隐藏随机，玩家会归因于玄学。

### ③.1 玩家必须能收到的三类信号

| 信号 | 内容 | 玩家据此的决策 | 状态 |
|---|---|---|---|
| **维度数值移动** | 雷达图各轴显示的 `V_current`，软肋升、冷落维降、强项固 | "这张图在动 → 我不能一条道走到黑" | **部分实装**：雷达图基础版（renderRadar：六维多边形 + 数值标签 + 软肋 ≤4 黄字 + 命中维红点）已实装；漂移值随回合刷新呈现由 D1 承接 |
| **方向性漂移提示** | 本回合漂移过的维度给出升/降箭头 + 命中热度（波纹/纹理由虚变实） | "刚打过的这条在补强 / 那边在露破绽" | **未实装（D1 演进项，规格约束）** |
| **判定标签反馈** | 每次结算固定输出「维度 × 强度 × 方向」标签（如 `情感 · L2 · 命中软肋`） | "这句话为什么有效 / 为什么被反驳" | 已实装（`turn_resolved` 事件） |

> **实现状态二分（2026-09-07 工程核实）**：`demo/static/app.js` 的 `renderRadar()`（L111 起）**已实装雷达图基础版**——六边形网格 + 六维多边形 + 每维数值标签 + 软肋值 ≤4 显示黄色 + 命中维度红点高亮。**漂移专属可视化（方向箭头 / 命中热度 / 新软肋浮现高亮）均未实装**，属 D1 演进项，本文仅作规格约束。D1 开发时以"基础版已有、待加漂移信号"为起点。

### ③.2 给 D1 的可读性硬约束（本系统对雷达图的最低要求 · 三条均为 D1 演进项，当前未实装）

1. **方向必须可见**：即使数值精度被误差带掩盖，漂移的**方向**（升/降/不变）不能被误差带吃掉——否则玩家无法判断"这条还有没有戏"。
2. **命中热度可回溯**：最近 2–3 回合被命中的维度要有残留标记，让玩家看出"我一直在打这条"。
3. **新软肋浮现要给提示**：维度从普通跨入 ≤4 的当回合，需要有别于普通降值的呈现（否则玩家发现不了新破绽，反抄作业无从谈起）。

> 若 D1 无法满足以上任一条，漂移机制的效果将不可见——**这是本系统与 D1 之间的硬接口契约，不是软建议**（§⑥ 输出列重申）。

### ④.3 个性乘数全表（5 名对手 · 实装 `drift_personality`）

| 层 | NPC | `vigilance_mult`（警觉快慢） | `abandon_mult`（弃守快慢） | 难度含义 |
|---|---|---|---|---|
| L1 | 王阿姨 | **0.8** | 1.0 | 警觉最慢 → 同一软肋可反复打，新手容错高 |
| L2 | 林经理 | 1.0 | 1.0 | 基准 |
| L3 | 陈博主 | 1.1 | 1.0 | 警觉略快 |
| L4 | 赵律师 | 1.2 | **0.8** | 警觉快 + 弃守慢 → 旧软肋失效快、新软肋出得慢 |
| L5 | 陆教授 | **1.4** | **0.6** | 警觉最快 + 最难露出新破绽，叠加"软肋仅 1 个"，构成 L5 核心难度 |

**设计意图（这条梯度是支柱 2 的量化表达，是难度分层的一部分）**：

- `vigilance_mult`：越高 = 玩家**越难持续打同一个软肋**（补强快）。L1 0.8 是新手保护（打同一个点能多打几次建立正反馈），L5 1.4 逼高手必须不断换维。
- `abandon_mult`：越低 = 被冷落的维度**越难自然下沉成新软肋**。陆教授 0.6 意味着玩家"等 TA 露破绽"的耐心会枯竭——**高警觉 × 低弃守的组合，效果是"又不能不换维、又等不来新破绽"**，只能靠更强的论据硬啃单软肋。
- 二者**与软肋数量、token、判定严格度协同**构成难度曲线（L5：单软肋 + 最快警觉 + 最难弃守 + token 最少），而不是任何单一维度单独负责难度。

### ④.4 数值约束（调参不可违反的设计意图）

- **C1 · 软肋必须"会失效但不会立刻失效"**：警觉步进 × 初值到阈值的距离，决定了同一软肋的可打次数。目标区间：高层 ≈ 3 次有效命中失效，低层 ≈ 5–6 次（新手容错）。**当前实装值与 MEMORY 记载的"2–3 次"存在口径差异**，登记 §⑧ 待定 2。
- **C2 · 下沉必须能造出新软肋**：`DRIFT_ABANDON × abandon_mult` 逐回合累积要足以让相邻档普通维跨过 ≤4。L5 陆教授 IDENTITY 5 → 0.6/回合 ≈ 2 回合后 3.8（变软肋），节奏可接受。
- **C3 · 钳制保"人格可识别"，不保"不跨档"**：钳制 ±3.0 大于阈值区间跨度（6.5 − 4.0 = 2.5），**允许单维在整局中跨档翻转**（普通维沉成软肋、软肋补回普通）——这**正是**新破绽产生的机制。"人格不崩"由钳制限总量保证，不由禁止跨档保证。⚠️ 注意：模板 §3 半填充示例曾写"钳制须小于阈值跨度"，与实装矛盾，此处在正式 GDD 中**予以更正**。
- **C4 · 警觉步进 < 弃守步进（对同一目标）**：警觉只在被打时触发（0.5×vig），弃守每回合对最弱维触发（1.0×aban）。全局步进大小关系随 NPC 个性变化，不做硬性大小约束；由 playtest 校准目标节奏（C1）。
- **C5 · 任何调参不得把基准系数写死进逻辑**：四参数必须可外置（指向 F8 数值表工作项，裁决文档 §6）。

### ④.5 校准方法

- 工具：`demo/playtest.py`（纯数值模拟，可重跑）。
- 观测指标：① 同一软肋的可打次数（应落在 C1 区间）；② 固定一套话术打到底的通关率（反抄作业目标：应显著低于换维打法）；③ 新软肋浮现所需冷落回合数（C2）。
- 人工复验：试玩三步法（见 §⑧ 验收 6）。

## ⑥ 与其他系统的接口

### ⑥.1 接口表

| 方向 | 对端 | 数据 | 时机 | 失败约定 |
|---|---|---|---|---|
| 入 | F6 结算引擎（同一纯函数段） | `{dimension, strength, delta_conf}` | 每回合自信度/token 结算后 | 字段缺失或 `dimension == NULL` → 跳过 R1/R2，仍执行 R3/R4 |
| 入 | F1 会话状态层 | `state.drift` / `state._last_hit` / `state.memory_on` | 读写同帧 | 状态不存在 → 按 0 处理，不抛异常 |

| 出 | D1 雷达图 HUD | `{dim, drift_delta, V_current}` | 随 `turn_resolved` 事件同帧 | 前端未收到 → 沿用上一帧 |

### ⑥.2 与通道 2（C4 跨局成长）的接口契约

> 归属：通道 2 的规则在 `21-npc-memory-growth.md`，**本文只立契约**。真值源：`_current_dims()` / `_finalize_match()`。

1. **合并只发生在读数时**：`V_current = base + drift(通道1) + adj(通道2)`，由 `_current_dims()` 统一计算——通道 2 不写 `state.drift`，通道 1 不写 `npc_state.adj`。
2. **`adj` 只在 `memory_on = true` 时并入**（自由切磋模式记忆关 = 纯净，等价于无成长）。
3. **漂移的目标选择与方向判定都基于合并后的 `V_current`**——即成长也会改变"当前谁最弱"，漂移会沿着叠加后的值继续演化。两条通道是**串行叠加**，不是并行两套人格。
4. 通道 2 的微调按"本局有效命中维度"统计（含 L1），与通道 1 的"警觉只认 L2/L3"**口径不同**——这是两条通道各自的设计，不是 bug（L1 蹭刀虽不引起警觉，但会让 NPC 跨局长记性）。

### ⑥.3 与 LLM 的边界

- **LLM 完全不参与本系统**。漂移是确定性纯函数（ADR-002/003）：玩家无法用任何话术影响漂移方向或幅度（不能"话疗 NPC 别补强"）。
- Judge 只产出本回合 `{dimension, strength, confidence}`，无权读取或改写 drift；NPC 只产出台词，不被注入 drift 数值（NPC 不该"知道"自己软肋的数字）。

## ⑦ 边界情况与失败处理

| # | 类别 | 现象 | 判定 | 处理 | 玩家可见反馈 |
|---|---|---|---|---|---|
| 1 | **AI 失效** | Judge 超时 / 非法 schema / 置信度不足 → 降 L0（`dimension = NULL`） | `dim == None` | 跳过 R1/R2（无命中不警觉不加固）；**R3 仍执行**（时间流逝，冷落维继续下沉）；`_last_hit` 不更新 | 该回合无命中高亮，雷达图仍有 1 条冷落维下降 |
| 2 | 状态边界 | `V_current` 越出 [0,10]（如 base 9 强项 +drift→12；base 2 软肋 −drift→−1） | `base+drift+adj` 越界 | **判定层不夹取**（阈值口径 ≥6.5 / ≤4 在越界后仍正确）；**显示层前端夹取到 [0,10]** | 雷达图显示被夹取，不显示负数/超 10 |
| 3 | 状态边界 | 本回合命中维恰好是全局最弱维 | `_last_hit == weakest` | R3 跳过该维（排除规则内置），避免"同一维边升边沉"自抵消 | 无 |
| 4 | 玩家侧异常 | L0 回合（空话/刷屏/注入），`_last_hit` 保持上一次命中维 | `dim == None` 且 `_last_hit` 非空 | 弃守下沉继续回避最近命中维（等效"刚被打的点不立即下沉"） | 无（行为是否保留见 §⑧ 待定 4） |
| 5 | 玩家侧异常 | 玩家用 L1 反复戳同一软肋（"蹭刀流"） | direction weak 但 L1（\|Δ\|=8 < 20） | 不触发 R1 → 软肋不上浮，可慢速磨血；**存在低层"L1 蹭刀流"通关的平衡风险** | 无（风险评估见 §⑧ 待定 1） |
| 6 | 极端状态 | 六维全部 ≤4（全部成软肋） | 所有维 weak | 判定仍按表走（全弱 = 每击都有效）；`_weakest_dim` 照常返回最小值，漂移继续 | 正常结算 |
| 7 | 状态边界 | 连击/多命中结算与漂移同回合 | 无冲突 | 漂移只依赖最终 `{dimension, strength, delta_conf}`，不感知连击 | 正常结算 |
| 8 | 内容/安全 | NPC 站位与命题（本系统无关，仅完整性提醒） | — | — | — |

### ⑧.1 验收标准（可判定 · 每条附观测方法）

1. **反抄作业有效**：数值模拟 + 人工试玩中，"固定一套话术打到底"的通关率显著低于"读图换维"打法（脚本：`playtest.py` 对比两组策略通关率）。
2. **软肋会失效且会换位**：连打同一软肋，数次命中后该维判为 normal（模拟断言：`V_current` 跨 >4）；随后冷落维沉到 ≤4 产生新软肋（模拟断言成立）。
3. **人格可识别**：整局任一时点 `|drift[d]| ≤ 3.0`；模拟全 20 回合后，任一位玩家应仍能说出"TA 大体是原来那个人"（人工试玩抽样）。
4. **可复现**：同一输入序列跑两次，漂移结果逐回合完全一致（纯函数无随机，配单测）。
5. **AI 失效不阻塞**：Judge 超时降 L0 时，回合照常推进、漂移 R3 照常执行、NPC 回复不中断（注入故障测试）。
6. **玩家可感知（试玩三步法）**：① 只打一个软肋连打 5 回合 → 应观察到收益递减 / 软肋失效；② 换到新浮现维度 → 应重新有效；③ 全程不改打法 → 应打不赢（L1 以上）。
