## ① 概述与目标

**一句话职责**：用一段**零延迟、零 token、不可编辑的脚本化对局**，在 30～60 秒内把一个冷启动玩家（或评委）的心智从"像吵架一样乱打"矫正为"先读软肋，再出拳"，并把这段体验**以一次真实的胜利收尾**。

**对应设计支柱**：总纲 §4.2 支柱 1「**先读懂，再出拳**（Read, then strike）」——这是全作的第一支柱，也是本教学关唯一要注入的核心心智。次要涉及支柱 3「每一句话都是资源」（只用最小提示，不教，见 §③）。

**删掉它会失去什么（本关存在的理由）**：`00-game-concept.md:247` 成功标准 #5 白纸黑字写着"冷启动玩家不看任何说明能在合理尝试次数内通关 L1"，但**当前全项目零教程实现**（无代码、无文档、无帮助入口）。失效链条已被推演确认：

```
冷启动玩家凭直觉 → 打 EMOTION / IDENTITY（王阿姨的强项）+ 上来就是 L1 弱质论证
   → 命中强项 L1 = 自信度 0 变化（core-loop §3.2：强项 L1「NPC 不屑，不升不降」）
   → 玩家打了几轮，数值一动不动 → 归因「这游戏没反馈」→ 退出
```

这条链条恰好同时击穿：成功标准 #5（赢不了）、支柱 1（"读人"从未被体验）、以及评审第一印象（`submission-tech-readiness.md`：评委第一屏是"全解锁关卡列表 + 零解释"，30 秒看不懂即关掉，这段就是评委对游戏的完整印象）。

**本关不负责什么**（划清边界）：

| 不负责 | 归属 |
|---|---|
| 教 token 经济（精炼表达 / 刷屏惩罚 / 废话题惩罚） | 正式对局 + A4 Token 经济 GDD；本关只用最小提示（§③） |
| 教立场分配规则（为什么我站反方） | A8 立场分配 GDD + 玩法帮助入口；本关立场固定、不解释 |
| 教六维漂移 / 跨局记忆 / 系列赛 | 对应系统 GDD；本关**刻意不触发**漂移（见 §⑥），避免一次注入两个以上新概念 |
| 替代正式 L1 对局 | 本关结束后玩家仍需自己打通天梯；本关**不解锁任何关卡**（§②） |
| 任何 LLM 调用 / 任何自由文本 | 硬约束 ③④；本关是纯前端状态机（§⑥「与 LLM 的边界」） |

## ② 核心机制（规则 / 状态 / 流程）

### ②.1 触发与退出规则

**触发时机（大王 2026-09-10 拍板：仅主界面按钮，不自动播放）**

```
主菜单（mode-screen）
   │
   └─ 玩家点「新手教学」卡（#mode-tutorial）
         │
         └─► runTutorial()  ──► 胜利演出  ──► 结算页（复用 #result-overlay） ──► 点「返回主界面」 ──► showMode()（高亮「天梯」卡片）
```

> **不自动播放，登录/游客流程保持原样**，教学不参与启动链路。
> 否决自动播放的理由：需 hook `bootstrapIdentity()` 并抢占首屏资产加载顺序（R10 首屏预算），
> 改动面与登录流程耦合；而主菜单常驻卡片已覆盖"想看的人能找到"。

| # | 规则 | 结论 | 依据 |
|---|---|---|---|
| T1 | **何时触发** | **从不自动触发**。唯一入口 = 主菜单「新手教学」卡（`#mode-tutorial`）被点击 | 大王 2026-09-10 拍板：登录流程保持原样，不为教学改动启动链路 |
| T2 | **"已看过"如何记录** | **不记录**（该机制已整体移除） | 不再自动播放 → 无需"防重复弹"标记。教学仍**不写** `progress.json` / `npc_state.json`（零存档污染；`progress.json` 的 `highest_cleared` 是全局单值、有并发写隐患，见 R7/G2） |
| T3 | **能否跳过** | **能**。教学条常驻「跳过教学」按钮，任意步可点 | SDT 自主性：不想看的人不该被拦。因不自动播放，不存在"反复弹"问题 |
| T4 | **过完是否写 `progress.json`** | **不写 `highest_cleared`**。教学不是天梯对局，写它会让"看个教程"直接解锁 L2，破坏天梯节奏 | 天梯进度语义 = "战胜本层"，教程的胜利是教学性的，非真实战绩 |
| T5 | **重看** | 主菜单常驻「新手教学」卡（即唯一入口），随时可再点，每次从 step 0 开始 | 重看是正当需求（玩家/评委/录屏）；卡片常驻比"藏在设置里"更易达 |
| T6 | **与 `judge_mode` 的衔接** | 同普通玩家：**通过主菜单卡片进入，不自动播放**。播放结束后弹与普通关卡一致的结算页（`#result-overlay`），点「返回主界面」回主菜单（**不自动跳 L1**），且**不写 progress、不写真实战绩** | 大王拍板：评委也走同一个按钮。全解锁解决的是"能玩到几层"，不解决"看懂怎么玩" |
| T7 | **中途退出** | 关页面/刷新 → 无任何记录 → 下次点卡片从头播 | 教学关无状态、时长极短，从头播成本 < 维护续播状态的成本（简化优先） |
| T8 | **每步推进方式** | NPC/系统步：点击任意处 / 「继续」推进；玩家步：**只读发言卡 + 「就这么说」按钮**（见 §③） | 见 §③ 交互形态论证 |

> **自动播放方案已整体关闭**（含原"身份前 B / 身份后 A"两档）。若赛后数据表明冷启动流失严重，
> 再评估"首次进入自动播一次"——届时必须先解决首屏资产优先级（R10）。

### ②.2 状态机

```
[NOT_STARTED]
   │ 点击主菜单「新手教学」卡（唯一入口，无自动触发）
   ▼
[STEP 0] ── advance(click/button) ──► [STEP 1] ── … ──► [STEP 8]
   │                                                        │
   │ 跳过（任意步）                                          │ advance
   ▼                                                        ▼
[SKIPPED] ──► showMode()                          [VICTORY 演出] ──► 结算页（#result-overlay，复用普通关卡 UI） ──► 点「返回主界面」 ──► showMode()（高亮天梯卡）
```

**状态字段（前端会话内存，不落盘）**：

| 字段 | 类型 | 范围 | 说明 |
|---|---|---|---|
| `tut.active` | bool | — | 教学是否进行中；为 true 时禁用 `/api/message`、计时器、自由输入 |
| `tut.stepIndex` | int | 0…N−1 | 当前步 |
| `tut.confidence` | number | 0…100 | 当前显示的自信度（由每步 `confidence_to` 推进，初始 100） |
| ~~`tut.done`~~ | — | — | **已移除**：不再记录"已看"，无需该字段（不落盘、不写 localStorage） |

### ②.3 步骤推进规则

- **R1 · 顺序推进**：`stepIndex` 只能 +1，不可回退（教学无分支）。
- **R2 · 推进放行**：`performance` 里的演出事件（表情/异议/自信度/雷达高亮）在**进入该步时立即播放**；打字机播完或玩家点击后放行下一步。
- **R3 · 玩家步锁输入**：`speaker == "player"` 的步，发言内容以只读卡呈现，**输入框禁用、无光标、不可编辑**；唯一操作是「就这么说」按钮。
- **R4 · 无对局系统**：教学全程**不触发** A3 自信度系统、A4 Token 经济、A5 漂移、A6 异议调度——所有数值变化来自脚本 `confidence_to` 字段，**不是结算结果**。
- **R5 · 收尾**：最后一步（胜利）播放完成 → 弹结算页（`#result-overlay`，复用普通关卡 UI、不写真实战绩）→ 玩家点「返回主界面」→ 回主菜单并高亮天梯卡片（**不写任何标记**）。跳过路径则直接回主菜单，不弹假胜利结算。

### ②.4 与正式对局的隔离（防串味）

> 教学关**复用对局界面 DOM**，但必须与真实对局做硬隔离，否则会污染真实结算：

| 隔离项 | 教学关 | 正式对局 |
|---|---|---|
| 后端调用 | **零**（无 `/api/new_session`、无 `/api/message`） | 有 |
| 计时器 | **关闭** | 480s 倒计时 |
| Token | 静态显示 420，不扣 | 真实扣减 |
| 漂移 | **不触发** | 每回合触发 |
| 发言 | 预写、只读 + 单按钮 | 自由文本 |
| 自信度来源 | 脚本 `confidence_to` | `settle()` 纯函数 |

## ③ 玩家交互与 UX

### ③.1 交互形态论证（deliverable 4）

**结论：推荐「单按钮『就这么说』驱动玩家回合 + 点击推进驱动 NPC/系统回合」；把"高亮软肋"从交互降级为自动演出。**

| 候选形态 | 评价 | 取舍理由 |
|---|---|---|
| **A. 点击任意处推进（纯视觉小说式）** | 部分采纳（仅用于 NPC/系统步） | 玩家步若也用它，玩家会觉得自己"只是在翻页"，失去"我在出拳"的**施为感（agency）**——而本作的核心心理需求正是"我说话是有用的"（总纲 §3.2）。NPC 步用它则节奏轻快、无负担 |
| **B. 单按钮「就这么说」（玩家步） ✅ 推荐** | 采纳 | 对"不可编辑发言"是**最优解**：① 发言内容已被预写成只读卡，玩家唯一能做的就是"说出口"——单按钮把这个动作显式化，保住 agency；② 按钮是**明确的因果枢轴**："我按下 → 台词送去 → 她动摇了"，让玩家把"打软肋"和"我的行动"绑定；③ 与正式局的"发送"按钮**同构**，肌肉记忆可迁移——正式局里只是把"预填文本"换成"自己打字" |
| **C. 允许玩家手动点击高亮软肋** | **不采纳，降级为自动演出** | 若把"高亮软肋"做成玩家操作，等于教玩家"**有个按钮能看软肋**"——但正式局里没有这个按钮（软肋在图上是自动可见的）。这会种下错误心智："赢了是因为我点了高亮"，而非"我读懂了对手"，直接违背支柱 1。**软肋高亮必须是自动演出**（进入相关步时该维自动脉冲一次），既教会了"看这里"，又不要求玩家做任何额外决策 |

**一句话**：玩家的**唯一操作**是「就这么说」（+ 点击推进），**唯一要学的事**是"先看软肋"。操作面越窄，心智注入越纯。这正契合本关"交互式过场（tutorial cutscene with clicks）"的定位。

### ③.2 即时反馈表（每次变化的可见性）

| 事件 | 触发条件 | 玩家看到/听到什么 | 玩家据此能推断什么 |
|---|---|---|---|
| 软肋自动高亮 + 引导箭头 | 进入 step 0 | 雷达图上 EVIDENCE/AUTHORITY/LOGIC 三轴脉冲一次（复用既有"软肋 ≤4 黄字"逻辑，加 300ms 呼吸）；同时屏幕弹出**指向「对手底细」按钮的箭头 + 文案「查看王阿姨的软肋」**，玩家点开面板即收起——把"看软肋"从文字提示升级为指向性引导 | "黄的那几条，是能打的地方；点这个按钮能看仔细" |
| 打强项（无效） | step 3 | NPC 切「得意」+ **红异议**闪帧 + 自信度条**不动** + 判定标签 `情感 · L1 · 命中强项（无效）` + 字幕点破 | "打她擅长的地方 = 白费力气" |
| 打软肋（有效） | step 5 / 7 | NPC 切「动摇」+ **金异议** + 自信度条**下降** + 判定标签 `证据 · L2 · 命中软肋` + 数值跳动动画 | "打黄的地方，她的自信真的会掉" |
| 自信度归零 | step 8 | 自信度条清空 + NPC 切「被说服」+ 胜利定格 + 字幕 | "把自信度打到 0 = 赢" |
| token 存在感 | 全程 | 角落 token 徽章静态显示 `420`，不变化 | "有个东西叫 token，但它现在不动"（**最小提示，不解释**，见 §③.4） |

### ③.3 关键屏幕与布局（复用，不新造）

**复用对局主界面**（`index.html` 中央对战屏），仅新增两层：

1. **教学字幕条**（屏幕上方或对话框顶部）：`speaker=system` 的 caption 专用，区别于 NPC/玩家气泡，用系统色（不引入第四情绪色，遵守 `art-bible-v2` §1 铁律）。
2. **只读发言卡 + 「就这么说」按钮**：替换原自由输入框区域。发言卡视觉 = 输入框的"禁用态"，提示"教学演示中，发言已为你写好"。

**隐藏**：倒计时环、麦克风按钮、教练提示按钮、（可选）倒计时数字。

### ③.4 最小提示 vs 不教（deliverable 3 的取舍落点）

| 概念 | 处理 | 取舍理由 |
|---|---|---|
| **token 是弹药** | **最小提示**（静态徽章 420，不消耗） | token 的深层玩法（精炼表达、超长扣费、刷屏惩罚、废话题惩罚）无法在几句话内教会，硬教 = 规则轰炸（认知过载红线）。而本关强制"预写台词"，恰好绕开了 token 的压力场景——在没压力的地方讲"资源焦虑"是空谈。留一个徽章，让玩家**知道它存在**，正式局用实战建立体感 |
| **立场分配** | **不教** | 教学关立场固定且唯一（王阿姨 pro=信保健品，玩家自动站反方），玩家只需"读"，不需要"懂规则"。立场分配是"规则透明"问题（评委可能问"为什么我站这边"），不是"心智模型"问题——它属于 A8 立场分配 GDD + 帮助入口，塞进教学关只会稀释两个核心概念 |

## ④ 数据结构与数值

> ⚠️ 教学关**不产生新数值**。下表数值全部**引用**既有真值源；脚本内的 `confidence_to` 是**对真值查表结果的固化**（教学关无结算引擎，故必须预存结果值）。

### ④.1 脚本数据落点与 schema（deliverable 6）

- **落点**：`demo/static/tutorial.json`。
- ⚠️ **为什么不落 `demo/data/`**：`demo/data/` 由 `server.py` 在服务端 import 时加载，**不经 HTTP 暴露**（服务仅映射 `demo/static/`）。若放 `data/`，前端 `fetch` 会得到 **404**，并按 §⑦-1 降级逻辑**静默跳过整个教学关**——功能等于没做，且不报错。（原拟与 `npcs.json`/`topics.json` 同层属内容数据层，因 HTTP 可访问性硬约束改落 `static/`；分层原则仍参照 `40-config-and-value-tables.md` §②.2。）
- **设计原则**：字段名沿用既有约定（`npc_id` / `dimensions` / `confidence`），使 engineering-lead 可直接消费；**不复制**六维真值（用 `null` 表示"从 `npcs.json[L1_A]` 取"）。

```jsonc
{
  "schema_version": 1,
  "id": "tutorial_l1",
  "title": "新手教学：读懂王阿姨",
  "npc_id": "L1_A",                 // 立绘/六维从 characters.json + npcs.json 取
```

**脚本内自信度弧线（＝上表查表结果的固化，非新数值）**：

```
step 3 撞强项(EMOTION, L1)   : 100 → 100  (Δ=0,   白打)
step 5 打软肋(EVIDENCE, L2)  : 100 →  80  (Δ=−20)
step 7 打软肋(AUTHORITY, L3) :  80 →  40  (Δ=−40)
step 9 打软肋(LOGIC, L3)     :  40 →   0  (Δ=−40)  → 归零，玩家胜
```

> **设计意图**：教学关的 4 击**必须命中真实档位**（0 / −20 / −40 / −40），这样玩家学到的心智模型（"打软肋掉自信，打强项不掉"）在正式局里**逐格可迁移**。若教学用自定义数值，玩家进正式局会撞上"手感不一致"。**这是已推演结论，非实测。**

### ⑥.2 与 LLM 的边界（硬约束 ④）

- **本关完全不调用 LLM**：无 `/api/message`、无 judge service、无 npc service、无 `/api/new_session`。
- 自信度变化来自 `tutorial.json.confidence_to`（脚本固化值），**不由任何模型产生**。
- 由此保证：**零延迟、零 token、零不确定性**——网络面板应验证全程 **0 个对局 API 请求**（见 §⑧ 验收 2）。

- **刻意不触发漂移（A5）**：漂移是第二课的复杂度；本关只教"软肋存在且可打"，因此六维在整个教学过程中**保持不变**（雷达图只做高亮，不移动）。
- **不注入记忆（C3）**：教学关无"翻旧账"；记忆系统留给正式对局。
- **不写 `npc_state.json` / 不改 `progress.json`**：教学不留痕（除前端 done 标志）。

## ⑦ 边界情况与失败处理

> 本关无 LLM，"AI 失效"类等价替换为**资源加载失效**（脚本/立绘/TTS 404 或异常）——这是本关最可能的失败面。

| # | 类别 | 现象 | 判定 | 处理 | 玩家可见反馈 |
|---|---|---|---|---|---|
| 1 | **资源失效（=AI 失效类）** | `tutorial.json` fetch 失败 / JSON 语法错 | 捕获异常 | **跳过教学**，直接进主菜单，控制台告警 | 无（玩家无感，仍能正常玩） |
| 2 | 资源失效 | 立绘 404 / `characters.js` 未就绪 | 资源状态非 ready | 走 `characters.json` 的 `fallback` 整图；仍失败则立绘区留空 | 立绘降级为占位图或空白，**文本与流程不受影响** |
| 3 | 资源失效 | TTS 报错 / 无语音后端 | `speak()` 抛错 | 静音继续，不阻塞推进 | 无声音，字幕照常 |
| 4 | 玩家侧 | **中途退出**（关页/刷新） | 未写 done | 下次从头播（无状态） | 无 |
| 5 | 玩家侧 | **重复进入**（已看过/重看入口） | done=true 或点重看 | done=true 时默认不弹；重看入口重置到 step 0 | 重看时从头开始 |
| 6 | 玩家侧 | **连点推进**（打字机未完就狂点） | 点击事件密集 | 首次点击=跳到本步文字完，二次点击=推进下一步（标准 AVG 行为） | 文字立即全显 |
| 7 | 环境 | `localStorage` 不可用（无痕模式） | `setItem` 抛错 | 捕获降级：本次会话内存记 done，但刷新后会重播 | 无（可能每次重看教学） |
| 8 | 评审路径 | `judge_mode=true` | 全解锁 | **仍播教学**（除非 done/跳过）；结束回主菜单不自动跳 L1；不写 progress | 同普通玩家 |
| 9 | 边界 | 玩家在最后一步（胜利）前跳过 | 未胜利 | 视为已看（写 done），**不播胜利演出** | 直接进主菜单 |
| 10 | 边界 | 教学期间用户切到后台标签 | `document.hidden` | 暂停打字机/TTS（复用 `characters.js` `visibilitychange` 行为） | 回前台继续 |

## ⑧ 验收标准与待定项

### ⑧.1 验收标准（可判定 · 每条附观测方法）

1. **零 LLM / 零网络对局请求**：全程网络面板 **0** 次 `/api/message`、`/api/new_session`；自信度变化不依赖任何后端。（自动化：拦截 `fetch` 断言）
2. **不可编辑**：教学期间发言输入框 `readonly/disabled`，无任何方式修改预写台词；唯一操作是「就这么说」/点击。（人工 + DOM 断言）
3. **以胜利收尾**：走完全程后自信度到 0，玩家获得胜利演出。（脚本断言最后一步 `confidence_to == 0`）
4. **心智模型可迁移（对齐成功标准 #5）**：冷启动受试者（清空 `localStorage` + 未被告知玩法）看完教学后，**进入正式 L1 的前 2 个回合中，命中维度落在王阿姨软肋集合 {EVIDENCE, AUTHORITY, LOGIC} 的比例**显著高于"未看教学"对照组。（小样本试玩：≥5 人 × 2 组，观察性指标；**这是 #5 的量化口径**）
5. **定性证据**：受试者能被问出"该打她的软肋 / 别跟她打感情牌"（说明 M1 注入成功）。
6. **可跳过 / 可重看 / 不骚扰**：跳过与完成都会写 done；已看后不再自动弹；重看入口可用。
7. **时长**：快进点击路径 ≤ 60s；耐心观看路径 ≤ 90s。
8. **降级不阻塞**：人为删除 `tutorial.json` / 让立绘 404 → 游戏仍能正常进主菜单并开局（注入故障测试）。

> **说明**：#4 是"观察性"指标而非硬断言（solo 项目、样本有限），标注为 `[待实测]`。建议列入赛前试玩清单，与 `05-drift-system.md` §⑧ 的试玩三步法一并执行。
