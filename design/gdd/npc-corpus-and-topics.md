## ① 问题速览

玩家实测一局：NPC 林经理（L2_A）辩「该花的钱不能省，名牌才有面子」，**连续 4 回合全在讲同两件事**——「小舅子买西装」和「西装一脱露个大肚腩」，且第 1 句与第 3 句**逐字相同**。根因不在"防重复机制不够狠"，而在**没有弹药可换**：NPC 数据里只有人物背景一句话 + 6 条身份标签（tags），全是"身份属性"（"外企干了15年""房贷压身"），**没有一件可被引用/论证的具体人、事、数字、见闻**。

于是 LLM 每回合被迫即兴编造具体素材；一旦编出「小舅子 + 西装」，它立刻进入对话历史，成为 NPC 手上**唯一的具体弹药**。后续回合即使 prompt 强命"换个新例子"，也**没有新的源头可换**——只能换说法讲同一件事，或干脆复读原句。

现有防线（字面相似度 / 论据指纹 / 整句判重 / 重试）本质是**刹车，不是油箱**：无新素材时，重试只能复现，越刹越空转。**修复的关键不是加更严的去重，而是给 NPC 一个"素材源"**——让模型只负责"从预置素材里选用与组织"，不负责"发明"。

## ② NPC「素材库」数据 Schema

### ②.1 设计原则

1. **一条素材 = 一个可独立引用的"具体弹药"**，必须含**具体人名 / 具体数字 / 具体场景**三要素中的至少两项，否则退回重写。
2. **模型只做"选用 + 组织 + 改写"**，不做"发明"。素材内的一切专有名词（人名、品牌、地名、数字）由数据预置，杜绝运行时漂移。
3. **字段克制**：只保留"影响 prompt 消费 / 影响筛选 / 影响审核"的字段；可由现有代码派生的信息（如人名抽取）不设重复字段。
4. **可攻击性是特性不是缺陷**：素材自带"可信度"标记，低可信度素材就是留给玩家的把柄（呼应攻防铁律"允许歪理"）。

### ②.2 字段定义（核心 8 字段）

> 数据模型：`npc_corpus.json` 顶层以 `npc_id` 为 key，值为该 NPC 的素材条目数组；或每条素材内嵌 `npc_id` 扁平存放。两种皆可，见 §⑦ Q1。

| 字段 | 类型 | 取值 / 约束 | 作用 | **prompt 消费形式** |
|---|---|---|---|---|
| `id` | string | 唯一，约定 `{NPCID}-C{NN}`，如 `L2A-C03` | 运行时黑名单 / 去重 / 日志 / 审核定位的唯一键 | **不进 prompt**（模型看不到 id，由运行时记账） |
| `gist` | string | 一句话，**必须含具体人名 + 场景**，40~70 字 | 素材的最小可引用单元；NPC 选中后把它**改写成 2~3 句口语** | 进入【你手上的素材】候选清单，**一行一条**，模型选它当"这回合要讲的东西" |
| `details` | string[2..4] | 每条 15~40 字，是 gist 的**可展开细节**（时间/数字/后续/对方反应） | 让 NPC"话有肉"；也是**追问深挖的唯一燃料** | 默认不注入；仅当(a)该条被选中且本回合需要"有肉"或(b)玩家追问该条时，随该条 gist 一并注入 |
| `dim` | enum 六维 | `LOGIC`/`EVIDENCE`/`EMOTION`/`UTILITY`/`IDENTITY`/`AUTHORITY` | 素材"打哪个维度"；保证一个 NPC 的弹药覆盖多维度，避免单一打法 | (1)**筛选**：与当前 `beat`、玩家攻击维度、NPC `strength` 匹配时优先；(2)**轻标注**：在候选行尾附「(利益)」提示模型选合适的料 |
| `stance` | enum | `pro`（支持本题立场）/ `anti`（反对本题立场）/ `both` | 路由：只把与当前 `topic.npc_stance` 不冲突的条目喂给 NPC | **过滤**：注入前按当前题的 `npc_stance` 筛掉相反立场素材 |
| `beats` | enum[1..3] | 表现标签，取值见 §②.3 | 标记这条素材"适合在哪种表现下用" | **筛选/排序**：当前回合 beat 命中时该条靠前 |
| `deep` | bool | `true` / `false` | 是否可被玩家追问深挖 | **追问豁免白名单依据**：`true` 时允许被玩家追问并注入其 `details` 继续；`false` 首次用完即弃，被追问时 NPC 走"记不太清/换个说法"，**不临时编造** |
| `source` | enum | `firsthand`(亲历) / `secondhand`(身边人/熟人/客户) / `hearsay`(行业传闻/道听途说) / `public`(公开数据/报道) | 来源可信度标记；同时是**可攻击性**信号 | `firsthand`/`secondhand` 注入时无附加提示；`hearsay` 会在 NPC 话里自然带出"我听人说"，从而给玩家留把柄（符合攻防铁律） |

**可选扩展字段（默认不启用，避免字段膨胀）**：`themes`(string[]，领域关键词，如`["职场","消费"]`)。**仅在"跨命题复用同一素材"成为主要用法时（§⑦ Q2 选"抽取式"）才需要**，用于按题筛料。见 §⑦ Q4。

### ②.3 表现标签枚举（`beats`）与 server 现有 beat 的映射

> 本文的 `beats` 是**素材适配的"打法定性"**，不是 server 的回合 beat。二者用下表对齐，实现侧按此映射做筛选。

| 本文 `beats` | 含义 | 对应 `BEAT_INSTRUCTION`（`server.py` L1153） |
|---|---|---|
| `open` | 开场亮立场、讲自己信这个立场的具体原因 | `OPENING` |
| `argue` | 摆事实、讲道理、举证 | `TALK`、`REBUTTAL` |
| `rebut` | 正面拆招、抓住对方漏洞反击 | `REBUTTAL`、`OBJECTION` |
| `emote` | 情绪 / 共情 / 拿别人的故事打动人 | 任意 beat（EMOTION 维度素材专用挂载） |
| `patch` | 被逼到墙角的"嘴硬找补" | `YIELD` |
| `hook` | 反问、把问题甩回给玩家 | `HOOK`、`DISMISS` |

### ②.4 JSON 示例片段（单条素材）

```json
{
  "id": "L2A-C03",
  "gist": "我前公司的戴总，干销售三十年，头回见客户就撂下一句——人家前三十秒看的不是你会什么，是你穿什么。",
  "details": [
    "那年他带我去见一个国企大客户，他自己一身定制西装，皮鞋擦得能照出人影。",
    "他说，你穿得寒碜，对方第一反应是'这家公司是不是快不行了'。",
    "那单最后拿下来了，签的是三百万的框架协议。"
  ],
  "dim": "AUTHORITY",
  "stance": "pro",
  "beats": ["open", "argue", "rebut"],
  "deep": true,
  "source": "secondhand"
}
```

### ②.5 派生索引（不进 schema，加载时计算）

为支撑 §④ 的"命中判定"，运行时在加载素材时**自动派生**一个 `cite_keys`（不进数据文件）：从 `gist` 抽**人名 / 品牌 / 数字**三类 token。**直接复用 server 现有 `_nominals()` 与实体记忆抽取逻辑（L1311~L1354）即可，无需重复造轮子。** 这样既避免新增字段，又让素材命中判定与实体记忆**共用同一套实体识别**，天然不打架。

## 素材双源分层与公共知识引用护栏（v0.2 新增）

> **本节是 v0.2 的核心修订。** v0.1 把弹药来源收成"只有预置库"，NPC 只能讲自己圈子里的人——能治复读，但"换料"的池子仍是有限的。大王批复指出：**用于举例的语料应放宽，允许模型结合类似的新闻时事回话**；且"不可能在库里预置大量新闻并打标签，只能靠模型自己的语义理解"。本节据此把素材体系改为**双源（三源）分层**，并给新增的公共知识引用配上**三层护栏**。

### 一、为何放宽：预置库能"保底"，但新闻时事才是"活水"

预置库（A 源）解决的是"**复读没有替代品**"——但它是**封闭**的：一个 NPC 的一生能提炼出的具体见闻有限，十几回合高强度辩论仍可能见底。**新闻时事是近乎无限的素材源**：模型对公共领域的语义记忆远超任何人工词条库，放开它比堆预置库更彻底地解决"没料可换"。代价是引入了新风险（幻觉、内容安全、人设漂移），**故"放宽"必须与"三层护栏"同时落地，缺一不可**。

### 二、三源分层：各自承担什么、不承担什么

| 源 | 名称 | **承担** | **不承担** | 是否预置 | 元数据 |
|---|---|---|---|---|---|
| **A 源** | 预置人格素材库 | ①**人格锚**（这是"我"亲身/身边的事）②**私人关系的可追问一致性**（能被追问、认账、不漂移）③**复读保底**（当 B/C 源不安全或说不圆时，永远退回 A 源） | 不承担"广度/新鲜度"——它本就不追求覆盖时事 | ✅ 预置（本文 §② 八字段不变） | 需要 `dim/stance/beats/deep`（**注入预算控制用**，与语义理解无关） |
| **B 源** | 模型自主公共知识引用 | **新鲜度 / 广度 / 时事感**——引用"类似新闻""普遍现象""大家都这么说" | ①**不承担精确举证**（见护栏一）②**不承担私人关系**（不能拿新闻里的人冒充自己人） | ❌ **不预置、不分类、不打标签**（大王判断正确：靠模型语义理解自行调用） | **无**（这正是"放宽"的定义：不加分类标签） |
| **C 源** | 普遍常识 / 行业规律 / 生活类比 | **通用论据**：无来源要求的"道理"——"一分钱一分货""便宜没好货""这行都这样""谁都爱面子" | 不承担"具体"——它是**类比与规律**，不是人、事、数字 | ❌ 不预置（属模型通用知识） | **无** |

> **是否单列 C 源？——建议单列（用于放宽 prompt 口径）。** 理由：C 源（生活类比/行业规律）是"最安全的一档"——它既不涉及具体人事（无幻觉风险），也不涉及敏感领域（无内容安全风险），却恰是"中国老百姓抬杠"最自然的语言。把它与 B 源并列为"可自由引用"的白名单，能让模型在不确定时**有一个安全的默认档位**，而不是硬凑新闻。**C 源无需护栏，是 B 源的降级落点。**

### 三、护栏一 · 反幻觉（最高优先）

> **辩论游戏里编造事实 = 致命。** 玩家一旦发现 NPC 拿"假新闻"当真事举证，信任瞬间崩塌，比复读更毁体验。**原则一句话：公共知识只做"趋势论据"，不做"精确举证"。** 私人的事可以编（那是人设，A 源职责），**公共的事不许编——这条界线写死**。

**许可：模糊归因。** 允许——"我看新闻上说""前阵子不是有个事嘛""现在好多地方都这样""大家都这么说"。
**禁止：精确到可核查的细节。** 禁止——**具体日期 / 精确百分比 / 具体机构名 / 具体人名 / "据某某报告显示 XX%"**。

| 场景 | ✅ 该这么说（可直接喂 prompt） | ❌ 不该这么说 |
|---|---|---|
| 引趋势 | "你别看新闻老说消费降级，我瞧着现在年轻人买起好东西来一点不含糊。" | "国家统计局数据显示，2024 年全国人均服装消费同比增长 12.7%。" |
| 引事件 | "前阵子不是有个事嘛，具体哪家我记不清了，反正是有人为了撑面子把日子过崩了。" | "去年 10 月北京朝阳法院判过一个案子，当事人王某某……" |
| 引规律 | "现在这社会你也知道，第一印象就那么几十秒。" | "某招聘平台《2024 人才报告》显示，仪表好的候选人面试通过率高 23%。" |

### 四、护栏二 · 内容安全（参赛硬伤）

> **只允许与话题池 `domain` 同域的领域**——消费 / 职场 / 生活 / 科技 / 养生 / 教育 / 家庭。
> **禁止**：政治、涉政人物、群体性事件、民族宗教、重大灾祸、涉外敏感。
> **不确定安全时，一律回退到 A 源**（讲自己圈子里的事）——**安全永远优先于新鲜**。

| 场景 | ✅ 该这么说 | ❌ 不该这么说 |
|---|---|---|
| 谈社会现象 | "现在这风气就是这样，大家都爱比较，谁家孩子怎么样、谁买了什么，饭桌上就这些。" | 复述任何群体性事件、地方冲突、涉政新闻 |
| 谈政策 | 回避，改谈个人体验："反正落到咱们普通人身上，就是钱更不经花了。" | 评价任何具体政策、官员、外交 |
| 拿不准时 | "这我哪说得上来，我就知道我们单位、我们小区里那点事儿……"（**退回 A 源**） | 硬编一条"新闻"来撑场面 |

### 五、护栏三 · 人设过滤（新闻必须"经这个人过滤"）

> 新闻不是"裸引用"，必须**用该 NPC 的圈层、语言、关注点重新表述**。**王阿姨不提美联储，陆教授不提直播间 9 块 9。** 过滤失败 = 人设穿帮（比复读更出戏）。

| NPC | ✅ 该这么说（经其人设过滤） | ❌ 不该这么说（人设出戏） |
|---|---|---|
| 王阿姨（L1 退休街道办） | "我们小区楼下那个超市，你是没见着，一到周末人挤人……" | "从宏观经济看，美联储加息会传导到国内消费。" |
| 林经理（L2 外企中层） | "从 ROI 角度讲，这笔钱花得值不值，得看它换来什么。" | "我奶奶说，年轻时候省一分是一分。" |
| 陆教授（L5 哲学系） | "这几年有些畅销读物都在讲这件事，本质上还是那个老问题。" | "直播间 9 块 9 包邮，家人们冲啊。" |

### 六、护栏违例的自动回落

模型若触碰任一护栏（精确数字、敏感领域、人设不符），**该回合的公共知识引用作废，回落到 A 源**（讲一条预置素材）或 C 源（讲一句通用道理）。**"宁可不引用，不可编造"**——这条优先级高于"必须有新料"。回落不消耗 A 源黑名单名额（属"救场"，不属"新消耗"）。

## ③ 林经理（L2_A）完整素材库样板

> **命题**：T206「该花的钱不能省，名牌才有面子」
> **林经理立场**：`npc_stance = 支持`（即素材需**撑"名牌/该花的钱值得花"**）
> **命题薄弱维度**：`weakness_hint = [IDENTITY, UTILITY]` → 素材要重点供 IDENTITY / UTILITY 弹药
> **人设锚点**：外企 15 年、部门经理、讲 ROI/KPI、房贷压身、离过一次婚、健身卡过期、瞧不上没学历的、`EMOTION` 弱（emotion_bias 4）、`UTILITY`/`AUTHORITY` 强

### ③.1 样板条目（12 条，刻意避开"亲戚 + 买东西"套路）

### ③.2 覆盖度自检

- **维度覆盖**：UTILITY ×3（C01/C06/C11）、EVIDENCE ×3（C02/C07/C10）、IDENTITY ×3（C04/C09/C12）、EMOTION ×2（C05/C08）、AUTHORITY ×1（C03）、LOGIC ×0。→ **LOGIC 缺口需在正式落档时补 1 条**（例如"归谬式算账：为省一件西装的钱，丢掉一个单子，这笔账谁划算"）。
- **人物类型多样性**：下属/同事 C01·C11、客户 C02·C06、行业前辈 C03、老同学 C04、自己 C05·C09·C12、父亲 C08、猎头传闻 C10。→ 覆盖"职场圈层 + 亲历 + 二手"多来源，**无一条是"亲戚 + 买东西"**。
- **中国背景核验**：浪琴／奥迪 A6／国企／评标现场／羊绒衫／私募／外贸 / 两千块月预算，均为中国语境。

- **追问承载**：`deep:true` 共 9 条，足以支撑一局里多次"你上次说的那个周建明后来怎么样了"。

## ④ 素材注入与消耗策略（策划规格）

### ④.1 核心规则：未用优先 + 已用黑名单 + 每回合最多消耗 N 条

> 以下为**行为规格**，不涉及实现细节。落点由 `ENG-DEDUP-001` 与 `engineering-lead` 决定。

**规则 1 —— 未用素材优先。**
每场对局维护一个"本局素材账本"：`unused`（本 NPC 中与本题 `stance` 不冲突、且未被本局引用过的条目）与 `used`（已引用）。每回合注入 prompt 的候选清单**只从 `unused` 里取，按 `未用 > 已用` 绝对优先**。排序权重建议：`当前 beat 命中 (beats 含映射 beat) > dim 命中弱点维度 > dim 命中 NPC strength > 随机`。取 **top-K（K 建议 6~8）** 注入，不注入全量（控 token、且候选越聚焦越不易乱用）。

**规则 2 —— 已用素材进黑名单。**
命中判定：NPC 本回合回复命中某条目的**任一 `cite_keys`（人名/品牌/数字，见 §②.5）**，即把该条 `id` 移入 `used`，**后续回合不再作为候选注入**（追问豁免除外，见 ④.2）。理由：让"换素材"从"模型自觉"变成"数据上没得复读"，**把刹车换成油箱**。

**规则 3 —— 每回合最多消耗 N 条。**
单回合 NPC 新引用的素材**上限 N=1**（默认值）。依据：NPC 输出目标本就只有 2~3 句短句（50~150 字），塞不下第二条具体素材；多塞会诱导拼接、破坏"像人说话"的自然度铁律。**`YIELD`（找补）回合**允许消耗 0 条新素材 + 允许复用 1 条已用素材（见 ④.2）。

**规则 4 —— 素材耗尽时的降级。**
当某题下 `unused` 为空（理论上一局通常 6~10 回合、单题可用素材 ≥8，正常不触发），NPC 才允许"不举新例"：改为纯讲道理、反问、或复用一条已用素材**加新补充**。**这是最后一档退路，不得成为常态**——一旦日志显示某场频繁触发耗尽，说明该 NPC×该题的素材量不足，进 §⑥ 审核回流。

### ④.2 与「实体记忆 / 追问豁免」的协调（一致性优先）

**优先级铁律：追问豁免 > 未用优先 / 黑名单 > 防重复。** 即：玩家追问时，**一致性永远优先于"换新素材"**。

- **追问命中**：玩家这句话命中 NPC 说过的某条素材（复用现有 `_is_entity_followup()`，L1338），且该条 `deep = true` → 进入追问模式：
  1. 把该条**从 `used` 临时解冻**，连同其 `details` **一并注入** prompt，明确要求"就讲这个人、这件事，称呼与细节一个字不许变"；
  2. 深化来源**只能是该条 `details` 里尚未用过的项**，或合理延伸（他后来怎么样了），**严禁临时新造人物/亲戚**；
  3. 该回合**不消耗新素材**，不占用黑名单名额。
- **`deep = false` 素材被追问**：**不注入 details**，NPC 走"记不太清 / 跟你说了你也不认识"这类**软回避**，绝不现场编细节（避免出现第二个"小舅子西装"式的临时设定）。
- **与实体记忆的天然一致**：素材是**预置**的，NPC 首次引用时用的就是 `gist` 里的人名、品牌、数字；实体记忆（L1311）抽到的一定是这些**预置实体**，因此"人设 → 台词 → 记忆"三段天然对齐。**这比现状（LLM 即兴编、再由记忆去追）从根上更稳。** 素材注入不得与实体记忆规则冲突：**素材只提供"可讲的内容"，实体记忆只负责"讲过的要认账"**，职责分离、互不打架。

### ④.3 开场素材分配：另立一套

**是，开场（`OPENING`）单独配比，不参与随机池与黑名单统计。**

- 每个 NPC 的素材库中，**指定 1~2 条为"开场签名素材"**（建议选 `source=firsthand` 且 `dim` 命中 NPC `strength` 的条目，最像"这就是我信这个立场的原因"）。林经理的开场签名素材建议 **C05**（自己被前台晾一小时的亲历，最有代入感）或 **C03**（戴总那句话，最有权威底）。
- 开场素材**不消耗** `unused` 名额、**不因开场使用而入黑名单**（因为它是被"指定"的，不是被"抽取"的）。
- 理由：开场是"第一印象"，必须**可控、稳定、有质感**；若开场也随机抽取，首因效应会不稳定，也难做演示/录屏。**不同题的 NPC 可选不同开场签名素材**（若按题建库）或**同一 NPC 固定开场素材**（若按 NPC 建库，见 §⑦ Q2/Q4）。

### ④.4 注入位置（prompt 装配顺序建议）

> 供 `ENG-DEDUP-001` 对齐。建议在 `_npc_system_prompt()`（L1357）中，把素材块插在**【你的身份】之后、`facts_block` 之前**。
> **v0.2 改动**：原 v0.1 的关键约束"**具体的人和事只准从【你手上的素材】里挑，不许自己另编**"是一源口径，已**改写为双源许可版**——**私人见闻仍限 A 源，公共事实开放 B/C 源但受三层护栏约束**（见 §「素材双源分层与公共知识引用护栏」）。以下为改写后的**完整 prompt 文案**（可直接落为 prompt 文案）。

```
【你的身份】…（现状保留）

【你手上的素材】（这是"你"自己的具体弹药——只准从这里面挑你亲身经历/身边的人和事）
  1. [利益] 我手下一个销售主管周建明…
  2. [证据] 做建材的王总…
  …（top-K，未用优先）
  讲私人见闻（你亲历的、亲戚朋友、同事客户）时，**只能用上面这几条**，不许自己另编人、另编事——编了回头玩家追问，你就圆不上了。

【你还能引用的公共知识】（除了自己圈里的事，你也可以顺手拿大家都知道的事儿撑场面）
  允许你引：
   · 新闻时事、社会现象、行业规律、生活常识——用"我看新闻上说""前阵子不是有个事嘛""现在好多地方都这样""这行都这样"这类**模糊说法**带出来就行。
  三条铁律（违反 = 比复读更致命，务必守住）：
  1. **公共的事不许编。** 只当"趋势"说，**绝不报**具体日期、精确百分比、具体机构名、具体人名、"某报告显示 XX%"——记 不全就模糊带过，宁可说"我记不清了"，也别硬编一个数字。
  2. **不碰敏感。** 不聊政治、不评官员、不提群体性事件、民族宗教、重大灾祸、涉外敏感。拿不准，就闭嘴不讲新闻，回头讲你自己圈子里的事——讲自己的事永远安全。
  3. **新闻要过你的脑子再用。** 你就是你这个人（用你的身份、圈层、口气去说），别人怎么说不重要，关键是这话得像是"你会说出来的"。

【你在本场对话里说过的人和事】（实体记忆，现状保留）
```

关键约束（写进素材块头部，务必保留；已按 v0.2 双源口径改写）：
1. **私人见闻（亲身/亲戚朋友/同事客户）只准来自【你手上的素材】（A 源）**——这是把 LLM 从"编造私人关系"拉回"组织者"的核心一句。
2. **公共事实（新闻/现象/常识）开放 B/C 源自主引用，但受三层护栏约束**——反幻觉（只做趋势论据、不做精确举证）／内容安全（同域、不碰敏感）／人设过滤（经本人口吻）。
3. **最高优先级 = 反幻觉**：公共知识**只做"趋势论据"，不做"精确举证"**。私人的事可以编（那是人设），**公共的事不许编——这条界线写死**。
4. **不确定是否安全时，一律回退 A 源**（讲自己圈里的事）或 C 源（讲一句通用道理）——**"宁可不引用，不可编造"**。
5. **这回合新引用最多一条**（对应 §④ 规则 3），挑中之后用你自己的话讲、别照抄，别露"素材腔"。

## ⑤ 题目池字段扩充规格

### ⑤.1 新增字段（在现有 7 字段基础上）

> 现有字段：`id / tier / domain / topic / npc_stance / target_stance / weakness_hint`。新增以下 4 项，**均为 NPC/审核侧服务，不暴露给玩家（守复盘克制铁律）**。

| 新增字段 | 类型 | 取值 / 约束 | 作用 | 消费方 |
|---|---|---|---|---|
| `pro_directions` | string[3..5] | 正方（NPC 所持立场）可用素材**方向**，每条一句话 | 给素材库生产定**生产大纲**；运行时可用于给素材打 `themes` 匹配 | 内容生产（§⑥）· 素材注入筛选 |
| `opp_attacks` | string[3..5] | 反方（玩家侧）**常见论点** | 让 NPC"预判"玩家打法；也给机制侧提供"玩家可能命中弱点维度"的参考 | NPC prompt（预判）· 平衡评估 |
| `gaps` | string[2..4] | 该命题自身的**可攻击漏洞** | 定位命题"歪理把柄"，确保辩题**可被攻破但不易被一击**（守可玩性） | 难度评估 · NPC 找补素材设计 |
| `ideal_npc` | string[1..3] | 最适 NPC 类型描述 | 用于**命题与 NPC 的匹配校验**（避免"养生题配律师"的违和） | 题库调度 · 内容生产 |

> 命名克制说明：不新增"素材正文字段"——**素材正文属于 NPC 素材库（§②），题目只提供"方向"**，避免同一份素材在两处重复维护、必然漂移。

## ⑥ 内容生产 SOP

### ⑥.1 批量补齐的总体路径

> 目标：为**另外 4 个 NPC**（L1_A 王阿姨 / L3_A 陈博主 / L4_A 赵律师 / L5_A 陆教授）补齐素材库，为**剩余 45 道题**补齐 §⑤ 四字段。**严守铁律 4：离线批量生成 + 人工审核，禁止运行时生成。**

1. **定生产文件**：以 `topics.json` 每题新增的 `pro_directions` 为**素材生产大纲**；以 `npcs.json` 的 `persona + tags + speech_style + strengths` 为**人格约束**。
2. **批量生成候选**：用 LLM 按"NPC 人格 × 命题方向"生成候选素材（每 NPC 每方向 2~3 条），输出为**待审草稿**（只进草稿区，不进 `data/`）。
3. **人工审核**：按 §⑥.2 清单逐条过。
4. **落档**：审核通过 → 写入 `demo/data/npc_corpus.json`；同时回填 `topics.json` 的 4 个新字段。
5. **抽样实测**：补完一个 NPC 即跑一轮 playtest（`demo/playtest.py`），重点看"同一素材是否跨回合复读""追问是否一致"。

### ⑥.2 人工审核清单（逐条过，命中任一即打回）

**内容安全**
- [ ] **中国背景**：地名/单位/物价/社会习惯符合中国语境（铁律 5）。
- [ ] **无政治敏感 / 无地域歧视 / 无民族与性别歧视**。
- [ ] **人名不撞真实公众人物**；品牌不出现"引导商标误导"。
- [ ] **无真人隐私**：任何具体到可识别人身份的现实个人信息一律替换。

**人格一致**
- [ ] 素材符合该 NPC 的**身份、年龄、圈层**（外企中层的弹药不能是"街道办老大妈"的）。
- [ ] 素材口吻能"用该 NPC 的 `speech_style` 讲出来"。
- [ ] **无 AI 样板腔**（不堆职业术语、不写成金句排比、不像宣言）。

**素材质量**
- [ ] **三要素**：具体人名 / 具体数字 / 具体场景，至少命中两项。
- [ ] **维度覆盖均衡**：单个 NPC 的库覆盖 ≥4 个维度，不出现"一整库都是 UTILITY"。
- [ ] **人物类型多样**：**避免"亲戚 + 买东西"套路**（本次事故的根源），人物类型至少含 3 类（同事/客户/前辈/同学/亲历/传闻）。
- [ ] **可攻击性**：每 NPC 留 ≥1~2 条 `source=hearsay` 或 `deep=false` 的"把柄素材"。
- [ ] **去重**：同一素材不跨 NPC 重复；同一 NPC 内不近义重复。

**字段规范**
- [ ] `id` 唯一且符合 `{NPCID}-C{NN}` 约定。
- [ ] `stance` 与目标题的 `npc_stance` 不冲突。
- [ ] `beats` 取值在 §②.3 枚举内；`dim` 在六维枚举内；`source` 在四档枚举内。
- [ ] `deep=true` 的条目 `details` ≥2 条且细节足够深挖。

### ⑥.3 产出节奏与优先级排序

| 批次 | 范围 | 优先级 | 理由 | 建议节奏 |
|---|---|---|---|---|
| **P0-1** | **L2_A 林经理** 素材库 + T206 等 L2 十题字段 | **最高** | 本次实测暴露的就是 L2，且 §③ 样板已给出，**可立即落档** | 样板复用，1 天内落档 |
| **P0-2** | **L1_A 王阿姨** 素材库 + L1 十题字段 | 高 | 玩家最先遇到 L1，首因效应最重（新手层口碑） | 紧随 L2 |
| P1 | L3_A 陈博主 + L3 十题字段 | 中 | 中期内容量最大的一层 | 第二批 |
| P1 | L4_A 赵律师 + L4 十题字段 | 中 | 硬核层，素材需"证据感"更强，生产难度高 | 第二批 |
| P2 | L5_A 陆教授 + L5 十题字段 | 相对低 | 触达率最低；哲学题素材难度最高 | 第三批 |

> **排序原则**：按"**玩家触达顺序 × 事故命中**"排。L2（事故点）与 L1（首因层）必须最先补；越靠后的 tier 越可后置。补 NPC 素材与补该 tier 的题目字段**同批进行**（互为上下文）。

## ⑦ 待大王拍板的开放问题

> 每条给出**推荐选项 + 理由**，请大王拍板。默认推荐已按"最小改动、守铁律、可直接落地"取向。

**Q1 · 素材库放 `npcs.json` 还是独立文件？**
> **推荐：独立文件 `demo/data/npc_corpus.json`。**
> 理由：①`npcs.json` 现已被 API 直接读并经 `server.py`（L1942 等）下发（含 `tags`/`weakness`），素材库是**生成期资产、体积大、不该随接口下发**；②独立文件便于**离线批量生产与人工审核**（不误伤 NPC 主体字段）；③符合"改表不改码"的工程控制。**结构建议**：以 `npc_id` 为 key，值为条目数组。

**Q2 · 每局素材是"抽取"还是"全量注入"？**
> **推荐：筛选后"抽取 top-K"注入（K≈6~8），非全量、非纯随机。**
> 理由：①全量注入会撑爆 `token_quota`（NPC 配额仅 280~420）且稀释注意力；②纯随机无法保证"未用优先"，违背本方案的动机设计；③按 `beats/dim/未用` 排序取 top-K，兼顾**聚焦**与**新鲜**。开场另按 §④.3 单独配比。

**Q3 · 素材数量目标是多少条 / NPC？**
> **推荐：每 NPC ≥36 条（按 NPC 建库口径）；单题可用 ≥8 条。**
> 理由：①每个 NPC 对应**其 tier 的 10 道题**（玩家可任选），按 `match_domains`（如林经理"职场/理财/消费"3 域）分摊，**每域 ≥10 条**、跨题复用后有重叠，即可保证**任一题可用 ≥8 条**；②一局约 6~10 回合、单回合消耗 1 条，≥8 条足以覆盖不触发 §④ 规则 4 耗尽降级。**备选**：若采用"按命题建库"（每 NPC 每题独立 8 条 × 10 题 = 80 条/NPC），一致性更强但生产量为 2 倍以上，**不推荐**。

**Q4 · 素材是否跨 NPC 共享 / 复用？**
> **推荐：人格化素材不共享；"世界事实"另立共享池。**
> 理由：①同一件"小舅子买西装"若被两个 NPC 讲，会破坏"每人一个真实人生"的质感；②但**客观世界设定**（如"上海内环房租均价""某年考公人数"）可抽到统一 `world_facts` 池，供所有 NPC 引用，避免各写一份、数字不一致。

**Q5 · 追问深挖是否允许 LLM 在 `details` 之外想象延伸？**
> **推荐：不允许。`details` 是深化的唯一燃料，用尽即视为"该素材耗尽"。**
> 理由：①铁律 4 明确"LLM 只负责选用与组织，不负责发明"；②一旦允许 `details` 外延伸，就会重演"临时编出小舅子西装"的漂移穿帮；③`details` 用尽后，NPC 应转向"换一条素材 / 纯讲理 / 找补"，而不是硬编。**代价**：`details` 的写作质量成为关键，须在 §⑥ 审核清单中重点把关（`deep=true` 的条目 `details` ≥2 条）。

**Q6（v0.2 新增）· 公共知识引用的"护栏松紧度"设几档？**
> **推荐：默认"中等偏严"，并提供三档可选（严 / 中等偏严 / 松），首版直接上"中等偏严"。**
> **三档定义**：
> - **严**：只允许 C 源（普遍常识/行业规律/生活类比），B 源（新闻时事）一律不给——最安全，但等于没放宽，不解决"没料"。
> - **中等偏严（默认推荐）**：B 源开放，但**必须模糊归因、禁止任何可核查细节**（日期/百分比/机构名/人名全禁）；敏感领域一律回退 A 源；人设过滤强制。
> - **松**：B 源允许带**大致时间/大致量级**（"去年""涨了一大截"），仍禁精确数字。
> **推荐理由**：①参赛评审对"AI 编造事实"零容忍，**中等偏严**既拿到了"新闻时事"的广度收益，又不引入可核查的幻觉；②"松"档收益有限（玩家很难感知"去年"与"前阵子"的差别），风险却显著升高，**不建议首版使用**；③保留三档是为了**上线后按实测数据回调**（若发现 NPC 因护栏过紧频繁回落到 A 源、又出现复读，再考虑放宽到"松"）。**默认取"中等偏严"，把"松"作为后手。**
