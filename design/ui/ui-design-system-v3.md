## 0. 结论先行

v2 已有品牌资产（三色铁三角、判决书/票据质感、逆转裁判式切角），**不推翻，只重排**。v3 解决五个真问题：

| # | v2 问题 | 影响 | v3 解法 |
|---|---|---|---|
| 1 | 两侧立绘卡各占 268px 固定宽，中间对话流被挤压 | 辩论游戏的核心是"读文字"，正文区却最窄 | 对话流居中且限宽 720px（最佳阅读行长），立绘卡改为可折叠的悬浮对峙卡 |
| 2 | HUD 四面开花：token/计时在左下、提示在输入行、投降在右下、比分在顶部独立条 | 视线扫描成本 5 处，局中紧张时丢失信息 | 收进**顶部一条 HUD**（辩题 / 比分 / 资源），局中所有状态一眼扫完 |
| 3 | 入口链路 4 层：登录 → 模式 → 选关 → 辩题确认 → 对战 | 每次试玩重复点击 5 次以上 | 合并为 3 层：入场 → 选对手（含模式）→ 辩题确认 → 对战 |
| 4 | 大量 emoji 充当图标（🎤 💡 🪙 ⏱ 🔊 ⓘ ⚙） | 跨平台字形不一致，档次低，无法着色 | 全量替换为 20 枚 SVG 图标，`currentColor` 驱动 |
| 5 | `overflow:hidden` + 固定三栏，移动端基本不可用 | 手机端玩家流失 | 移动端纵向单列：对峙卡折叠为顶部条、底细改为全屏抽屉 |

**设计铁律（沿用，不新增）**：任何新界面不引入第四种情绪主色。靛蓝=场，红=进攻/异议，金=命中/胜利，青=玩家。

## 1. 设计语言：法庭卷宗

界面元素被当作**压在深靛蓝桌面上的一叠纸质法庭文书**。

- **形状**：切角矩形（ticket / 通缉令感），硬边框 1–2px，圆角仅 4–8px。禁止 16px+ 大圆角、禁止毛玻璃拟物。
- **层次靠边框不靠阴影**：主容器 `1px 白 8%`，强调卡 `2px 主题色 + 内发光`，悬浮层才用 `shadow-lg`。
- **纹理**：强调条用 135° 斜纹（透明度 4–8%），禁止大面积噪点贴图。
- **排版气质**：标题思源宋 Heavy + 字距 2–4px（判决书），正文思源黑体，所有数字 `tabular-nums` 防跳动。

| Token | Hex | 用途 | 对比度（on bg-deep） |
|---|---|---|---|

### 2.4 动效

| Token | 值 | 场景 |
|---|---|---|
| `--ease` | `cubic-bezier(.2,.7,.3,1)` | 全局默认 |
| `--t-fast` | 150ms | hover / focus / 按钮 |
| `--t-mid` | 300ms | 面板展开、表情交叉淡入、消息入场 |
| `--t-slow` | 520ms | 界面切换、印章落下 |

- 只动 `opacity` / `transform`，禁止动画 `width` / `height`（v2 自信度条已用 `scaleX`，沿用）。
- 尊重 `prefers-reduced-motion`：关闭震动与位移，仅保留透明度过渡。

## 4. 界面规格

链路从 4 层压缩到 3 层：

```
v2: 登录 → 模式 → 选关/自由 → 辩题确认 → 对战
v3: 入场券 → 选对手(模式内联为 Tab) → 辩题确认 → 对战
```

### 4.1 入场券（Entry）
- 品牌标题 48px 宋体 Heavy，金色，字距 6px。
- 身份条内联在顶部（游客 / 账号 / 切换），不再单独一屏。
- 底部：重置进度、演出设置（收纳进 ⚙）。
- 主 CTA：「开始抬杠」→ 进选手页。

### 4.2 选对手（Roster）
- 顶部 Tab：天梯赛 / 自由切磋（自由模式下 Tab 下方出现"记忆与成长"开关）。
- 天梯为**通缉令墙**：5 张票据卡，含层名、对手名、交手次数徽章、锁定态（灰化 + 锁图标 + `aria-disabled`）。
- 卡片纵向排列优于 v2 网格：5 个对手需要读名字和人设，网格会换行割裂。

### 4.3 辩题确认（Briefing）
- 中央判决书边框大卡：辩题 36px 宋体。
- 立场行：两行对照「TA · 正方（支持）」/「你 · 反方（反对）」。
- 话柄 chip 组（TA 的底细 · 可当话柄）。
- 主 CTA「开 辩」金色 44px；次级：返回、换一题。

### 4.4 对战（Arena）— 重构重点
```
┌──────────────────────── HUD 52px ────────────────────────┐
│ 领域·辩题（左，省略截断）  第2/3局 你1:1王阿姨（中）  🪙280 ⏱6:12（右）│
├──────────────────────────────────────────────────────────┤
│                                            ┌─ 对峙卡 ─┐  │
│        对话流（限宽 720px，居中）              │ NPC立绘   │  │
│        npc / player / judge / system 气泡     │ 自信度    │  │
│                                            │ 情绪      │  │
│                                            │ [底细]    │  │
├──────────────────────────────────────────────┴──────────┤
│ [提示]  [ 输入你的论点…            ] [🎤] [发送]   [投降] │
└──────────────────────────────────────────────────────────┘
```
- 对话流限宽 720px（≈38 字/行中文最佳阅读区）。
- NPC 对峙卡固定右上、宽 240px，可折叠（移动端默认折叠为顶部条）。
- 玩家侧状态收进输入行左侧（青色小立绘 + 情绪标签），不再占整栏。
- 投降移入右上"更多"菜单，避免误触（v2 放在输入行右侧是误触高发位）。

### 4.5 底细抽屉（Dossier）
- 从全屏遮罩改为右侧 360px 抽屉（移动全屏），保留雷达图、软肋、话柄。
- 顶部展示当前情绪（表情图 + 状态标签 + "此刻的心理状态"说明）。
- 抽屉打开时对话流不阻断滚动。

### 4.6 结算（Verdict）
- 大金印「晋级！」落下（`--t-slow` + 印章 SVG）。
- 三句复盘卡片（克制版：只给战术反馈，不暴露数值——沿用已拍板策略）。
- 双 CTA：再来一局（primary）/ 回到主界面（ghost）。

## 5. 响应式

| 断点 | 布局 |
|---|---|
| ≥1280 | 对话流 720px + 对峙卡 240px，两侧留白 |
| 1024–1279 | 对话流 640px + 对峙卡 220px |
| 768–1023 | 对峙卡折叠为顶部条，对话流全宽 |
| <768 | 纵向单列：顶部条（对手+自信度）/ 对话流 / 底部输入区（安全区 `env(safe-area-inset-bottom)`） |

移动端强制规则：所有可点击元素 ≥44×44px；输入区 sticky 底部；HUD 辩题超 20 字截断为 `领域 · 前18字…`。

## 6. 无障碍

- 对比度全部 ≥4.5:1（见 2.1 表），金色为主色不单独承载语义，必配文字。
- 键盘：Tab 顺序 = HUD → 对话流 → 输入 → 发送；Esc 关闭抽屉/遮罩；Enter 发送，`Shift+Enter` 换行。
- 焦点：`:focus-visible` 2px 金色描边，禁止 `outline:none` 裸奔。
- 语义：`role="log"` + `aria-live="polite"` 于对话流（NPC 流式输出自动朗读）；自信度条 `role="progressbar"` + `aria-valuenow`；雷达图 `role="img"` + `aria-label`。
- 动效：`prefers-reduced-motion: reduce` 时关闭震动与位移。
- 演出降级开关（已拍板 v2 项）保留：关震动 / 关闪屏。

## 7. 与 v2 的取舍（不做什么）

- **不做**亮色主题：法庭对峙氛围依赖深底，且当前受众在手机/PC 暗环境试玩为主。
- **不做**大圆角/毛玻璃/渐变堆叠：与"纸质法庭文书"隐喻冲突。
- **不做**完整换装 UI：玩家形象维持 P3，界面只留一个入口占位。
