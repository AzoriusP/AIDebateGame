## 0. 结论先行（TL;DR）

1. **一句话根因**：现有防重复是「**刹车，不是油箱**」——它的全部力气都花在"**禁止复读**"上，却没有给模型 "**可以讲什么新东西**" 的**来源**。当模型即兴编出唯一的具体弹药（小舅子 + 西装）后，刹车踩到底只会让它"换词复述"甚至"逐字复现"，因为**没有新弹药可用**。
2. **机制层第一缺陷（可直接修复）**：`followup`（追问）判定**过宽**（玩家任意亲戚/熟人称谓即命中，见 `_is_entity_followup` L1345），而一旦 `followup=True`，除「整段字面 ≥ 0.62」外的**所有闸门被旁路**——论据判重、整句复读、严格模式警告、recent-self 注入**全部失效**（L1546-1550、L1568、L1378-1388）。于是"同一个素材、换个措辞"与"整段照搬"都能过关。
3. **机制层第二缺陷（可直接修复）**：`npc_reply` 结尾 `out = best_reply or reply`（L1573）——**当所有重试都重复时，明知重复也照样返回**，没有终极兜底。这是「#1 与 #3 逐字相同仍被展示」的**最后一棒**。
4. **内容层缺陷（交 DS-CORPUS-001）**：`npcs.json` 的 NPC 只有 `background` 一句话 + 6 条 `tags`，**没有素材库字段**（已核对 `demo/data/npcs.json` L1-96，林经理 L2_A 亦然）。模型无稳定的"具体弹药源"。
5. **v0.2 修订（素材体系放宽为双源）**：**A 源** = 预置人格素材库（现有 F9，承担人格锚 / 可追问一致 / 复读保底）；**B 源** = 模型自主引用公共知识（承担新鲜度 / 广度 / 时事感，**不预置新闻库、不打分类标签**，靠模型语义理解）。B 源配**三护栏**（反幻觉 / 内容安全 / 人设过滤，见 §3.5）。关键机制结论：**私人实体（A 源）进一致性追踪与黑名单；公共实体（B 源）不进**（§3.6）；**字面相似度与整句判重照旧全量生效**。
6. **本规格给出**：失效归因（逐条证伪/证实）、根因定性（机制 vs 内容边界）、P0/P1 机制层修复方案、精确改动清单与回归测试点、以及**明确不要动**清单。

## 1. 失效归因（最重要）

### 1.0 场景与符号定义

设 NPC 连续四回合发言为 `R1, R2, R3, R4`；`opening` = 开局句（`npc_reply(..., "OPENING", [], state)`，L2083；结果以 `assistant` 写入 history，L2087）。玩家实测：
- `R1 == R3`（**逐字完全相同**）；
- `R2` 与 `R4` 换了措辞，但**仍是同两个素材**（小舅子 / 西装）；
- 四回合全部围绕同两个素材。

所有四句都是 `role=assistant` 的历史条目。

### 1.1 防重复闸门链路（现状）

```
生成回复 reply
  ├─ 取 recent_self = 最近 3 条 assistant（含 opening）  [L1488, _extract_recent_npc_lines L1186]
  ├─ used_nominals = 近期出现的人名（排除自称）          [L1493-1495, _nominals L1279]
  ├─ self_facts = 全 history 抽"编过的人/说过的事"        [L1497, _extract_self_facts L1311]
  ├─ followup = _is_entity_followup(last_player_text,…)  [L1498, L1338]
  └─ for attempt in range(1+2+1):                        [L1506]
        reply = _chat(temp = 0.7 / 0.95)                 [L1522]
        worst_lit/worst_fp = max over recent_self         [L1540-1543, _repeat_score L1238]
        reused_sents = 整句复读                            [L1545, _reused_sentences L1258]
        if followup:  hard_dup = worst_lit >= 0.62   ← 只此一条闸   [L1550]
        else:         hard_dup = lit>=0.42 or fp>=0.82 or reused_sents  [L1553-1555]
        score = lit + fp + 0.3*reused + 0.5*len(reused_sents)   [L1556]
        best = min(score)                                  [L1557-1558]
        if hard_dup and len(banned) < 1: 重试 (banned+=reply)      [L1559-1569]
        if hard_dup: 仅打印日志                              [L1570-1571]
        break
  out = best_reply or reply        ← 明知重复仍返回            [L1573]
```

### 1.2 逐条归因（含代码证据：证实 / 排除）

#### (a) followup 豁免路径 —— **证实为主因（必要条件之一）**

**结论**：`followup=True` 时，防重复的**三道闸里有两道被彻底旁路**，且模型还被**明确指示"接着讲同一个"却不给新弹药**，于是逐字复现。

**证据链**：

1. **触发条件过宽** —— `_is_entity_followup`（L1338）第一判据：
   ```python
   if _KIN_PAT.search(t):          # 玩家提到任何亲戚称呼（表弟/二舅…）
       return True                 # ← L1345
   ```
   而 `_KIN_PAT`（L1294-1305）囊括 `大爷/大妈/大伯/表舅/表叔/小舅/舅舅/舅妈/…儿子/女儿/闺女/老伴/老头子/同事/同学/房东/店老板/柜员`。
   本局题目是「该花的钱不能省，名牌才有面子」（消费/职场域）。玩家为了讲自己的道理，**极可能说出"我同事""我儿子""我老婆"**——这些**都不是在追问 NPC 的小舅子**，却因命中 `_KIN_PAT` 把 `followup` 置真。**这是"误伤式进入追问模式"，是穿帮链的起点。**

2. **ask 模式替换了防重复注入** —— `_npc_system_prompt`（L1357）中：
   ```python
   if followup:                    # L1378
       dup_block = "…【本回合模式：玩家在追问你说过的人/事】…必须接着讲同一个…补充新的细节接着讲…"  # L1380-1387
   elif recent_self_lines:         # L1388  ← 只有非追问才注入"你最近说过的话 + 防重复铁律"
       dup_block = "【你最近说过的话】…【防重复铁律】…"
   ```
   → followup 时，模型**根本看不到【你最近说过的话】**，也**收不到【防重复铁律】**。它被要求"接着讲同一个"（L1383），却**没有被告知自己上一句到底是怎么说的**，只能靠参数记忆复现。

3. **硬判据只剩一条**：
   ```python
   if followup:
       hard_dup = worst_lit >= 0.62      # L1550
   ```
   → `worst_fp`（论据重合，L1554 的第二个闸）与 `reused_sents`（整句复读，L1555 的第三个闸）**在追问模式下全部不作数**。这意味着：
   - `R3` 即使**整段逐字等于** `R1`，也才是 `worst_lit≈1.0 ≥ 0.62` → 触发重试（但见 (b)）；**若换措辞**，`worst_lit` 会掉到 0.62 以下，**直接放行** → 这正是"换了措辞但同两个素材"（R2/R4）能过关的机制原因。

4. **严格模式被关闭** —— `strict = not followup`（L1568）：
   → 追问下即便发生重试，也**永远不会**加挂 L1391 的"必须彻底换人换事"警告。

**判定：`followup` 豁免链（过宽触发 + 撤掉所有闸 + 撤掉注入 + 不给新弹药）是"逐字复现"的充分成因。证实。**

#### (b) best-of 兜底 —— **证实为"最后一棒"（必要条件之一）**

**结论**：即便某次重试判定为 `hard_dup`，代码**不会阻止返回**——`out = best_reply or reply`（L1573）**明知重复也返回重复句**。

**证据链**：
- 重试预算极小：`NPC_DEDUP_RETRY = 1`（L226）；条件 `if hard_dup and banned.__len__() < NPC_DEDUP_RETRY`（L1559）→ **本回合至多触发 1 次重生成**。
- 重试后若再次重复：`banned.__len__()==1` **不再 < 1** → 跳过 L1559 分支 → 执行 `if hard_dup: print("重试后仍重复…取较低重复度版本")`（L1570-1571）→ `break`。**这个分支只打印日志，不阻断，不兜底。**
- 返回 `out = best_reply or reply`（L1573）。`best_reply` 由 L1557-1558 选出：
  ```python
  if best_score is None or score < best_score:   # L1557  ← 严格小于，平局保留先到者
      best_score, best_reply = score, reply
  ```
  **平局保留先到者（attempt0）**。若重试在高温下**又逐字复现** `R1`，则 `score` 与 `R3` 相等 → **保留 `R3`** → 返回的就是「与 R1 逐字相同的 R3」。**这精确解释了实测现象。**

**判定：best-of 兜底缺陷是"重复句仍被展示"的最后一道放行。证实。**

#### (c) recent_self 窗口边界 `NPC_DEDUP_WINDOW=3` 是否覆盖 #1 —— **排除（否认其为主因）**

**结论**：窗口 **足以覆盖** `R1`，**不是**"#1 与 #3 逐字相同"的漏因。

**证明**：`_extract_recent_npc_lines(history, n=3)`（L1186）倒序取**最近 3 条 assistant**。生成 `R3` 时，`assistant` 序列为 `[opening, R1, R2]`（opening 于 L2087 写入，占一格），取最近 3 条 = `[R2, R1, opening]`——**`R1` 在窗口内**。故 `R3` 与 `R1` 的 `worst_lit≈1.0`，**必然被判重**（followup 下 ≥0.62，非 followup 下 ≥0.42）。
→ **窗口不是漏点**；漏点在 (b)（判重后仍返回）。

**残留（次要，非本现象主因）**：`recent_self` **只在循环外抽取一次**（L1488），**重试后不刷新**；重试自身产物的复读只靠 `banned_block`（L1510-1515）在 prompt 层提示，不参与 `reused_sents` 计算。这一点**加深**了 (b)（重试若复现"本回合上一次草稿"同样可能平局保留）。

**判定：排除为主因。** 仅作为 (b) 的次要放大器登记。

#### (d) 整句判重 `NPC_SENT_DUP_MINLEN=6` 与 stopwords —— **部分成立：在 followup 下是真空洞；非 followup 下基本可用**

**证据链**：
- 非 followup：`hard_dup` 含 `or bool(reused_sents)`（L1555）；`_split_sentences`（L1248）以 `NPC_SENT_DUP_MINLEN=6` 与 11 条 stopwords（L252-255）过滤；**长句（>6 字）会被保留并精确匹配**，逐字整句必被拦。**合格。**
- **followup：`reused_sents` 不参与 `hard_dup`（L1550）** → **整句判重完全失效**。若 `R3` 是"换措辞 + 夹一句逐字老句"，整体 `worst_lit` 可能 < 0.62 → **放行**。这解释了"R2/R4 换了措辞但仍是同两个素材"。

**边界细节**：`_split_sentences` 先 `re.sub(r"[^\u4e00-\u9fa5]","")` 只留汉字——数字/标点会被剥离，故"大几千"这类仍可匹配；但若模型改动任意一个字（如加"了"），集合成员判定即失配 → 判重召回有限（见 `_content_fingerprint` 注释 L1224-1225 已自陈）。**这是"软召回"天花板，非本轮首要。**

**判定：(d) 成立但**仅**在 followup 豁免下成为空洞。非 followup 下合格。**

#### (e) 重试温度提升 0.7→0.95 是否足以打破确定性复现 —— **不足（对本地模型偏弱）**

**证据**：
- 温度只在 `attempt>0` 时提升（L1522）：`temp = 0.7 if attempt == 0 else 0.95`。
- **只有 1 次重试**（`NPC_DEDUP_RETRY=1`）。
- 本地 `qwen3.5:latest` 在"上下文里明确写着'必须接着讲同一个人'（L1383） + 相同近 6 条历史（L1518）"下，**温度 0.95 也常复现高度相似文本**（尤其中文短句、固定人物）。
- 一旦复现，因 (b) 的**平局保留先到者**，返回的仍是 attempt0 的逐字句。

**判定：温度提升是"锦上添花"，不足以单独打破确定性复现——它必须与 (a)(b) 的修复联动。成立为次要成因。**

### 1.3 归因汇总

| 假设 | 结论 | 关键证据 |
|---|---|---|
| (a) followup 豁免撤闸、指示"讲同一个"却不给新弹药 | ✅ **主因（必要）** | L1345 触发过宽；L1378-1388 撤注入；L1550 仅剩一闸；L1568 关严格 |
| (b) best-of `out = best_reply or reply` 明知重复仍返回 | ✅ **主因（必要·最后一棒）** | L1559-1571 重试后只打印；L1573 无条件返回；L1557 平局留先到者 |
| (c) 窗口 `NPC_DEDUP_WINDOW=3` 未覆盖 #1 | ❌ **排除为主因** | L1186 近 3 条 assistant 含 opening，生成 R3 时 R1 在窗口内 |
| (d) 整句判重 minlen/stopwords 漏长句 | ⚠️ **仅 followup 下失效** | L1550 旁路 `reused_sents`；非 followup（L1555）合格 |
| (e) 温度 0.7→0.95 不足以打破复现 | ⚠️ **次要成因** | L1522 仅 1 次重试；L1557 平局保留 |

## 2. 根因定性

### 2.1 一句话

**机制缺陷叠加内容缺陷**：现有防重复是**只有刹车、没有油箱**——它把所有预算投在"禁止复读"的**拦截**上，却没有给模型"**可讲的新弹药**"（素材库）与"**拦不住时的终极兜底**"，于是刹车越踩、复读越硬。

### 2.2 机制缺陷 vs 内容缺陷（边界划分）

| 类别 | 归属 | 具体条目 | 负责方 |
|---|---|---|---|
| **机制缺陷** | 程基岩（本 Task） | ① followup 判定过宽 + 追问豁免把论据/整句/严格/注入全部旁路（L1345/L1550/L1568/L1378-1388）<br>② best-of 明知重复仍返回，无终极兜底（L1573）<br>③ 重试预算仅 1 次、温度提升有限（L226/L1522）<br>④ recent_self 重试后不刷新（L1488） | **ENG-DEDUP-001** |
| **内容缺陷** | 设计/内容（并行） | ⑤ NPC 数据无「素材库」→ 无稳定新弹药源（`npcs.json` 仅 `background`+`tags`）<br>⑥ 每条素材缺「人物/事件 + 细节 + 维度 + 适配 beat」的结构 | **DS-CORPUS-001** |

> **边界声明**：本规格只负责**机制层**（①~④）与**素材库的"注入/消耗/黑名单"机制设计**（假设 schema 已定）。素材库的**字段语义、内容生产、林经理等人物的具体素材条目**由 DS-CORPUS-001 负责，本规格仅标注**对接协议**（见 §3.1）。
>
> **v0.2 双源边界**：**A 源**（预置人格素材）的字段/内容/人物条目 = 内容侧（DS-CORPUS-001）；**B 源**（公共知识引用）**无预置数据**，其"三护栏文案"由工程侧拟一版（§3.5）+ 内容侧另拟一版，**由主理人合并**。机制侧负责"**哪些实体进追踪/黑名单、怎么判**"（§3.6）与"**追问公共信息怎么答**"（§3.7）。

## 3. 机制层修复方案

### 3.1 P0-A 「素材库注入」（刹车之外接上油箱）

**数据契约（与 DS-CORPUS-001 对齐，字段名暂定）**

```jsonc
"corpus": [                          // = A 源：预置人格素材库
  {
    "id": "c1",                        // 稳定标识 —— 用作"本局已用"标记
    "entity": "小舅子",                 // 人物/事物主体 —— 私人实体（一致性锚 + 命中检测）
    "detail": "前年咬牙买了套名牌西装，说谈客户得有行头",  // 一句可讲的具体细节
    "dimension": "UTILITY",            // 打哪个六维（配合软肋/漂移调度）
    "beat_fit": ["TALK", "REBUTTAL"],  // 适配节拍（BEAT_INSTRUCTION 的键）
    "source": "preset",                // v0.2 新增：A 源标记（仅 A 源实体进一致性追踪与黑名单）
    "deep": true                       // v0.2 可选：该实体是否要求"追问必认账 + 补 details"（默认 true）
  }
  // …每人 6~10 条
]
```
- **优雅降级**：`_extract_corpus(npc)` 在字段缺失时返回 `[]` → **行为与现状完全一致，零回归**（旧数据无 `corpus` 也不报错）。
- **v0.2 说明**：`corpus` 即 **A 源**；**B 源（公共知识）无预置数据、无 `id`**，因此**天然不进** `corpus_used` 黑名单（见 §3.6）。

**每局状态字段与存放位置**
- 新增 `state["corpus_used"] = []`（session state，init 位置 L2054-2079 区块内）。
- **取舍：放 session state（内存 / per-sid），不放 `npc_state.json`。**
  1. 反重复是"**本局之内**"的问题；真人跨天重复讲同一个小舅子的故事是**自然**的。
  2. `npc_state.json` 语义是**跨局**记忆/成长（`memories/adj/fights`，见 `_normalize_npc_entry` L376）——塞"本局已用"会污染语义并随局无界增长。
  3. session state 已作为 `state` 传入 `npc_reply`（L2168 / L2257）→ **零接口改动**。
  4. 局终 `_finalize_match` 天然丢弃，无需清理代码。
- （P1 备选）若产品要求"同一 NPC 跨局也别老讲同一故事"，另在 npc_state 加 `corpus_recent`（限长 N）。**默认不做。**

**prompt 注入格式**（新增 `corpus_block`，插入 `facts_block` 之后）
```
【你可以用的素材】（本轮优先讲没用过的；标 ✗ 的本局不要再讲）
```

### 3.2 P0-B 「追问豁免漏洞修复」（追问≠允许照搬）

现状缺陷（两条，均有行号）：
- followup 下 `hard_dup = worst_lit >= 0.62`（L1550）——**整句判重（`reused_sents`）与论据判重（`worst_fp`）被旁路**。
- followup 的 `dup_block`（L1380-1387）**替换**了 recent-self 注入（因 L1388 `elif recent_self_lines`），模型**看不到自己最近说过什么**，却被要求"必须接着讲同一个"（L1383）。

修复：
1. **追问下仍拦"整段照搬"与"整句复读"**：
   ```python
   if followup:
       hard_dup = (worst_lit >= NPC_FOLLOWUP_HARD_LIT or bool(reused_sents))
   ```
   新增常量 `NPC_FOLLOWUP_HARD_LIT = 0.9`——比 0.62 **更松**（避免误杀"合理重复提及同一人"），但能拦住**逐字/近逐字整段照搬**；同时把 `reused_sents` **重新纳入**（"补充新细节"≠"复制老句"）。
2. **追问下注入"关于这个人的未用细节"**：新增 `_entity_unused_details(corpus, self_facts, entity, used_ids)`，把该人物**尚未用过**的细节注入 prompt，让"接着讲同一个"**有新弹药**，而不是让模型复述。
3. **追问下也列出"你最近说过的原句"（只读、不施压）**，并在 `dup_block` 明确：**同一人允许，同一句/同一细节不许原样复述**。
4. **收紧 `_is_entity_followup`（L1338）**：现 `_KIN_PAT.search(t)` 无条件判真（L1345），而 `_KIN_PAT` 含"同事/同学/儿子/女儿/老伴"等高频词 → 玩家在职场/消费题说"我同事也…"即**误触发**。改为下列**任一**成立才算追问：
   - 玩家句中的称谓/人名**与 NPC 的 `self_facts` 或 `used_nominals` 有交集**；或
   - 玩家句含**明确指代**（新增 `_REFER_PAT`：「你说的」「你刚说」「你那个」「你说的那个」「刚提的」「刚才那个」）。
   - **过渡方案**（低风险）：保留 `_KIN_PAT` 命中，但**要求同时命中实体记忆**，否则不启用追问豁免。

### 3.3 P0-C 「终极兜底」（拦不住时也不能原样返回）

现状缺陷：`out = best_reply or reply`（L1573）——**当所有重试都重复时，明知重复仍原样返回**；`if hard_dup:`（L1570-1571）只打印日志、不阻断。

修复（**分级替代动作，任一分支都保证不返回 `hard_dup` 句**）：


### 3.6 P0-E 「判重与实体记忆：私人实体 vs 公共实体」（本次重点）

#### 3.6.1 问题：B 源引入会造出两个新病

- **(a) 逼出一条新闻反复讲**：若把公共实体（新闻里的人名 / 机构 / 事件）当作"私人实体"拉进 `_extract_self_facts` 与一致性追踪，`facts_block`【人物一致性铁律】（L1407-1419）会要求 NPC **跨回合对同一条公共新闻保持"一致"**——既不必要（公共信息不承载人格），又**逼它复读同一条新闻**。
- **(b) 把趋势表达误判成复读**：若"现在好多人……""网上都在传……"这类**趋势型表达**被塞进 `used_nominals`/黑名单或当作论据锚，则下一回合换措辞再讲趋势就会被判重，**误伤正常表达**。

#### 3.6.2 设计思路与论证

**命题 P**：只有 **A 源预置实体**进一致性追踪（`_extract_self_facts`）与黑名单（`used_nominals` / `corpus_used`）；**公共实体不进**；但**字面相似度与整句判重照旧全量生效**。

**论证（判定 P 成立，附条件）**：

1. **语义正确，不是权宜**：一致性追踪（`facts_block` / 【人物一致性铁律】）的唯一目的是"**人格锚可追问、不漂移**"。只有 NPC **自己编的私人实体**（小舅子 / 远房表弟 / 淘宝）才承载人格；公共信息不承载 → 排除公共实体是**语义上正确**的。
2. **黑名单语义也正确**：反重复黑名单的目的是"**同一私人弹药不重复打**"。公共信息**天生是公共的**、非弹药，不该被"消耗/封禁"。
3. **可操作，且与批复一致**：**私人实体是"有限已知集"**（A 源 `corpus.entity` 白名单 + NPC 自身身份锚），**公共实体 = 补集**（不枚举、不预置、不打标签）→ 用**闭世界假设**识别私人：**在白名单里 = 私人；否则 = 公共**。这正好满足"**不预置新闻库、不打分类标签**"的批复——机制侧无需认识任何公共实体。
4. **字面/整句全量成立**：复读穿帮的本质是"**同一句话/同一整句**又被说了一遍"，**与来源无关**；无论 A/B 源，一旦逐字重复就是穿帮 → `_similarity`（L1214）与 `_reused_sentences`（L1258）**全量生效**。

**成立的前提与风险**：命题 P 成立**当且仅当** A 源 entity 白名单能覆盖 NPC 会跨回合复用的私人实体。若 NPC **即兴又编了个不在 `corpus` 里的私人实体**（如"我们部门张姐"），它不在白名单 → 被当公共 → 不追踪 → 可能出现漂移/复读。**缓解：静态白名单 + 动态晋升**（见 3.6.3）。→ **结论：思路成立，但需补"动态晋升"覆盖即兴私人实体。**

#### 3.6.3 判定规则（映射到函数）

| 判据 | 归属 | 规则 | 涉及位置 |
|---|---|---|---|
| **私人实体白名单** | — | `_private_entity_whitelist(npc, corpus)` = `corpus` 中 `source=="preset"`（缺省视为 preset）的 `entity` 归一化集合 **+ NPC 自身身份锚（name/persona）** | 新增函数 |
| **动态晋升** | — | history 中 NPC 发言里由 `_KIN_PAT`/`_nominals` 首次引入的**命名实体**，若与已存在私人实体形成**稳定指称**或出现在 A 源 `entity` 中 → 晋升入白名单，存 `state["private_entities"]`（session 级） | `_promote_private_entity`（P1） |
| **一致性追踪 `_extract_self_facts`（L1311）** | 私人 | 只保留**引用私人实体**的事实（`private_whitelist` 成员命中）→ 进入 `facts_block`；**公共事实被排除** | 改 `_extract_self_facts` |
| **`_nominals` / `used_nominals`（L1279 / L1493-1495）** | 私人 | `_nominals(recent_self)` 结果**过滤为白名单成员** → 公共人名不进 `used_nominals`（避免"同一公共名"被当"同一例子重放"） | 改 `used_nominals` 构造 |
| **`corpus_used` 黑名单** | 私人 | 仅 A 源 `id` 进；B 源无 `id` → 天然不进 | §3.1 |
| **字面相似度 `_similarity`（L1214）** | **全量** | A/B 源一律生效 | 不改 |
| **整句判重 `_reused_sentences`（L1258）** | **全量** | A/B 源一律生效（含追问分支，见 §3.2） | 不改 |
| **论据重合 `_content_fingerprint`（L1222）** | **全量** | A/B 源一律生效（判重类，非实体追踪类） | 不改 |

**优雅降级**：`corpus` 缺失（旧数据）→ 白名单为空 → `_extract_self_facts`/`used_nominals` **退回现状行为**（等价 v0.1），零回归。

**关于 (b) 趋势表达的残余风险（诚实登记）**：字面/整句全量下，**逐字**重复的趋势句会被 `reused_sents` 拦（**正确**，逐字即穿帮）；但**换措辞**的趋势句仍可能触及 `worst_fp`（论据实义字重合 ≥0.82）。这是 v0.1 既有阈值的行为，**本轮不改**（遵"字面/整句全量"口径，且 fa/fb 阈值 0.82 取高位本就为避误杀）。若后续 playtest 出现误伤，**P1 备选**：在 `_content_fingerprint` 的 stop 表中补入泛化指称（"好多人/大家/现在都/如今/不少人"），**仅作调优、需回归**。

### 3.7 P0-F 「`_is_entity_followup` 对 B 源的策略：认账，但可软回避」

**背景**：`_is_entity_followup`（L1338）现返回布尔，`True` 时走 §3.2 的追问深挖路径。B 源引入后，玩家可能追问**公共信息**（"你刚说的那条新闻咋回事？"），其正解与 A 源**不同**。

**策略：区分追问目标，返回 `followup_scope`**

| 追问目标 | 判定 | 处理 | 理由 |
|---|---|---|---|
| **A 源私人实体**（`deep=true`） | 玩家句命中的称谓/人名 ∈ 私人白名单 | **必须认账 + 补 details**（沿用现有【人物一致性铁律】+ `_entity_unused_details`） | NPC 自己编的人 = 人格锚，必须自认、不许否认 |
| **B 源公共信息** | 玩家含**明确指代**（`_REFER_PAT`）指向公共内容，且**未命中**私人白名单 | **软回避**：允许"记不清细节"，**绝不许改口否认自己说过**；**不强制**继续讲同一条 | 公共信息记忆本就模糊；但"我确实说过"是诚信底线 |

**新增/修订判定**：`_followup_scope(player_text, private_whitelist, self_facts_private, used_nominals_private) -> "private" | "public" | None`
- 命中私人白名单 → `"private"`；
- 仅命中 `_REFER_PAT`（如"你说的/你刚说的"）且**无**私人实体 → `"public"`；
- 否则 → `None`（非追问）。
- **顺带修复 v0.1 的过宽**（§1.2 (a)）：现在 followup 需**命中私人实体或明确指代**，玩家说"我同事也…"不再误触发。

**prompt 新分支（B 源追问，软回避）**：
```
【本回合模式：玩家在追问你刚提过的公共见闻】
玩家问的是你在新闻/网上扫到的那件公共事。公共信息你只记得个大概，细节可以说不太清：
  ✅「具体哪天我还真记不准了，反正就那个意思」
  ✅「我就扫了一眼，大概说的是……」
  ✅ 顺势拉回你自己圈子里的人和事。
  ❌ 绝不许说"我没提过""哪有这回事""你记错了"——你确实说过，不许赖账。
```

**判重口径（B 源追问）**：**不启用** §3.2 的私人豁免；按**非追问全量**判重（`worst_lit≥0.42 / worst_fp≥0.82 / reused_sents`）。→ 既避免逐字复述同一条新闻，也不逼 NPC 对公共新闻保持"一致"。

**否认兜底**：若 B 源追问下模型输出含**否认模式**（"我没说过 / 我没提过 / 哪有这回事 / 你记错了"）→ 视为违规草稿，**触发重试或替换为兜底动作**（复用 §3.3 通道）。
