## ⓪ 一句话

内容侧供「**油箱**」，机制侧管「**刹车 + 兜底**」。v0.2 再进一步：**油箱改成双源**——
**A 源**预置人格库（人格锚 / 可追问一致 / 复读保底）+ **B 源**模型自主引用公共知识（新鲜度 / 广度 / 时事感），
B 源配**三护栏**。**核心红线：私人的事可以编（人设），公共的事不许编。**

## ① 权威 Schema（v0.1 裁定，v0.2 不变）

**数据文件**：`demo/data/npc_corpus.json`，顶层以 `npc_id` 为 key，值为该 NPC 的素材条目数组。

| 字段 | 类型 | 定义 | 机制侧用途 |
|---|---|---|---|
| `id` | string | `{NPCID}-C{NN}` | 黑名单 / 记账 / 日志 / 审核定位唯一键。**不进 prompt** |
| `gist` | string | 40~70 字，含具体人名 + 场景 | 注入候选行；**私人实体由此派生**，不另设字段 |
| `details` | string[2..4] | 15~40 字/条 | 追问深挖的唯一燃料（`deep=true` 时注入） |
| `dim` | enum 六维 | LOGIC / EVIDENCE / EMOTION / UTILITY / IDENTITY / AUTHORITY | 筛选 + 排序 + 轻标注 |
| `stance` | enum | `pro` / `anti` / `both` | 注入前按 `topic.npc_stance` 过滤 |
| `beats` | enum[1..3] | open / argue / rebut / emote / patch / hook | 当前回合 beat 命中则排序靠前 |
| `deep` | bool | 是否可被玩家追问深挖 | 追问豁免白名单依据 |
| `source` | enum | **可信度四值**：firsthand / secondhand / hearsay / public | 可攻击性提示；hearsay 注入时自然带"我听人说" |

> **两条不许推翻的裁定**：① `entity` **不设字段**（由 `gist` 经现有 `_nominals()` L1279 派生，与实体记忆共用一套识别）；
> ② `source` **只表示"可信度"，不表示"是否预置"**（见 §④ 冲突 D）。

## ② 双源契约（v0.2 新增）

### ②.1 三源分工

| 源 | 名称 | **承担** | **不承担** | 是否预置 | 元数据 |
|---|---|---|---|---|---|
| **A 源** | 预置人格素材库 | ①**人格锚** ②**私人关系可追问一致** ③**复读保底**（B/C 不安全时永远退回这里） | 广度 / 新鲜度 | ✅ 预置（`npc_corpus.json`） | `dim/stance/beats/deep` 全套（**注入预算控制用**，与语义理解无关） |
| **B 源** | 模型自主引用公共知识 | 新鲜度 / 广度 / 时事感 | ①精确举证（见护栏一）②私人关系（不许拿新闻里的人冒充自己人） | ❌ **不预置、不分类、不打标签** | **无**——这正是"放宽"的定义 |
| **C 源** | 普遍常识 / 行业规律 / 生活类比 | 通用论据："一分钱一分货""这行都这样""人活一张脸"——**不需要任何来源** | 具体人 / 事 / 数字 | ❌ 不预置 | **无**（最安全一档，**B 源的降级落点**） |

### ②.2 私人实体 vs 公共实体（机制核心 · 本次重点）

**命题**：只有 **A 源实体**进一致性追踪与黑名单；**公共实体不进**；但**字面 / 整句 / 论据判重全量生效**。

| 判据 | 归属 | 规则 |
|---|---|---|
| **私人实体白名单** | — | `npc_corpus.json` **全部条目**的 `gist` 派生实体（`_nominals(gist)`）∪ NPC 自身 `name`/`persona` |
| **一致性追踪** `_extract_self_facts`(L1311) | 私人 | 只保留命中白名单的事实 → 进 `facts_block`；**公共事实被排除** |
| **`_nominals` / `used_nominals`**(L1279 / L1493) | 私人 | 过滤为白名单成员 → 公共人名不进（避免"同一公共名"被当"同一例子重放"） |
| **`corpus_used` 黑名单** | 私人 | 仅 A 源 `id` 进；**B 源无 `id` → 天然不进** |
| **字面相似度** `_similarity`(L1214) | **全量** | A / B 源一视同仁 |
| **整句判重** `_reused_sentences`(L1258) | **全量** | A / B 源一视同仁（含追问分支） |
| **论据重合** `_content_fingerprint`(L1222) | **全量** | A / B 源一视同仁 |

**为什么必须这么切**：若把公共实体当私人实体追踪，会造出两个新病——
(a) `facts_block`【人物一致性铁律】会要求 NPC **跨回合对同一条新闻保持"一致"**，不必要且**逼它复读同一条新闻**；
(b) 把"现在好多人…"这类**趋势型表达**塞进黑名单，下回合换措辞再讲趋势就被判重，**误伤正常表达**。

**优雅降级**：`corpus` 缺失（旧数据）→ 白名单为空 → 追踪退回现状行为（等价 v0.1），**零回归**。

**已知残余风险（机制侧诚实登记，本轮不改）**：**换措辞**的趋势句仍可能触及 `worst_fp`（论据实义字重合 ≥0.82）。
属 v0.1 既有阈值行为；若 playtest 出现误伤，P1 备选是在 `_content_fingerprint` 的 stop 表补入泛化指称（"好多人/大家/现在都/如今/不少人"），**需回归**。

**待补前提**：白名单需配「**静态白名单 + 动态晋升**」——NPC 即兴编出的私人实体（如"我们部门张姐"）不在 `corpus` 里，
会被误判为公共 → 不追踪 → 可能漂移。动态晋升（`_promote_private_entity`，session 级 `state["private_entities"]`）列入 P1。

## ③ 合并后的护栏 Prompt 文案（主理人合并版 · 唯一版本）

> 两侧各自拟了一版（内容侧 §三/四/五 对照句更生动；机制侧 §3.5 结构更适合直接进 prompt）。
> **以机制侧结构为骨架，注入内容侧的对照句**，合并如下。**实现直接采用本块，不要再各用各的。**
> **插入位置**：`corpus_block` 之后、`facts_block` 之前。**开关**：`NPC_PUBLIC_KB_ENABLED`。**预算**：固定 ≤220 字。

```
【可以引用公共见闻（选做，非必需）】
你可以偶尔拿"新闻上看来的、网上听说的、大家都这么说"这类公共见闻当佐证，让话更有时事感。
但必须守住三条，任一条拿不准就别说——退回讲你自己圈子里的事：

① 反幻觉——公共见闻只当"趋势论据"，不做"精确举证"：
   ✅ 允许：「我看新闻上说，现在好多人都……」「前阵子不是有个事嘛，具体哪家我记不清了……」「网上都在传……」
   ❌ 禁止：具体日期、百分比/精确数字、机构或公司全名、真实人名。
   （讲"大方向、普遍现象"，不讲"可查证的具体事实"。想要精确的例子，就用你自己圈子里的人。）

② 内容安全——不碰这些话题：政治敏感、涉政人物、群体性事件、民族/宗教、重大灾祸伤亡、涉外敏感。
   只聊跟眼前这个话题同类的日常领域（消费/职场/生活/科技/养生/教育/家里那点事）。
   拿不准算不算敏感，就别说——退回讲你自己的见闻。

③ 人设过滤——就算是真事，也要用"你这个人的圈子"能接触到的说法讲。
   你是{身份}，就讲{身份}会关心、会聊到的那一面，别像新闻播报。

【最稳的一档】只想讲个道理、打个比方，就用常识和生活经验说——
「一分钱一分货」「便宜没好货」「这行都这样」这类，不需要任何来源，最安全。

用公共见闻时，一句带过就行，然后立刻回到你自己的立场和道理上。
```

**违例回落顺序**：触碰任一护栏 → 本回合公共知识引用作废 → **优先回 C 源**（讲句通用道理）→ 否则回 **A 源**（讲一条预置素材）。
回落**不消耗** A 源黑名单名额（属"救场"，不属"新消耗"）。

## ④ 冲突裁定

### ④.1 v0.1 已裁定三处（保留）

| # | 冲突 | 裁定 |
|---|---|---|
| A | 注入预算：内容侧 K=6~8 vs 机制侧 4 条/120 字 | 折中 **K=5 / ≈220 字 / 候选行截断 32 字**（截断只管展示行，不影响选中后正文） |
| B | 开场素材是否入黑名单：内容侧"不入" vs 机制侧"mark used 含 opening" | **以内容侧为准**——开场用指定签名素材，记 `state["opening_corpus_id"]`，不计入 `corpus_used`，不占"未用"名额 |
| C | 追问放宽阈值：0.9 + `reused_sents` vs "允许复用同素材但须补 details" | **一致**：followup 下仍拦"整段逐字"（≥0.9）与整句复读；同时注入该人物 `details` 未用项；`deep=false` 走软回避 |

### ④.2 v0.2 新发现两处（本次核订）

| # | 冲突 | 裁定 |
|---|---|---|
| **D** | 机制侧 §3.1 给 `corpus` 加了 `source:"preset"` 标记、§3.6.3 直接用 `corpus.entity` 字段 | **驳回，按 §① 权威 schema**：① `entity` **不设字段**，由 `gist` 派生；② **不加 `preset` 标记**——"位于 `npc_corpus.json`"本身即 A 源身份，机制侧用"是否命中 `corpus` 派生白名单"判定即可；③ `source` **保持"可信度四值"语义不动**（它不表示是否预置，`source:"public"` 的条目仍是 A 源预置素材） |
| **E** | 内容侧主张单列 **C 源**（无护栏、B 源降级落点） vs 机制侧只做 A/B 两源 | **C 源不立独立机制**，并入 §③ `public_kb_block` 的"【最稳的一档】"段；它本就无需护栏、无需数据；回落顺序 = C 源 → A 源 |
