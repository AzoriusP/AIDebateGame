## 1. 免费云能不能让评委玩到？——能，但只能当加分项

已核实腾讯云 Lighthouse 免费试用：**2核2G / 3Mbps / 40G SSD / 200G 流量 / 1 个月**。四条硬约束：

| # | 约束 | 后果 | 对策 |
|---|---|---|---|
| 1 | **不能备案**。腾讯云规则：备案需包月 ≥3 个月 | **80/443 不可用** | 只能 `IP:8787` 非标端口直访（境内未备案拦的是 80/443，非标端口可用） |
| 2 | **3Mbps = 375KB/s** | 当前 assets **28MB** → 首屏 **75 秒** | 首屏压到 ≤2MB：懒加载 `acting-v2/`(12M) 与 `npc_t*.png`(9.8M 遗留原图)，首屏只加载 `portrait/`(788K) |
| 3 | **2核2G 跑不动 ollama** | qwen3.5 9.7B 需 ~8GB 内存 | **必须切云端 LLM**（代码零改动，改 config）；GLM-5.3-Flash 判定 + 混元 Hy3 NPC，约 0.032 元/局 |
| 4 | **1 个月期限** | 9/15 提交 → **10 月中失效**，评审期大概率覆盖不了 | **视频是唯一不会失效的载体** |

> **结论：免费云能用，但它是"锦上添花"，不是主交付。** 这条和你的第 4 条判断完全一致——**视频才是主战场**。
> 补充提醒：部分企业内网（含评委可能用的办公网）会封非标端口，所以不能假设评委一定能打开 8787。

### 1.1 【澄清】Live2D 不会拖垮免费云，200 块不用花

大王担心"上了 Live2D 就跑不动" —— 这是个误解。**Live2D 是纯前端技术，跑在浏览器里，不吃服务器算力**：

- `characters.js` L8-9 加载的是 `/static/vendor/live2d/5-r.5/preview-runtime.js` + `live2dcubismcore.min.js`，Cubism Core 是浏览器端 WASM/JS
- **服务器只负责托管静态文件**，2核2G 绰绰有余
- 真正吃内存的是 **ollama 本地 LLM**（9.7B 需 ~8GB）——而你已经定了 LLM 走 API，这个雷已经拆了

**实测 Live2D 体积（比想象的小得多）**：

| 项 | 体积 | 说明 |
|---|---|---|
| `vendor/`（Cubism Core + runtime） | **847K** | 全部运行时 |
| `male-master.moc3` + json + motions | ~63K | 模型本体 |
| `male-acting.moc3` + json + motions | ~22K | 动作模型本体 |
| `male-master.2048/texture_00.png` | **1.8M** | 主贴图 |
| `male-acting.2048/texture_00.png` | **4.3M** | 动作贴图（**可按需加载**） |

**首屏只加载 master**：847K + 63K + 1.8M ≈ **2.7MB**，3Mbps 下约 **7 秒**，可接受。
**acting 模型（4.3M）改为异议时按需预取**——正好异议动画现在要停留 1 秒，够它加载。

> **结论：免费云能跑 Live2D，不用买服务器。** 唯一要做的是贴图压缩（2048 → 1024 可再省 75%）和加一个加载进度条。

## 2. 【新发现】演出引擎正在空转 —— 这是"加强动画"的第一件事

美术线实测发现，**当前录屏里 6 个角色全是完全静止的死图**，不是"动得少"：

| 证据 | 位置 |
|---|---|
| `character-performance.js` 每帧算出 breath / eyeOpen / mouthOpen / bodyAngle / browForm / mouthForm / objection **7 个值** | L43, L92-102 |
| `characters.js` 只调 setter（setEmotion / playObjection / setSpeaking），**从不读回 values** | L167-269 |
| `characters.css` 把立绘钉死 `transform: none; animation: none` | **L4** |

**好消息**：计算层已完整就绪，不用出任何新图，只要把它接成 CSS 变量 + 删掉那行 `animation:none`。
**成本 0.4 人天，收益 = 呼吸、点头、异议前冲、垂头全套动作一次性活过来。**

> **性价比远高于出图。这必须是动画类第 0 项。**

### 2.1 【澄清】不是预留接口没做完，也不是"要接上 Live2D"

大王问：演出空转是不是预留动画接口时做的？是不是要接上 Live2D？

**`character-performance.js` 第 1 行注释已经写死了答案**：

```js
/* Shared performance parameters. This drives a rig; it is not a Live2D renderer. */
```

它是**共享演出参数层**——产出 breath / bodyAngle / browForm 这些**抽象参数**去驱动 rig（绑定），**它自己不是渲染器**。

所以设计上它要喂给**两条渲染后端**：

| 渲染后端 | 消费方 | 当前状态 |
|---|---|---|
| **Live2D** | `root.Live2DCharacterRuntime.setEmotion()` / `setSpeaking()` | ✅ 已接通（characters.js L348 / L368） |
| **静态图** | CSS transform（呼吸/点头/前冲/垂头） | ✅ **已接通**——见下 |

## 6. 录屏工程硬要求（A7）

| 项 | 要求 | 原因 |
|---|---|---|
| 分辨率/帧率 | **1920×1080 @60fps**，视口 1:1，桌面布局 | 异议仅 0.9s，30fps 会丢锐利感；竖屏两侧留黑 |
| 码率 | **≥12 Mbps，关键帧 2s** | 浅底小字是 H.264 的天敌 |
| 指针 | 实机段保留，讲解段隐藏 | 保留 = 证明是真机操作 |
| 录制前检查 | `portrait/*.webp` **零 404** | 404 会回退到**带 AI 水印**的 fallback 原图 |

> **红线**：视频里每处效果都须能在游戏里真实复现；剪辑只加全局镜头语言（Ken Burns、转场、分屏），**不给单个角色加游戏内不存在的特效**。
