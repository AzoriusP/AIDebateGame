## 1. 评委怎么玩到？部署方案对比

### 1.1 三方案对比表

| 维度 | **方案 A：轻量云 IP 直访** | **方案 B：录屏为主 + zip 兜底** | **方案 C：混合（推荐）** |
|---|---|---|---|
| **做法** | 腾讯云轻量 2C2G，起 `server.py`，`http://<公网IP>:8787` | 云盘交付 zip + `start.bat`；录 8-12 min 演示视频 | A 为主交付 + B 的视频为**必备保险** + zip 兜底 |
| **成本** | 轻量 68-240 元/年（促销，以官网为准）；按量约 0.1 元/h。取 **200 元**封顶 | **0 元**（云盘免费） | **200 元**（同 A） |
| **所需时间** | 0.8 人天（开机器 0.2 + 部署脚本/systemd 0.3 + 防火墙/回归 0.3） | 1.3 人天（zip+脚本校验 0.4 + 录屏剪辑 0.9） | **2.0 人天**（A 0.8 + B 1.3，共用回归省 0.1） |
| **无备案域名处理** | **不买域名 → 无 ICP 备案义务**（备案对象是域名，不是服务器）。用 `IP:8787`，**严禁 80/443** | 不涉及（本地运行） | 同 A |
| **评委体验** | ⭐⭐⭐⭐ 点链接即玩，唯一能体现"AI 原生实时对话"的方案 | ⭐⭐ 视频能看懂；亲手玩需装 Python（评委**大概率不做**） | ⭐⭐⭐⭐⭐ 主用在线，视频兜底 |
| **"完成度/可玩性"评分** | 高（评委真玩到了） | 中低（无法验证实时 LLM 质量与稳定性） | **最高** |
| **合规风险** | 中低（灰区，见 §1.3） | **零** | 中低 |
| **单点故障** | 高（宕机/端口被封 = 评委玩不到） | 低 | **低**（视频兜底） |
| **需要材料** | 服务器、部署脚本、防火墙规则、保活 | zip（**须含 28MB assets**）、启动脚本、视频 | 全部 |
| **结论** | 体验最好但有单点 | 零风险但评分打折 | **✅ 推荐** |

### 1.2 推荐方案 C 及理由

**推荐：方案 C（轻量云 IP 直访为主 + 录屏为必备保险 + zip 兜底）**

理由（按权重排序）：

1. **评审维度决定必须能亲手玩。** 大赛评「可玩性 = 趣味性 + **完成度**」「创新性 = 体验独特性」。本作的核心卖点是**实时 LLM 驱动、NPC 会记住你并成长**——这两点**只有亲手玩第二局才能感知**。视频里说"TA 记得你"是苍白的自述，评委自己被"翻旧账"才是体验。纯视频方案在这两项上结构性丢分。
2. **视频不是"可选加分"，是"必备保险"。** 远程评审场景下，评委网络可能在企业防火墙后（封非标端口）、服务可能宕机、LLM 可能限流。**视频必须做**，它的作用是"即使线上全挂，评委仍能完整看到核心玩法"。所以我把视频标为 **P0 而非 P1**。
3. **IP 直访在无域名时是合规的**，与 `docs/release-plan.md` §2.1「不买域名时该项成本为 0」「不绑自有域名 = 可以不做域名备案」一致，也与仓库 `README.md`「未备案时可用 `公网IP:端口` 直接对外」一致。**无需 ICP 备案**（10-25 自然日，物理来不及）。
4. **zip 兜底成本极低（0.4 人天）**，且能覆盖"评委就是想本地跑"的少数派，同时是**素材归档**，值得做。

### 1.3 无备案域名的三种处理方式（澄清）

| 方式 | 可行性 | 说明 |
|---|---|---|
| **IP 直访（推荐）** | ✅ | `http://<公网IP>:8787`。无域名 → 无 ICP 备案义务。**关键：避开 80/443**（云厂商对境内节点未备案的 80/443 会阻断；8787/8080/8888 一般不拦） |
| 腾讯云默认域名 | ⚠️ **待确认** | 轻量应用服务器是否附带可直接公网访问默认域名，**我未在代码中找到依据，需大王在控制台实测确认**。云托管/云函数有默认域名，轻量云存疑 —— **不要把它写进计划的关键路径** |
| 境外节点 / 静态托管 | ⚠️ | 可对境内提供未备案服务属违规，且跨境延迟伤 LLM 体验。**不推荐** |

### 2.4 限流 / 降级 / 兜底设计

#### 五级降级链（建议）

```
L0 正常      云端主（GLM-5.3-Flash 判定 + Hy3 NPC）
  ↓ 单次失败：重试 1 次（指数退避 0.5s）
L1 重试失败  切云端备（豆包 lite / qwen-flash）
  ↓ 备也失败
L2 本地兜底  本地 ollama qwen3.5（若服务器可跑；2C2G 跑 9.7B 不现实 → 本机不适用，仅本机开发用）
  ↓
L3 免费兜底  智谱 GLM-4.7-Flash（永久免费，QPS 低但零成本）
  ↓
L4 规则模式  mock（已实现，游戏可继续，文案降级）
```

> **UX 关键**：降级时前端必须**主动告知**——"AI 评委繁忙，已切换规则模式，玩法不受影响，回复质量略降"。**绝不能让评委以为游戏坏了**（这会直接打到"完成度"评分）。当前 mock 回退是**静默**的，这是缺陷。

#### 限流设计（四条护栏）

| 层级 | 规则 | 目的 | 工作量 |
|---|---|---|---|
| 会话级 | 已有 `state["_session_lock"]`（RLock）—— 单会话串行，**保持** | 防同局并发写状态 | 0（已具备） |
| 单 IP 级 | `/api/message` ≤ 6 次/分钟、≤ 200 局/日 | 防误触/脚本刷 | 0.2 人天 |
| 全局级 | 累计局数日上限（建议 400 局/日）+ LLM 花费日上限（建议 20 元/日） | 防失控账单 | 0.2 人天 |
| 供应商级 | 在混元/智谱/火山控制台设**预算硬上限**（三家均支持） | 最后一道，防代码失效 | 0.1 人天（配置） |

> **日配额耗尽的 UX**：返回友好提示「今日演示额度已用完，请观看演示视频或明日再来」，并**直接给出视频链接**——把限流事故转成兜底分流。

**单回合墙钟**（输入 30-60 字中文 + 读 NPC 回复）：

| 组成 | 云端 API | 本地 9.7B（现状） |
|---|---|---|
| 玩家阅读 + 思考 + 打字 | 30-60 s | 30-60 s |
| 判定 LLM（1 次） | 1-2 s | 8-20 s |
| NPC LLM（1 次，max_tokens=320） | 2-4 s | 10-25 s |
| **合计/回合** | **≈ 40-70 s** | **≈ 50-90 s** |

**单局时长结论**：10 回合 × 55 s ≈ 9 min → **频繁被 480s 上限截断**。
👉 **实际单局 5-8 min（取 6.5 min 为期望）**

### 3.2 总时长核算

| 路径 | 局数 | 单局 | 总时长 | 判定 |
|---|---|---|---|---|
| **天梯全通**（5 层 × BO3，期望 2.5 局/系列） | 期望 **12.5 局** | 6.5 min | **≈ 81 min** | ✅ 远超 30 min |
| 天梯全通（乐观：全 2-0 横扫，5 min/局） | 10 局 | 5 min | **≈ 50 min** | ✅ 达标 |
| 天梯单层（L1 系列赛，2-1） | 3 局 | 6.5 min | **≈ 20 min** | ❌ 不足 |
| 自由切磋（60 token/回合，任意 NPC） | 无限 | 5-8 min | 无限 | ✅ 但**需 1 代币，初始为 0** |

### 3.3 ⚠️ 真正的判定：时长达标，**可达性不达标**

**内容时长本身富余 1.7-2.7 倍。但评委默认路径会塌缩到 ~18 分钟。** 已核实三重门禁叠加：

| # | 门禁 | 代码证据 | 后果 |
|---|---|---|---|
| **G1** | **游客只能玩 L1** | `_can_access_tier()` L1253-1263：`_is_guest_ctx` → `return int(tier) <= 1` | 未登录评委只见 1 个 NPC |
| **G2** | **逐级解锁，且进度是全局的** | `tier_list()` L1333-1351：`unlocked = (not guest) and t <= highest_cleared + 1`；`data/progress.json` 当前 `{"highest_cleared": 0}` | 登录评委初始**也只开 L1**；且 `highest_cleared` 是**服务器全局单值，不是 per-account**（`progress_update` L1276 直接改全局） |
| **G3** | **自由切磋需 1 代币，初始 0** | `ACCOUNT_INITIAL_TOKENS = 0`（L199）、`ACCOUNT_TOKEN_COSTS["free_mode"] = 1`（L202）、`_can_use_account_feature` L405 | 游客与新建账号**均进不去自由模式** |

> 另外：`new_session()` L1442 也硬校验 `_can_access_tier`，前端绕过无效。
> `PROGRESS` 全局化还带来**跨评委污染**：任一评委调用 `/api/progress` 重置，会清空所有人进度（反之，任一评委通关会给所有人解锁）。

**判定结论**：

| 维度 | 结论 |
|---|---|
| 内容时长（若全解锁） | ✅ **50-81 min，达标，富余** |
| 评委默认可达内容 | ❌ **1 个 NPC + 10 条命题，BO3 最多 3 局 ≈ 18 min 且重复** |
| **综合** | ❌ **不达标 —— 但根因是门禁，不是内容量** |

### 3.4 最低成本内容扩容方案（按性价比排序）

| 方案 | 做法 | 工作量 | 效果 | 优先级 |
|---|---|---|---|---|
| **E1 预置全局进度** | 把 `data/progress.json` 改为 `{"highest_cleared": 5}` | **0.1 人天** | **登录用户直接 5 层全开**（`t ≤ 5+1`）。⚠️ 但对游客无效（G1 仍在） | **P0** |
