## 0. 结论先行（TL;DR）

### 0.1 六条硬结论

| # | 结论 | 判定 |
|---|---|---|
| **C1** | **参赛本身不需要上线、不需要备案、不需要域名**。大赛只要求「线上报名 + demo 包 + 视频 + 图文」。**今天到截稿（2026-09-15 23:59）只剩 7 天，唯一来得及的路径是「本地/离线 demo 交付」**。任何需要走 ICP 备案或小程序备案的方案，在这个窗口内物理上不可能完成（管局审核 7–20 工作日）。 | 🔴 极重要 |
| **C2** | **最大合规红线不是版号，是「生成式 AI 应用登记」**。中央网信办 2026-04 启动的「清朗·整治 AI 应用乱象」专项行动把「**未按规定履行大模型备案登记义务**」列为**头号整治问题**（CAC 2026-04-30 官方原文），第一阶段已处置违规 AI 产品 **1.4 万余款**（CAC 2026-07-06 官方通报）。模型方备案 ≠ 应用方免责：面向公众提供时，调用方（含个人）须按属地口径完成**登记/上线申请**。这条**对个人开发者同样适用且已被执法**，不是纸面禁令。 | 🔴 最高优先级 |
| **C3** | **第二条红线是版号，但它只在「商业化」那一刻触发**。免费、无收益、无广告 = 不构成付费运营。而大赛规则第 1 条恰好也要求作品「2026-01-01 之前未商业化运营」。→ **「参赛零变现」与「版号规避」是同一套动作，时序天然吻合。** | 🔴 |
| **C4** | **个人主体能收钱，但收的是「工具」的钱，不是「游戏」的钱**。2026-08 底起微信小程序已对个人主体开放虚拟支付，但**仅限「工具」类目 + 全终端月限 10 万 + Android 1%（T+3）/ iOS 12%（45–60 天）**；游戏/文娱/社交/教育类目不对个人开放。一旦被平台认定为游戏 → 通道关闭；走微信支付商户号「游戏」行业还需**提交游戏版号**。 | 🟡 可解但有边界 |
| **C5** | **微信小程序 / 微信云托管 优于独立网页，且不是小幅胜出**。小程序可用微信自带域名（免自购域名备案）、天生具备分享裂变、内置支付链路；网页必须自购域名 + ICP 备案 + 服务器，还要额外做公安备案。唯一劣势是被微信「判类目」的单点风险，以及一次前端重写。 | 🟢 |
| **C6** | **单位经济成立，真正的风险不是重度付费玩家，是免费蹭量和脚本刷量**。付费用户每月打 380 局才打平；反过来 **1 个免费 DAU ≈ 4 元/月流出，1,000 免费 DAU = 4,050 元/月**。而无限流时一个脚本号一天可刷约 1,000 局，100 个号 ≈ 10.2 万元/月。 | 🟢 |

## 2. 合规清单（逐项）

### 2.1 ICP 备案（非经营性网站备案）

| 维度 | 结论 |
|---|---|
| **是否适用** | **路径 B/C 适用且强制；路径 A 不适用** |
| **依据** | 《互联网信息服务管理办法》（国务院令第 292 号）第 3–4 条；《非经营性互联网信息服务备案管理办法》。腾讯云官方备案文档：「使用中国大陆境内节点的服务器开办网站或 APP，则必须先办理 ICP 备案，备案成功并获取 ICP 备案号后才能开通访问」。 |
| **无备案域名能否上线** | **不能**（限中国大陆节点）。境外节点可物理访问，但那是对境内提供未备案服务，属违规。 |
| **用腾讯云/微信云托管是否强制备案** | **是**。腾讯云《首次备案》文档：「如果您的网站/域名或者 APP 托管在腾讯云中国大陆地区云服务器……在开通服务前，需在腾讯云备案系统进行首次备案」。<br>**注意区分两层**：云托管/云开发的基础设施由腾讯云备案；**一旦绑定你自己的域名**（含云函数 HTTP 访问域名、云存储下载域名），**该域名本身必须完成 ICP 备案**。→ **不绑自有域名 = 可以不做域名备案**，这是小程序路线的核心优势。 |
| **办理主体** | **个人可以**。腾讯云备案可选「个人」主体；材料仅需身份证 + 人脸/视频核验 + 手机验证码 + 域名实名认证截图。 |
| **门槛** | ① 域名已实名认证且与备案主体一致（1–3 工作日）；② 需有符合条件的境内云资源（轻量/CVM/Serverless 资源包/负载均衡/**备案授权码**）；③ 部分省份要求云资源购买 ≥3 个月；④ 部分省份要求居住证/暂住证；⑤ **个人备案「新增类型」一个订单最多备案 1 个互联网信息服务**。 |
| **"游戏"类目是否难备** | **极难 → 实质不可行。**《互联网信息服务管理办法》第 5 条 + 原信息产业部 33 号令：**网络游戏属前置审批行业**，前置审批文件 = **《游戏版号核发单》**。<br>**一个关键制度细节**：腾讯云《首次备案》文档明确写「**仅单位备案有前置审批类型选择，个人备案无该选项**」——即**个人根本备不出"游戏"这个类目**。唯一合法做法是**不勾选任何前置审批、把服务内容填成不受管的内容**（如「其他」「软件工具」「信息服务」），且实际内容确实不从事前置审批行业。<br>→ 与 C3 一致：**个人域名备案的前提，是产品不能以"游戏"身份出现。** |
| **周期** | 域名实名 1–3 天 + 云厂商初审 1–2 工作日 + 工信部短信核验（**24 小时内必须完成**）+ **管局审核上限 20 工作日（普遍 7–15）**。**总计按 10–25 自然日规划。** |
| **成本** | **备案本身免费**。周边成本：域名 .cn 30–60 元/年、.com 50–100 元/年；SSL 证书免费；服务器见 §3。**不买域名时该项成本为 0（路径 A）**。 |
| **不办的后果** | 域名无法解析 / 云厂商阻断 / 被通报后停机整改。 |

**附带义务：公安备案** —— 网站通过管局审核取得备案号后，**需在网站开通后 30 日内完成公安备案**（腾讯云备案流程 Step 3 明示）。免费，**路径 B/C 必办**，且极易被漏掉。

**附带义务：小程序备案** —— 所有境内小程序上线必须完成小程序备案（MP 后台「去备案」入口）。流程：微信平台初审 1–2 工作日 → 工信部短信校验（24h 内）→ 管局终审 1–20 工作日（普遍 ~10 天）。

### 2.2 游戏版号 / ISBN

| 维度 | 结论 |
|---|---|
| **适用/不适用** | **路径 A/B 不适用（前提是零变现）；路径 C 适用，且对个人主体近乎无解** |
| **依据** | 《出版管理条例》《网络出版服务管理规定》第 27 条；腾讯云《前置审批相关》文档：「**游戏产品前置审批通过选择出版，填写游戏版号以及上传《游戏版号核发单》**」「游戏行业由中共中央宣传部出版局进行前置审批」。 |
| **什么情况算"游戏"需要版号** | 多方口径（代办机构与合规服务商口径，**置信度中、未见单一权威法条穷举**）一致指向：**面向国内公众商业化运营的上网游戏，上线前必须取得版号**。触发项：①付费下载；②道具/会员/内购；③**广告变现**；④上架主流应用商店 / 微信小游戏（多数渠道要求提供）。 |
| **纯文字辩论 + 无内购 + 无虚拟货币能否规避** | **"载体形式"不构成豁免，但"是否商业化"构成实质豁免。** 纯文字、无内购、无虚拟货币、**无广告** = 无营利的财政实质 → 可不做版号。但它**仍然是"游戏"**，所以要同步规避被认定之后的连锁义务（见 §2.5）。 |
| **参赛作品阶段是否豁免** | **不是"豁免"，是"未触发"**。赛事不以行政审批为前提；且大赛规则本身要求作品在 2026-01-01 前未商业化。→ **参赛期间保持零变现 = 天然不触发版号义务。** |
| **"网页游戏"与"网页应用"的判定边界** | **没有法定定义，监管实际看实质。** 建议按以下**五要素自检框架**（这是我的判断框架，非官方标准）：<br>① **变现** — 收费 / 广告<br>② **胜负与积点反馈** — 明确的赢/输、段位、排行、积分<br>③ **数值成长与占有** — 等级、收集、成长数值<br>④ **联网交互** — 注册、社交、排行榜<br>⑤ **上架与自称口径** — 商店选什么类目、宣传文案自称什么<br>**命中越多，被认定为"网络游戏"的概率越高。**<br>《辩弈》现状：**命中 ②③④**（天梯/三局两胜/晋级、六维成长/记忆成长、联网 session），①⑤ 可自控。→ 不建议对外自称"工具"的同时保留全部游戏化外壳，那是把 ⑤ 也送出去。 |
| **办理主体 / 周期 / 成本** | 主体必须是有出版资质的出版单位（持《网络出版服务许可证》且范围含网络游戏出版），运营侧需**纯内资公司 + ICP 许可证 + 软著**。**个人无法申报，必须挂靠。** 周期 **6–12 个月**（理想值 4–6 个月）。成本：**数万元起**（代办 + 出版社协作费）—— **具体金额未逐家核实，标注「待核实」。** |
| **不办的后果（路径 C）** | 「无版号运营」有 5–10 倍罚款的业内口径（**未核实具体法条，标待核实**）；更现实的后果是：**任何支付渠道都进不去**（微信支付行业 29「游戏」明确要求上传游戏版号），App Store / 安卓商店 / 微信小游戏均要求提供，以及被下架。 |
| **零变现无内购游戏是否有"非版号"通道（佐证）** | **有区域先例，但门槛在平台/运营主体，不在个人。** 广东省新闻出版局 **2023-08-30《关于进一步规范国产游戏小程序备案工作的通知》**已为「**无网络出版物号、无内购和充值功能**」的国产游戏小程序（含小程序、快应用）开辟**备案管理**通道：由游戏小程序**运营机构（分发平台）**向省新闻出版局申请备案，著作权人或开发者须为中国公民/内资企业（以软著登记为准）。<br>→ 三点含义：① **"零变现、无内购"是真实存在、有官方文件的"游戏不上版号"前提**，与本项目路径 A/B 完全同频；② 该通道走的是**分发/运营平台主体**而非个人，个人做独立站不直接适用；③ 说明监管边界在收紧与细化，**路径 C（收费）前必须致电属地出版主管部门确认当年口径**。 |

> 💡 **可执行的合规建议**：把对外定位从「AI 辩论**游戏**」调整为「**AI 辩论口才陪练工具**」，并**同步做减法**：<br>· 去掉排行榜 / 段位 / 积分；<br>· 「天梯 BO3 三局两胜」改称「**闯关训练**」；<br>· 「自信度归零 = 胜」改述为「**说服进度达成**」。<br>**核心玩法（Judging harness、六维、漂移、记忆）一行代码都不用动**，只改外壳与语言。这不是文字游戏 —— 它把五要素从 3 个减到 1 个，直接改变监管归类概率。

### 2.3 生成式人工智能服务备案 / 算法备案 🔴 最高优先级

| 维度 | 结论 |
|---|---|
| **适用/不适用** | **适用，个人也不例外。** |
| **依据** | 《生成式人工智能服务管理暂行办法》（七部门令第 15 号，2023-08-15 施行）：<br>· **第 2 条**：向境内公众提供生成文本等服务适用本办法；<br>· **第 17 条**：提供**具有舆论属性或者社会动员能力**的生成式 AI 服务，应开展安全评估并按《互联网信息服务算法推荐管理规定》履行**算法备案**；<br>· **第 22 条**：「生成式人工智能服务提供者」定义明确**包含"个人"**（"……提供生成式人工智能服务（包括通过提供可编程接口等方式提供）的**组织、个人**"）。<br>· 网信办答记者问原文同样确认该定义。 |
| **接入第三方 LLM API 的应用方是否需要自己备案** | **要，但走的是「登记」而非「备案」两条不同的路。** 中央网信办《关于发布 2025 年生成式人工智能服务已备案信息的公告》（**2026-01-09 发布**，cac.gov.cn，本次复核原文）：「对于**通过 API 接口或其他方式直接调用已备案模型能力的生成式人工智能应用或功能，由地方网信办开展登记**」；2025 全年新增完成备案 446 款、完成登记 330 款；**截至 2025-12-31 累计 748 款完成备案、435 款完成登记**。另据网信浙江/网信山东/网信甘肃 2026 年滚动公告，各省登记机制持续在办（山东受理电话 0531-51778555/51778559，甘肃 0931-8928733）。<br>→ **模型方备案 ≠ 应用方免责。** 你作为调用方仍是服务提供者，需独立完成登记。 |

| **属地落地口径不一致（必须致电确认）** | 各地网信办公告存在**三种不同落地方式**，「大王属地适用哪一种」目前未知：<br>· **西藏**：「通过 API 或其它方式直接调用已备案大模型能力的应用或功能，**无需备案，但需向网信办提出上线申请，申请通过后方可上线提供服务**」；<br>· **内蒙古**：「经自治区网信办同意后，**可不用备案直接上线**，后期运行过程中如出现违规行为，将视情通知开展备案」；<br>· **中央口径（2026-01-09 公告，本次复核原文）**：「提供具有舆论属性或者社会动员能力的生成式人工智能服务的，**可通过属地网信部门履行备案或登记程序**」+「**已上线的生成式人工智能应用或功能，应在显著位置或产品详情页面公示所使用已备案或登记生成式人工智能服务情况，注明模型名称、备案号或上线编号**」。<br>· **可佐证的省级登记机制（2026-08 滚动公告）**：山东、浙江、甘肃等多省网信办均在受理「调用已备案模型 API 的应用」登记；甘肃公告并写明「不具有舆论属性或者社会动员能力的生成式人工智能服务**无需备案**」「行业机构未面向境内公众提供服务的**不适用**本办法」。<br>→ **无论属地适用哪一种，"公示所用模型名称 + 备案号/上线编号"这一条是确定要做的。** |
| **"具有舆论属性或者社会动员能力"的判定门槛** | **无法定量化阈值。** 公开权威口径只有定性描述：「**以内容生成和分发为核心功能的 AI 产品，通常落入此范畴**」；「实践中各地网信办的判断尺度不一，建议有疑问时先咨询属地网信办进行确认」。<br>→ **《辩弈》的 NPC 对话实时生成并直接面向玩家，核心功能就是内容生成**，我的判断是**大概率落入**。**严禁按"我一个人做的小东西不会被管"来决策。** |
| **🔴 个人主体能否办理（关键不确定项，可能推翻排期）** | **口径冲突，必须实证：**<br>· 《暂行办法》第 22 条定义提供者**包含个人**（法条层面支持）；<br>· 但 2026 年腾讯云开发者口径：「**备案主体必须是在中国境内依法设立的独立法人企业，自然人、个体工商户均无法提交备案。个人开发者目前暂不支持直接备案，需通过境内关联企业或具有资质的企业实体进行申请**」；第三方合规口径同源：「备案主体需为境内依法设立的**法人或非法人组织**，个人不具备独立备案资格」。<br>→ **标注：未核实（建议以属地网信办电话答复为准）。** 若答复"个人不可办"，则路径 B/C 必须先升级主体。**这是一个可能推翻整个排期的前提。** |

| **🔴 不办的后果（已被实际执法）** | · **个案报道（二手、未独立核实）**：2026-03 前后有关于企业"通过 API 调用已备案大模型、未履行登记/安全评估 → 被约谈并责令下线"的公开报道。红线判断不以该个案为前提，而以以下官方事实为准。<br>· **官方通报（已核实）**：中央网信办 2026-04-30 部署开展为期 4 个月的「清朗·整治 AI 应用乱象」专项行动，**第一阶段重点整治 7 类问题，头号即"未按规定履行大模型备案登记义务"（应备未备、应登未登）**；2026-07-06 通报第一阶段**处置违规网站、应用程序、智能体等 AI 产品 1.4 万余款**，清理违法违规信息 600 余万条，处置账号 2.6 万余个，并同步整治"生成合成内容标识落实不到位""安全审核过滤能力不足"等问题。<br>· 常态罚则（《暂行办法》第 21 条）：警告、通报批评、责令限期改正；拒不改正或情节严重 → **责令暂停提供相关服务**；构成违反治安管理行为的依法治安处罚，构成犯罪的追究刑责。<br>→ **"责令下线"对一个靠留存和口碑的 Live Ops 产品基本等于归零。** |

| **周期 / 成本** | 近 0（前端弹窗 + 协议条款）。**建议今天就做** —— 它是 0 成本地把归类风险往"非游戏"方向再推一步。 |

### 2.6 用户内容安全（UGC + AIGC 双向）🔴

**这是本项目最被低估的成本项，也是《暂行办法》里明确写在服务提供者头上的义务。**

| 维度 | 结论 |
|---|---|
| **适用/不适用** | **适用，双向适用。** |
| **依据** | 《生成式人工智能服务管理暂行办法》：**第 4 条**（内容负面清单：颠覆国家政权/推翻社会主义制度/危害国家安全与利益/煽动分裂/宣扬恐怖极端/民族仇恨歧视/暴力淫秽/**虚假有害信息**等）；**第 9 条**（承担网络信息内容生产者责任、履行网络信息安全义务）；**第 14 条**（发现违法内容应及时停止生成/停止传输/消除并整改、报告；发现使用者从事违法活动应采取警示/限制功能/暂停或终止服务、**保存有关记录**并报告）；**第 15 条**（**必须建立投诉举报机制、设置便捷入口、公布处理流程和反馈时限**）。另有《网络安全法》通用内容安全义务。 |
| **为什么《辩弈》风险高于普通 AI 应用** | ① **玩家全程自由输入中文**（不是选择题）→ 输入天然是高风险 UGC；<br>② NPC 的 prompt 明确要求「反驳玩家」「点破他，别客气」「禁止说"你说得对"」「塑造偏见是 OK 的」→ **输出天然带攻击性与立场表达**，极易被诱导输出"XX 政策就是错的""XX 群体就是……"这类**可被截图断章取义**的内容。这不是假设，是 prompt 设定的必然副产物；<br>③ 这恰好与 §5 的舆情风险叠加。 |
| **`server.py` 现状（实测）** | **无任何内容安全环节**：无词表、无过滤、无举报入口、无处置日志。`llm-selection.md` §5.1 第 14 条已标注此项缺口。玩家输入只做了一件事 —— 塞进 LLM；`_extract_json` 只做**格式**兜底，不做内容兜底。同时 §5.1 第 17 条标注「无调用日志留痕」。 |
| **最小成本实现（三层，推荐）** | **L1 本地前置（0 元）**：玩家输入先过本地敏感词/正则/变体（拼音、谐音、符号分隔）字典，命中即拒答并给友好提示；同时做长度上限与纯符号/刷屏重复字符检测。**承担大部分低成本拦截。**<br>**L2 云端机审（腾讯云天御文本内容安全 TMS）**：<br>· 新客 **免费试用 3,000 条**（15 天有效期）；<br>· 套餐包：180 万条 **4,000 元/年（≈22 元/万条）**；720 万条 14,000 元/年（≈19 元/万条）；3,600 万条 63,000 元/年（≈18 元/万条）；<br>· 促销曾有 8.5 折（180 万条 3,400 元 / 720 万条 11,900 元）—— **促销是否仍在进行，待核实**；<br>· 按量后付费日结 **25 元/万条**（这是超出套餐后的价格，务必设预算告警）；<br>· 单条文本上限 10,000 Unicode 字符（远超我们单条输入的量级）；<br>· **AI 生成文本检测**：0.05 元/次按量日结，可作为抽样核实手段，**不建议全量**（太贵）。<br>**L3 人工与流程（0 元）**：举报入口 + 处理时限公示（建议 ≤48h）+ 处置日志留存 6 个月。 |
| **成本测算（重要，别漏）** | 22 元/万条 = **0.0022 元/条**。单局 12 回合：<br>· **仅审玩家输入**（12 条/局）= **0.027 元/局** —— **几乎等同于单局 LLM 成本（0.032 元）**，等于把单位成本翻倍；<br>· 输入输出**双向全审**（24 条/局）= **0.053 元/局**。<br>→ **这是极易被忽略的成本大头，不能只看 LLM 账单。**<br>**优化**：L1 本地前置过滤掉明显正常与明显违规的绝大多数，只对"灰区/不确定"调 L2，按 25–35% 调用率估算 → **约 0.006–0.010 元/局**。同时 NPC 输出侧采用「本地关键词回扫 + **5–10% 抽样送审** + 全量留痕」（输出安全性主要由 base model 对齐 + prompt 护栏承担，属行业通行做法，但**不是法定免责**，留痕 + 抽样 + 熔断才是 defensibility 的底线）。 |
| **必须做的熔断** | 输出侧一旦命中：立即替换为安全兜底回复 + 记录 `(sid, uid_hash, turn, model, 原文 hash, 时间)` + **单会话 3 次命中则终止会话**。这是《暂行办法》第 14 条「停止生成、停止传输、消除」的工程落地，也是舆情事故第一止损点。 |
| **不办的后果** | 直接落入 2026 清朗专项「安全审核能力不足」整治项。一旦发生真实事故（AI 被诱导输出敏感内容并被传播），可按《网安法》《数安法》《个保法》处罚，情节严重责令暂停服务。**对一个还没版号、没主体的个人项目，一次事故等于项目终止。** |

### 2.7 个人信息保护 / 隐私政策

| 维度 | 结论 |
|---|---|
| **适用/不适用** | **适用，但本项目可以做到"零个人信息收集"，从而把义务压到最低。** |
| **依据** | 《个人信息保护法》第 5–7 条（合法正当必要诚信、最小范围、目的限制、公开透明、知情同意）；《暂行办法》**第 9 条**（承担个人信息处理者责任 + **应与注册其服务的使用者签订服务协议，明确双方权利义务**）、**第 11 条**（不得收集非必要个人信息、**不得非法留存能够识别使用者身份的输入信息和使用记录**、依法受理查阅复制更正补充删除请求）；中央网信办、工信部、公安部 **2026 年个人信息保护系列专项行动公告**（2026-04-02）。 |
| **`server.py` 现状** | ✅ **好消息**：目前**完全不收集个人信息**（无登录、无 openid、无手机号）；会话只落在进程内存 `sessions`，`npc_state.json` 存的是 NPC 侧成长数据而非用户数据。这是个难得的优势。<br>⚠️ **但极易在加"限流/存档/排行榜"时丢掉**。另 `config.json` 里 `openai_api_key` 明文且随仓库走（`llm-selection.md` §5.1 第 2 条已标为密钥泄露风险）。 |
| **最小合规做法（强烈建议）** | ① **坚持不收集任何个人信息**：不登录、不拿微信 openid、不拿手机号、不问年龄/地区。<br>② **限流标识用匿名 ephemeral uid**：服务端签发随机 uid + 24h 轮换；若需防多开，用 `hash(ua + ip/24 + salt)` 且**不存原文 IP**。<br>③ **输入文本很可能夹带个人信息**（玩家不小心写出真名、电话）→ 按《暂行办法》第 11 条，**日志中对原始输入脱敏**（仅存 hash + 长度 + 命中标签）。<br>④ **必须公开《用户服务协议》+《隐私政策》**（第 9 条要求签协议），前端首启一次明示同意。<br>⑤ 若后续接微信登录拿 openid：openid 属个人信息，需入隐私政策并写明"仅用于配额与防刷，不做画像、不向第三方提供"。<br>⑥ 调用日志留存 **6 个月**（与 §5.1 第 17 条一致）。 |
| **2026 执法风向（重要背景）** | 2026 专项行动把「未公开个人信息收集使用规则」「未提供注销/删除渠道」「未经用户同意收集」「超出必要范围收集」列为一类治理问题，且**明确把小程序列入执法对象**（2026-05 公安部检测通报 41 款违规应用，其中点名微信小程序）。<br>→ **别因为"我是个人小项目"就省掉隐私政策。它是 0 成本且被明确检查的。** |
| **周期 / 成本** | 隐私政策 + 用户协议：0.5–1 人日（可基于模板改，但需针对 AI 内容生成、输入脱敏、6 个月留存写清）。货币成本 0。 |

| **时间线** | **7 天内可完成**（截至 9-15） | **T+25～40 天**（合规前置）→ 最早 2026-10 中上线 | **T+6～12 个月**（版号是硬闸门） |
| **主要风险** | 交付质量、创新性评审为主 | 🔴 **生成式 AI 未登记被责令下线**；🟡 被认定为"无版号运营" | 🔴 **个人主体办不了版号**；🔴 支付类目被拒；🔴 iOS 虚拟支付受限；🟡 违反大赛商业化歧义条款 |
| **推荐度** | ⭐⭐⭐⭐⭐ **立即执行** | ⭐⭐⭐⭐ **并行筹备** | ⭐⭐ **后置到颁奖后（11-27 之后）** |

### 3.2 补充：为什么「参赛期零变现」是最优解

三个约束在同一个时间点上收敛：

```
大赛规则要求"2026-01-01 前未商业化"      ─┐
版号义务由"付费 / 广告"触发               ─┼→ 同一套动作：
未成年强制实名由"被认定为游戏 + 收费"触发 ─┘   现在 → 11-27 保持【零变现、无广告、无内置收益功能】

副作用 1： diri demo 交付 → 不必开局 ICP 备案 → 7 天窗口来得及
副作用 2：颁奖后再开商业化 → 有约 2 个月完整时间做登记 / 备案
副作用 3：获奖后再启动主体注册 → 有奖金现金流 + 作品背书，个体户注册成本可回收
```

> **发布门控 judgement**：建议把「零变现」写进**路径 A/B 的发布门控**。任何"顺手加个打赏二维码 / 赞助按钮"的动作都必须在主理人处走一次显式审批 —— 因为它是一个同时可能触发三条例的开关。

### 3.3 特别评估：微信小程序 / 微信云托管 vs 独立网页

| 对比项 | **微信小程序 / 微信云托管** | **独立网页（腾讯云轻量 + 域名）** |
|---|---|---|
| **域名 ICP 备案** | ✅ **可以不买域名**。使用微信提供的默认域名（已备案）/ 云托管自带域名时，开发者无需自购域名、无需域名备案（只要不绑定自有域名） | ❌ 必须自购域名 + 实名 + ICP 备案（10–25 自然日） |
| **小程序 / APP 备案** | ❌ **需要**（MP 后台，7–20 工作日，**可与开发并行**） | N/A（只需网站备案） |
| **公安备案** | 视情况（小程序场景要求口径未统一，**待核实**） | ❌ 需要（备案号下发后 30 日内，免费） |
| **国内节点合规性** | ✅ 微信 / 腾讯云国内节点 | ✅（但必须备案才能解析） |
| **分享裂变** | ✅ **碾压级优势**：微信会话 / 朋友圈 / 群卡片天然可用 | ❌ 只能分享链接，微信内可能被降权 |
| **支付** | ✅ 原生。个人主体可开虚拟支付（限"工具"类目，月限 10 万）；个体户可申请商户号 | ❌ iOS H5 内虚拟支付受限；需引导站外/Android/PC |
| **UGC 内容安全对接** | ✅ 腾讯云同生态，云调用顺 | ✅ 同（SDK 直连） |
| **被"判类目"的单点风险** | 🔴 **高**：微信类目审核决定能否上线与能否收费。游戏类目需版号 + 企业/个体户主体；**个人主体只能做"轻休闲 + 纯广告变现"**，而这与"零变现"冲突 → **个人基本上不了游戏类目** | 🟡 中：无单一平台能一刀切下架 |
| **前端改造成本** | 🔴 **高**：当前是原生 HTML/CSS/JS，需重写为小程序（uni-app/Taro 可复用大部分 JS，但演出层需重做） | ✅ **几乎为零**：现有 `static/` 直接部署 |
| **能否适配 7 天窗口** | ❌ 来不及（备案 + 重写 > 7 天） | ❌ 来不及（备案） |
| **长期结论** | **中长期主路径**。支付、裂变、生态全占优；代价是类目单点风险 + 一次前端重写。 | **短期唯一能快速产出对外链接的方式**（但仍需备案），且保住现有技术资产。 |

**我的推荐（分阶段）：**
1. **现在 → 9-15**：两者都不做，全力保离线 demo 交付。
2. **9-16 之后并行启动**：**微信小程序（个人主体）改造**作为主线（建议用 uni-app 复用现有 `app.js` 逻辑，先做 MVP —— 只搬核心对话闭环，**暂不做美术演出层**），同时递交小程序备案。
3. **同期保留网页版**作为演示/作品集站（`demo/static` 静态化 + 备案后放轻量服务器），保证不被单一平台锁死。

### 4.1 个人主体能否收钱 —— 结论分三层

| 场景 | 能否收钱 | 说明 |

| **微信小程序虚拟支付（2026-08 底新开放）** | ✅ **能**，但有四道锁 | ① 主体：**个人**（开发者持居民身份证）；② 服务类目**必须包含「工具」**；③ 已完成小程序**认证 + 备案**；④ **全终端月支付限额 10 万元**（Android + iOS + 其他端**合计**，不是每端各 10 万）。<br>**明确不对个人开放**：文娱、社交、教育、**游戏**类目；不支持需增值电信业务资质的服务（电子邮件、语音信箱、储存转发、信息发布平台、信息搜索查询等）。<br>**iOS 额外条件**：微信客户端 ≥ 8.0.68、iOS ≥ 15、须配置「小程序简称」（Apple 要展示 display name）、单笔最低 1 元、仅中国大陆 App Store 账户。 |

### 4.2 最低成本主体方案：个体工商户

来源：成都武侯区/龙泉驿区、佛山南海区/三水区、上海市企业服务云政务办事指南（均核实于 2026-09-08）

| 项目 | 结论 |
|---|---|
| **政府行政收费** | **0 元**（多地明示"不收费" / "收费标准：不收取任何费用" / "注册个体工商户本身，政府行政收费已全面取消"） |
| **办理时限** | 承诺时限 **1 个工作日**（成都多地、佛山南海/三水明示）；法定时限 6 个工作日；上海口径 3–7 自然日 |
| **办理方式** | 全程线上（各省"一网通办" / "天府通办" / 广东"一照通行" / 上海"一网通办" + 随申办电子签名），也可窗口办理 |
| **材料** | 《个体工商户登记（备案）申请书》+ 经营者身份证 + 经营者住所证明；**仅网络经营**的，需**电子商务平台出具的网络经营场所使用证明** |
| **后续成本（关键，别漏）** | ① **刻章**：公章/财务章，公安局备案刻章点，**数百元量级（未核实具体金额，标待核实）**；<br>② **税务报到**：**领照后 30 日内必须完成，否则可能面临罚款**；<br>③ 结算账户：个体户可绑法人个人卡，免开对公户；<br>④ 记账报税：代账约数百元/年（**未核实，标待核实**）。 |
| **⚠️ 个体工商户 ≠ 免资质** | 它只是一个经营主体，**不解决**版号、游戏类目支付资质（文网文 2019-07 起已非网络游戏核心前置，见 §2.2），也**可能不解决**生成式 AI 登记的主体资格（见下）。它的真实价值：责任边界清晰、可开票、可对公结算、可申请支付商户号。 |
| **🔴 一个可能推翻主体选择的矛盾** | 有合规口径称「备案主体需为境内依法设立的法人或非法人组织，**自然人、个体工商户均无法提交备案**」。→ **若此条属实，个体户也解决不了 §2.3 的登记主体问题，必须注册有限公司。** 这条必须用一通电话问清，它决定主体路径是"个体户"还是"公司"。 |

> **决策顺序（建议）**：
> 1. 工具类 + 月流水 ≤10 万 + 不需要开票 → **直接开个人通道（0 元、当天）**；
> 2. 需要文娱/社交/教育/游戏类目，或预期 >10 万/月 → **个体工商户**（多数地区独立开发者的务实解）；
> 3. 需要融资/企业采购/复杂合同/多人股权 → **有限公司**。
>
> **🔴 主体迁移的代价远比想象中高**：主体变更本质是**重新验证业务资格**。即使 AppID 保留，新主体不具备某项行业资质时原有类目仍可能被暂停；支付订单、订阅权益、云资源、第三方 SaaS 授权都可能绑定错配。**建议一次性选对，别指望"先个人，后迁移"。**

### 4.4 iOS / 微信内 H5 虚拟支付限制的影响

| 限制 | 影响 | 应对 |
|---|---|---|
| **iOS 虚拟支付必须走 Apple IAP**（小程序场景抽成口径 12%） | iOS 端抽成约为 Android 的 12 倍；**且结算 45–60 天** → 现金流双轨 | iOS 与 Android 分开定价；**绝不能只按 Android 的 T+3 到账速度做资金规划**，iOS 一旦放量现金流就会出问题 |
| **iOS 端开发者无法主动退款**（用户须自行向 App Store 申请，由 Apple 裁定） | 客服成本与差评风险上升 | 付费页明示"iOS 端退款需通过 Apple"；准备标准话术 |

| **微信内 H5 直接拉起普通支付购买虚拟商品** | 属被明确点名处理过的违规链路 | **不做**。要么走官方虚拟支付，要么引导到 Android/PC |
| **前车之鉴：历史上被处理过的行为** | VIP 课程、游戏道具、页面保留价格或购买按钮却引导其他支付方式 → 处置措施含**限制支付接口、限制搜索和用户打开能力** | 路径 C 上线前做一次专门的"支付链路合规 review" |

### 4.6 三档定价方案

> **通用参数**：单局成本按 **0.045 元/局**（保守与推荐的中值）；支付抽成按混合 **5%**（以 Android 1% 为主 + 少量 iOS 12%）；"局" = 一次完整对局（约 12 回合）。

#### 方案 1：免费增值（Freemium）—— ⭐ 推荐起步

| 项 | 数值 |
|---|---|
| 免费额度 | **3 局/天**（≈2.7 元/月/DAU 的支出，可承受） |
| 付费会员 | **18 元/月**（无限局数 + 全部 NPC + 完整复盘 + 记忆成长） |
| 付费用户假设活跃度 | 60 局/月（约每周 14 局） |
| 单用户月变动成本 | 60 × 0.045 = **2.70 元** |
| 净收入（扣 5% 抽成） | 18 × 0.95 = **17.10 元** |
| **月毛利 / 毛利率** | **14.40 元 / 84.2%** |
| **盈亏平衡局数** | 17.10 ÷ 0.045 = **380 局/月 ≈ 12.7 局/天**<br>（按保守成本 0.059 元计算为 290 局/月 ≈ 9.6 局/天） |
| 判断 | ✅ **极度健康**。即使玩家每天打满 10 局仍毛利为正。**真正的现金黑洞是免费用户，不是付费用户。** |

#### 方案 2：订阅（按时长固定收费 vs 按局线性成本 —— 天然冲突）

| 档位 | 价格 | 月度局数上限 | 成本 | 净收入 | 毛利 |
|---|---|---|---|---|---|
| 体验 | 免费 | 90 局/月（3/天） | 4.05 元 | 0 | **−4.05 元**（获客成本） |
| 标准 | **12 元/月** | 300 局/月（10/天） | 13.50 元 | 11.40 元 | **−2.10 元** ❌ |
| 标准（修正） | **25 元/月** | 300 局/月 | 13.50 元 | 23.75 元 | **+10.25 元 / 43%** ✅ |
| 重度 | **48 元/月** | 800 局/月 | 36.00 元 | 45.60 元 | **+9.60 元 / 21%** ⚠️ |

> 🔴 **这张表是本文档最重要的发现之一**：**订阅制在 12 元/月的价位上是亏钱的**（300 局 × 0.045 = 13.5 元 > 11.4 元净收入）。因为**单位成本按局线性增长，而订阅按时长固定收费**，两者天然冲突。
> **解法二选一**：① 单价提到 25 元+；② 给额度硬上限，超额另计价。
> **推荐组合**：**18 元/月 + 300 局/月软上限，超出后 0.1 元/局（或看一次激励视频解锁 10 局）**。超额单价 0.1 元 vs 成本 0.045 元，超额部分毛利 55%，**永不倒挂**。

#### 方案 3：买断

| 项 | 数值 |
|---|---|
| 定价 | **30 元 / 永久**（解锁全部 NPC + 完整复盘 + 记忆成长） |
| 假设生命周期 | 3 个月，共 120 局 |
| 生命周期成本 | 120 × 0.045 = **5.40 元** |
| 净收入 | 30 × 0.95 = **28.50 元** |
| **毛利** | **23.10 元 / 81%** |
| 🔴 风险点 | 买断 = **无限期成本承诺**。重度玩家（如 1,500 局）成本 67.5 元 > 28.5 元 → **单用户亏损 39 元**。1,000 个买断用户里只要有 15% 是重度用户，就吃掉全部利润。 |
| **必须加的护栏** | 买断权益 = **"永久 + 基础局数 200 局/月"**，超出部分按 0.1 元/局或看视频解锁。**既保住"买断"的营销爽感，又封死下行风险。** |

#### 三档对比与最终推荐

| 方案 | 转化率经验 | 单位经济 | 现金流 | 推荐度 |
|---|---|---|---|---|
| 免费增值 18 元/月 + 300 局软上限 | 较好 | ⭐⭐⭐⭐⭐（84% 毛利，平衡点在 12.7 局/天） | 月月有 | ⭐⭐⭐⭐⭐ |
| 订阅（无额度上限） | 好 | ⭐（12 元档倒挂） | 月月有 | ⭐⭐ |
| 买断 30 元 + 200 局/月上限 | 低但客单高 | ⭐⭐⭐⭐（81%）但需护栏 | 一次性 | ⭐⭐⭐⭐ |

> **最终建议**：起步用「**免费 3 局/天 + 18 元/月会员 + 300 局/月软上限**」；同时上架「**30 元买断**」作为忠诚用户第二选项（同样带 200 局/月上限）。
>
> **❌ 明确不建议做抽卡 / 概率抽取**：一是 Sweep-canvas 的负面清单包含"诱导非理性消费"，且需概率公示；二是它与"AI 辩论"的价值主张毫无关系，只会徒增合规面。

### 4.7 「每个付费用户每月能承受多少局」—— 直接答案

| 定价 | 净收入 | 打平局数/月 | 打平局数/天 | 判定 |
|---|---|---|---|---|
| 12 元/月 | 11.40 元 | 253 局 | 8.4 局 | ❌ 重度用户会超，必然倒挂 |
| **18 元/月** | 17.10 元 | **380 局** | **12.7 局** | ✅ 安全线所在 |
| 25 元/月 | 23.75 元 | 528 局 | 17.6 局 | ✅ |
| 48 元/月 | 45.60 元 | 1,013 局 | 33.8 局 | ✅ |

**→ 一句话结论：定价低于 18 元/月时，一个每天打 10 局的活跃付费用户就会吃掉全部毛利。18 元是这条安全线。**
（若按推荐成本 0.030 元/局计算，18 元档打平点进一步放宽到 570 局/月 ≈ 19 局/天，更稳。）
